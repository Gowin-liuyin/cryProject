## 7. 风险与 BLOCKERS 处理

| 风险 | 表现 | 处理 |
|---|---|---|
| 锁频恢复失败 | restore_match=no | 立即停止采集，手工恢复并复核，写 BLOCKERS，不再继续锁频任务 |
| 新臂出现阳性 | 例如 M5 隐式拒绝可区分 | 如实报告；先排查类构造与漂移（同 M2 的教训：确定性密文重复 vs 逐样本变化），用复测或换核确认；不升级为泄漏结论，除非三次复测一致且定位到代码 |
| 预期阳性未检出 | 例如 -O0 下 M1 分支消失 | 如实写“该级别未出现分支”，这本身就是跨环境结论 |
| 格式破损在 API 层被拒绝 | 无法进入内核 | 记录拒绝路径与耗时；写明为何不进主检验 |
| Binsec/Microwalk 超时或 unknown | 格子无法判定 | 写“unknown + 参数”，不填“不存在” |
| 网络实验需要 netns/root 失败 | 可选任务 T25 | 写 BLOCKERS 并跳过，威胁模型章改为定性描述 |
| 报告编译失败或页数暴涨 | — | 把长表移到附录或证据文件，正文保留摘要和引用 |
| 匿名性泄露 | verify 标记 >0 | 修正源文件后重新打包，不手改 zip |
| 冻结 PLAN sha 变化 | 阶段 5 对比不一致 | 回退该文件改动（新提交恢复，不改历史），并在审计中说明 |
| 机时不足 | 阶段 2 超时 | 优先级为 T12 > T20 > T23 > T29(a) > T25；未完成项在审计中标“未做”，不缩减样本量冒充完成 |

BLOCKERS.md 格式：`编号 | 任务 | 现象 | 已尝试 | 影响的题面条款 | 建议`。
