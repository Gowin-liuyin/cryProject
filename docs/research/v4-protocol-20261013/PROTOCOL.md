# v4 分组确认与交替对照协议

rule_id=`v4_group_confirmation_20261013`

本文件在任何开发采集、确认采集和交替对照采集之前冻结。本地提交只记录作者自己的顺序，不是第三方预注册。此后不修改本文件。程序若与本文件冲突，改程序，不改本文件。

## 1. 分组

主比较只使用方向恒定组：`message-zero` 对 `message-ones`。

一条会话使用同一个公开会话种子派生 `key_count=16` 把封装密钥。密钥种子由 `expand_test_seed` 生成，purpose tag 为 `4`，sample index 为密钥序号 `0..15`。`message-zero` 的封装消息是 32 字节约 0，`message-ones` 的封装消息是 32 字节约 255。同一密钥下每类因此各有一条密文；16 把密钥使每类有 16 条不同密文。

每类唯一密文数必须等于 16，且每条密文在该类中的出现次数必须相同。不满足时该会话记失败并保留，不另抽密文补齐。

全 0 或全 1 硬币下的单密文对、以及 `valid`、`bit-flipped`、`random`，都不进入本协议的确认族。

## 2. 公开种子

| 用途 | 种子 |
|---|---|
| 开发会话 s=1..8 | `20261013000 + s` |
| 确认会话 s=1..S | `20261014000 + s` |
| 交替对照的顺序 | `2026101307` |
| 交替对照第 r 轮两侧共用的测量种子，r=1..5 | `20261015000 + r` |
| 3.6 节下标重抽 | `20261013` |

开发会话数固定为 8。开发阶段每条密文的重复参数 `R=2`。确认阶段的 `R` 不另估，就用这个 `2`，因为不把调用独立假设写成方差随 `R` 缩放的模型。

## 3. ABBA

一类单元格是一对 `(key_index, repeat_index)`。`repeat_index` 从 0 到 `R-1`。

- `key_index + repeat_index` 为偶数时，顺序是 A B B A。
- 为奇数时，顺序是 B A A B。

A 是该密钥的 `message-zero` 密文，B 是该密钥的 `message-ones` 密文。密钥序号外层、重复序号内层，不再另做随机打乱。每个单元格含两次 A 和两次 B，所以两类调用数相等。会话效应是两类调用均值之差，单位是 `CLOCK_MONOTONIC` 计数。

正式计时窗口只有一次解封装。密钥、密文、预热、空窗、摘要和写文件都在窗口外。预热 8 次。空窗 256 次，取偶数个样本的两个中央值的平均作为中位数。

## 4. Holm 族与主判定

确认族只有一个比较：16 条密文上的 `message-zero` 均值减 `message-ones` 均值。族水平 `alpha_family=0.01`，控制方式是 Holm。比较数为 1 时，逐步阈值就是 0.01，比较用小于等于。

分析单位是会话。对 S 个会话效应做双侧单样本 t 检验，自由度 `S-1`。`S` 至少为 4，至多为 40。

方向一致性不进入 Holm 族，也不改 p 值。全部会话效应同为正或同为负时记 `direction_consistent=yes`。出现 0 或符号不完全相同则记 `no`。

主结论只取下列之一：

| 条件 | 令牌 |
|---|---|
| 覆盖、完整性或会话数未满足 | `not_run` |
| Holm 不拒绝 | `not_rejected` |
| Holm 拒绝且方向一致 | `rejected_direction_consistent` |
| Holm 拒绝且方向不一致 | `rejected_direction_inconsistent` |

## 5. 协变量

预先声明两类会话协变量：空窗中位数，以及第 6 节的窗口覆盖率。

空窗中位数先减去各会话的算术平均，再对会话效应做一元线性回归。居中以后，截距等于未调整的会话均值。因此该回归不能把均值解释掉。输出调整前均值、调整后截距和斜率的双侧 p 值。斜率即使拒绝，也不改写第 4 节的主令牌。

覆盖率低于第 6 节阈值时，主令牌为 `not_run`，原记录保留。SMT 兄弟核的 `/proc/stat` 起止快照只归档，不进入主检验。

## 6. 频率窗口与覆盖率

开发采集不写频率，只把进程亲和到逻辑 CPU2，用来估计组效应的会话均值和样本标准差。

确认采集和交替对照的每一次计时进程必须包在 G2 式窗口里：只把计时 CPU 及其 `thread_siblings_list` 中另一个逻辑 CPU 的 `scaling_min_freq` 和 `scaling_max_freq` 请求为 `4300000` kHz，不改 governor、boost、EPP 或其他 CPU。兄弟列表不是恰好两个 CPU 时，在计时前停止。

采样器在计时期间读取计时 CPU 的 `scaling_cur_freq`。某次读数代表直到下一次读数的区间。工程带沿用 4257–4343 MHz，按 kHz 闭区间 `4257000..4343000`。覆盖率是带内区间长度除以首尾时间跨度。每条确认会话和每一轮交替计时的覆盖率阈值是 `0.99`。

这个比例是采样区间覆盖，不是 2026-10-10 那次 APERF 几何证书，也不签逐调用恒频、物理纳秒精度或 R02/R04 的总体验收。

窗口开始前先把可见的 min/max 基线写进该次运行目录。任何退出路径都把写过的字段设回基线。恢复失败则保留现场并停止后续会话，不另开一轮补样。

## 7. 功效与预算

功效针对第 4 节的双侧单样本 t，族水平 0.01，目标至少 0.9。非中心参数是 `abs(mean/sd)*sqrt(S)`。把握度用卡方混合对正态尾概率做 Simpson 积分；临界值用现有中央 t 的双侧概率二分求得。

开发阶段必须正好 8 个完成会话。样本标准差用除数 `7`。

- 均值和标准差都是 0：`stopped_no_stable_group_effect`。
- 标准差是 0 而均值不是 0：导出 `S=4`、`R=2`，把握度记 1。
- 均值是 0 而标准差不是 0：`stopped_no_stable_group_effect`。
- 否则从 `S=4` 找到 `S=40` 中第一个把握度至少 0.9 的 `S`，并导出 `R=2`。找不到则 `stopped_power_exceeds_cap`。

这两种停止都表示预算内没有可确认的稳定组效应。停止之后不追加未冻结样本，不开始确认采集，也不开始交替对照。

调用封顶按导出结果不能超过的边界书写：`S<=40`，`R=2`，每会话正式解封装 `16*2*4=128` 次，确认总正式调用不超过 `5120`。开发是 `8*128=1024` 次。交替对照 5 轮、每轮两个构建、每构建 1 个会话，正式调用 `5*2*128=1280` 次。空窗、预热和资格测试另计，不进入上述正式调用数。

墙钟封顶：开发 90 分钟，确认 6 小时，交替对照 8 小时。超时则停止并保留已写出的文件。

## 8. 交替对照

每轮只翻转宏 `MESSAGE_ENCODER_BRANCH`。`1` 是消息位分支，`0` 是与既有掩码相同的选择。两侧都保留同一套 `optnone` / `optimize("O0")` / `noinline`。两侧编译都带 `-falign-functions=32`。不改动 vendor 原件，补丁只进入构建副本。

顺序种子 `2026101307` 驱动 splitmix64。状态从该种子开始，每轮取一次，最低位为 0 时先测分支再测掩码，为 1 时相反。splitmix64 的增量是 `0x9E3779B97F4A7C15`，随后两次乘法常数是 `0xBF58476D1CE4E5B9` 和 `0x94D049BB133111EB`。

同一轮两侧使用同一个测量种子，因此输入日程相同。每轮都保留两侧反汇编中的 `poly_frommsg`，以及公开 KAT 的 25 次密钥生成、25 次封装、10 次解封装。失败轮次保留。完成轮次少于 5 时配对判定为 `not_run`。

配对差是该轮分支组效应的绝对值减去掩码组效应的绝对值。配对族只有这一个比较，Holm 水平仍是 0.01。

`protection_causality` 同时要求：5 轮全部完成，配对 t 拒绝，配对差均值大于 0，每一轮配对差都大于 0，且 5 个分支组效应符号严格相同。

其余完成了 5 轮的结果记 `environment_drift_dominant`。

该判定单独回答防护因果。它不并入第 4 节的确认族，也不与 r07 或 v3 回滚记录合并。

## 9. 诊断与 3.6、3.7.6、3.7.7

确认分析若实际跑完，另外输出会话效应的正态分位图、Shapiro-Wilk 统计量和会话内调用序列的滞后 1 自相关。这三项是描述，不是拒绝门。前提各用一句话写在输出里：分位图对照正态直线；Shapiro-Wilk 的原假设是会话效应来自正态；滞后 1 自相关描述会话内依赖，不代替会话级检验。

3.6 节旧规则“取原序 0–23”保留为 `docs/evidence/reference-label-control-20261007` 的六行条件拒绝数，不覆盖那些字节。新计算使用种子 `20261013` 的 splitmix64，对每一块 3000 条记录无放回抽取 24 个下标，按抽取顺序组成 12 对。块 `b=1..6` 的初始状态是 `20261013+b` 经过一次 splitmix64 之后的值。4096 种标签置换、含等值的上尾和分母 4096 仍沿用 C04 的统计定义。

3.7.6 与 3.7.7 保持探索性身份，不转入本协议的 Holm 族，也不为它们新开按格确认采集。表 7 和跨平台 v1 记录在冻结前已经阅读，不能再被选进同一族。3.7.5 只作为固定长度网络交互的可行性记录，不声明远程类别差已经确认。

## 10. 程序

`v4_analyze power`、`v4_analyze confirm`、`v4_analyze paired` 把同一份结论写到标准输出和输出目录的 `conclusion.txt`，不写时间戳。两次运行应当逐字节相同。输出目录必须已存在。

一次采集目录含 `calls.csv`、`meta.txt`、`empty.csv`。确认和交替对照另含 `coverage.txt`、`smt-sibling-stat.txt` 和 `binary.sha256`。`calls.csv` 的每一行是一次正式解封装。`input_sha256` 是密文十六进制列按行序拼接后的 SHA-256。`binary.sha256` 的一行必须等于 `meta.txt` 里的 `executable_sha256`。

`v4_analyze confirm-sessions` 读取会话目录清单，从原始行重算两类均值之差、空窗中位数和覆盖率，再执行第 4 节。`v4_analyze reduce-effects` 只做同一重算并写出效应表，供 `power` 使用。输入摘要不一致、唯一密文数不是 16、重复次数不相等、二进制摘要不一致，或覆盖率低于阈值时，结论的状态是停止，主令牌是 `not_run`，不输出一个成功的科学拒绝。开发阶段不要求覆盖率文件。
