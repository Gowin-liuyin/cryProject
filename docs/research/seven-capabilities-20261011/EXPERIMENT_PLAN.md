# 七项能力完整实施与验收计划

日期：2026-10-11。规划基线：`9e37d591188aea353868042f105f371c4523f51c`，`main`。

本计划响应用户本轮“七项全部做好、尽可能做到最好”的要求。七项全部进入项目必做范围；题面的基础、较强、高水平分档只说明官方层次，不再作为本轮略过增强项的理由。本文件是待执行计划，不是实验记录，不升级任何既有签收状态。

依据为已封存的[题目原件](../../reference/official-2026/A1-13-original.docx)、[当前验收表](../../full-work-acceptance.md)、[进度](../../full-work-progress.md)、现有源码与新旧证据。旧方案中不开展网络场景的范围决定，在本计划中扩展为自有测试端点的受控网络测量；不扩展到第三方服务、密钥恢复或通用云平台。

## 1. 最终交付与完成尺度

交付一条可运行、可复算、能解释失败的链路：

`功能资格 → 完整解封装测量 → 统计检测 → 函数追踪与候选排名 → 源码/实际产物核查 → 防护与回滚复测 → 编译/处理器/网络对照 → 匿名离线复现`

两项主要作品主张：

| 主张 | 最少所需证据 | 对应能力 |
|---|---|---|
| C1：在声明的本地测试条件下，能够测量并检出已有人工消息分支的时间差异，自动缩小到相关函数，再以同优化防护和回滚完成验证 | 新完整调用原始值、冻结统计协议、函数追踪、盲化排名、实际执行路径、功能等价、防护/回滚的新数据 | 1—4 |
| C2：能量化该检测与防护结论随编译配置、真实处理器和网络噪声变化的适用范围 | 构建矩阵、两种真实处理器上的同协议实验、客户端RTT与服务端诊断分离、负结果和检测能力边界 | 5—7 |

必须排除的替代解释：不同算法语义、不同优化约束、插桩本身制造差异、类别顺序与系统漂移、重复密文伪装成独立样本、选择有利种子或配置、将普通输入路径差异直接称为秘密泄露。

每项分别维护四栏：**软件完成、实际实验完成、拟定主张成立、作品材料验收**。程序能跑不等于主张成立；阴性结果可以完成场景研究，但不能代替“明显泄露能够检出”或“自动定位确实有效”的正向验收。后两项至少要在登记的已知人工案例上成功。参考版没有发现新漏洞不影响研究完成，也不能称全库恒时。

## 3. 共用实验合同（先冻结，再确认）

### 3.1 实现与证据边界

- 继续C11、ML-KEM-768、固定便携C后端和CMake/CTest。原六模块和原分析器保留；新能力作为小模块接入。图表可以用标准绘图工具，正式生成、采集、统计和资格判定用C。
- `reference / vulnerable / hardened / deployable`沿用四形态。人工分支与同优化掩码用于机制归因；正常优化的参考与deployable用于实际部署代价。不得把两种比较混合。
- vendor与`sources/`原件不改，必要插桩适配采用单独补丁和构建目录覆盖层。正式无插桩、诊断插桩、sanitizer三类产物隔离，分别保存摘要。
- 每个新构建先做公开NIST KAT、接口长度/空指针、隐式拒绝、随机源失败与跨变体等价；动态检查另构建。失败配置保留并阻断其计时结论。
- 每次采集记录完整源码提交/导出清单、工作区状态、实际编译/链接参数、工具版本、机器/OS/虚拟化、时钟、频率管理、CPU与SMT、温度/负载可见性、输入摘要、二进制摘要、实际执行路径、计划/完成次数、退出与清理状态。
- 新证据落入新的`docs/evidence/`子目录；研究合同在本目录或后续模块目录。旧证据和封存报告不回填、不改字节。当前未跟踪研究工作不纳入本模块提交。

### 3.2 输入与分析单位

保留五类1088字节输入：有效、翻位、随机字节串、全0消息、全1消息。长度错误属于接口检查，不混入内核计时比较；类别由生成器登记，不读取内部验证结果。

新主比较候选为“全0/全1两类的等权均值”与“有效随机消息类均值”；翻位、随机密文和全0对全1列为预登记次比较。主比较只含有效密文，有助于减少有效/异常路径混杂。选择依据已知历史机制，属于知情的新验证设计，不称从未见过数据的原始发现。

必须如实记录：同一密钥下全0/全1消息各自仍是重复密文。不能通过声称“换了封装随机数”将它变成独立样本；此处确定性封装消息决定相关派生值。新语料以多个公开测试密钥、不同有效随机消息与独立调度种子扩大覆盖，并保存每类唯一密文数和重复率。建议每会话10个测试密钥；其具体数量在试点后冻结。已知测试密钥仅属白盒夹具，普通使用继续系统安全随机源。

- 分清调用、时间块、进程、会话、日期、密钥和物理机器。20个进程不自动等于20个独立环境。
- 开发集决定阈值、样本数、分块和候选算法；确认集使用未用于开发的密钥/生成种子/调度种子。确认阶段不调阈值、不换主比较、不筛掉失败种子。
- 同会话内四变体用同语料，运行顺序平衡随机化；类别按固定大小的小块等量乱序，记录前驱类别和时间顺序。变体切换、预热、间隔规则在确认前冻结。
- 主估计量先固定为会话内类别均值差；人工分支与同优化掩码的差异衰减以同会话差之差衡量。P50/P90/P99、MAD及秩统计为解释和敏感性分析。

### 3.3 统计决策合同

建议确认阶段的主比较族控制`alpha_family=0.01`，比较清单在采集前列完，以Holm校正或事先分配的显著性预算控制；同时给效应量和与决策匹配的区间。具体计算方法、置信度和族划分必须在试点结束时冻结。历史的0.001等口径不改写。

逐次Welch/Mann–Whitney可用于探索和历史兼容，不能把全部相关调用堆成一组后据此签收。主推断以会话/预定块为单位：仅在支持其条件时使用分层或分块重采样；块长由开发集确定，确认集报告敏感性而不重新择优。若采用设计随机化检验，必须保持原随机化层级，并明确可交换性、漂移与跨调用携带效应条件。条件不足时标为描述性结果，不给保证性的覆盖率或FPR声明。

计划用20个完整确认会话、分布在至少3个时间段并尽量跨3天；这是排程起点，不是独立性证明或统计充分性的保证。每会话四变体、每类5000次起步。开发阶段依据目标效应`delta_target_ns`、区间宽度和相关性评估预算；若不足，在看到确认结果之前调整并重新冻结。不能不停采到显著。

“未检出”须同时报告样本量、适用输入、噪声和可分辨效应。要声称残差低于工程阈值，预定阈值并做相应等效性/区间判断；阈值需要应用意义和测量能力依据，不能按当前噪声随手设定，更不能当密码安全界。

固定预算到期无论显著与否都停止；提前停止只因资格失败、资源边界或预登记异常条件。保留所有正常长尾、缺失、超时、失败和实际花费；偏离协议另开探索记录，不替换原确认结果。

## 4. 七项具体实施

### W1 本地高精度计时与明显泄露检测

**目标：** 对完整解封装具有可重复、与目标效应相称的测量能力，并在已知阳性上检出差异。

1. 复用现有RAW空窗和完整调用采集器，统一元数据及原始记录格式。Linux主时钟延续已验证路径；macOS采用已验证单调时钟。记录实际分辨率，不把单位ns等同于1ns物理精度。
2. 用与正式采集相同的读钟路径完成空窗与重复读钟检查；测量全部长尾。新增检查要回答当前路径/配置的新问题，不机械重复已有六进程研究。
3. 完整窗口仅包围解封装；输入、分配、结果消费、分类、CSV和日志均在窗口外。随机化与结果验证成本另记。
4. 主实验在Ryzen裸金属专用时段运行，记录目标CPU/SMT、亲和性、后台负载和频率策略。优先复用已核验的管理恢复流程；如需新系统配置，先完成资源/恢复合同，不能把历史G2当作当前已锁频。
5. 按开发/确认协议重跑四变体和登记的无差异控制，给出运行顺序、分位数、噪声、效应与复现情况。增加正常负载与预定背景CPU负载的有限对照，单独报告，不能在主采集期间随意引入竞争。
6. 以目标差异和确认区间定义“足以检出该案例”的工程精度。可争取读钟P99开销相对目标效应足够小，但不能将空窗机械相减后称得到真实耗时，也不把比例门槛冒称官方要求。

**验收：** 原始值/整数计数/时钟路径/二进制可追溯；已知阳性在预登记确认中达到检测条件；防护与参考报告残差及检测边界；跨会话稳定性有数据。R02是否升级根据上述证据对应题面判定，不再无限追逐未要求的逐调用物理恒频证明。

**图表：** 同轴时间序列与类别分布、会话效应森林图、时钟与测量质量表。不要只给均值柱状图。

### W2 函数级运行时插桩

**目标：** 输出实际调用关系和函数耗时，覆盖解码、解密、消息提取、重加密、比较、拒绝密钥派生与选择。

1. 基于固定解封装调用图建立覆盖清单。先覆盖顶层阶段，再向产生差异的阶段细化，避免默认对每个小算术函数插桩导致无法解释的开销。
2. 首选编译器函数进入/退出钩子和独立C追踪器；GCC文档明确此选项能覆盖概念上的内联进入/退出，因此必须记录实际编译器行为，不能把事件当成未插桩机器码里存在独立调用。[GCC插桩文档](https://gcc.gnu.org/onlinedocs/gcc/Instrumentation-Options.html)
3. 插桩钩子本身、计时、内存记录和辅助函数禁止递归插桩。预分配有界事件存储，窗口内只写内存，无分配/日志/系统文件输出。每批结束后导出；溢出、事件不配对、栈深不足显式失败，不能默默丢弃。
4. 事件字段仅包括不透明样本编号、模块相对地址/函数编号、调用关系、时间戳和完整性状态；不记录参数、消息、私钥、共享秘密或验证标志。真实密钥运行不启用该诊断模式。
5. 计算包含耗时与自耗时，处理嵌套与重复调用；同一解封装内同函数按预定规则汇总，避免函数调用次数多的样本获得更多统计权重。
6. 构造“无插桩/仅钩子记账/完整计时插桩”三组，量化总开销、函数排名变化和类别效应变化。不以一律减去平均钩子开销得到所谓无扰动函数时间。
7. 内联严重或钩子无法覆盖的逻辑，诊断构建可增加明确阶段标记/限制内联；必须说明这是另一产物，并与正式无插桩产物的内联范围对应。不得修改deployable正式构建来方便观察。

**验收：** KAT/差分语义不变；关键阶段均有实测事件或明确的内联映射，覆盖分母来自实际范围；溢出与错误路径可测；包含/自耗时核算一致；插桩扰动有量化报告。只完成三个固定函数反汇编不算通过。

**交付：** 追踪CSV、调用树、阶段耗时表、开销表、插桩关闭验证。自动化指标与最终端到端结论来自各自合适的产物。

### W3 统计显著性与检测能力

**目标：** 让R04对应的真实采集推断有清楚的假设、单位、误差控制和独立确认。

1. 对现有C统计模块做能力盘点；旧复算逐字保持，新确认分析采用独立入口/协议版本，不改历史检验定义。
2. 将3.3节合同落实为机器可读清单：比较族、主/次比较、分析单位、样本预算、效应方向、异常规则、区间和停止条件。
3. 输出每会话效应、运行级区间、时间漂移、自相关/块长敏感性、重复输入比例。没有证明独立的会话不包装成iid。
4. 以预先构造的无类别效应模型验证数学实现，用手算/独立实现核对数值；以真实参考后赋标签或同输入随机标签验证流程性偏差。这些控制不能代替真实密码类别的总体FPR。
5. 以已有人工分支的留出密钥/会话评价有限测试集检出比例，报告分母与区间；可给指定有限基准的误警比例，但参考实现不是经过证明的“绝对无泄露真值”。不声称全体密文FPR/TPR。
6. 可引入固定提交的dudect作辅助交叉检查，先核对许可、平台计时和裁剪/变换规则，单列其输出；本项目主分析保留所有原始长尾。dudect作者也明确未检出不能证明恒时。[方法来源](https://www.reparaz.net/oscar/misc/dudect)
7. 需要画检测随样本数变化时，只使用预登记检查点作探索曲线；正式决策仍用冻结的终点，不能择最显著的检查点。

**验收：** 正式报告能回答“哪一输入范围、哪一比较、什么统计单位、什么效应、什么区间、什么假设”；开发/确认隔离；未通过前提时正确拒绝升级结论；真实新数据和独立数值复核均完成。软件测试通过不能直接关闭R04。

**图表：** 效应和区间、有限基准检出/误警的分母表、相关性敏感性、固定预算检测曲线。

### W4 自动化定位与防护闭环

**目标：** 给定采集数据及对应二进制，自动生成可核查的候选函数/阶段列表，而不把目标函数名硬编码为答案。

1. 从W2的实际覆盖范围建立候选集合。阶段差异先排序，再在选中阶段内细化，保留未覆盖/不确定列表。只支持登记范围，不宣称任意程序全自动定位。
2. 对每个候选计算类别效应、校正后统计量、跨会话方向一致性以及插桩开销敏感性。筛选优先级在开发集固定，不按最终答案调分数。
3. 输出Top-1/Top-3、函数或内联范围、源码位置、所属解封装阶段、包含/自耗时差和证据链接。调用者的包含耗时差不能自动当作根因，需结合自耗时和调用层级。
4. 对排名候选复用并扩展`mechanism_audit`：核查秘密相关条件分支、可变时除法、提前退出、比较/选择路径。未知指令、地址混淆、LTO消符号、数据流无法确认都输出unknown，不凭分支助记符断言秘密依赖。
5. 盲化变体标签，定位程序不读取补丁名称、预置目标名或真值字段；在开发中未用的密钥/时段/一个留出编译配置上生成排名，然后再解盲。已知同一机制仍不声称“发现未知类型漏洞”。
6. 对已知人工分支执行vulnerable→同优化hardened→重新构建的vulnerable回滚；比较端到端与目标函数的差异衰减/恢复，并重做功能资格。回滚是新目录新构建，不改历史产物。
7. 与“端到端告警后遍历整个覆盖集合”的朴素基线比较，报告真值排名、候选数减少、定位运行时间和总代价。改进需来自真实定位结果，不以硬编码真值创造R12收益。

**验收：** 留出阳性中真实目标进入预定Top-3，候选减少和逐会话成功/失败分母全部列出；防护和回滚方向与端到端证据一致；未检出/不确定时不强行给唯一根因。若仅产出候选但无法确认，软件可完成，定位效果尚不签收。

**交付：** `localization.json`、候选表、源码/二进制映射、修复与回滚对照。全自动证实秘密因果不是本轮承诺。

### W5 网络噪声环境

**目标：** 在自有测试端点量化本地差异经网络传输后是否还能辨认，以及检测预算如何变化。

1. 实现最小C客户端/服务端，仅用于测试。请求为固定长度密文和公开请求编号；服务端完成真实完整解封装、窗口外消费结果，回复固定长度确认。密钥/共享秘密/内部接受状态与服务端耗时不进网络响应。
2. 主协议采用预建立连接、单个在途请求、固定缓冲与一致传输选项；握手、连接重建另记。客户端以单调时钟测发送开始至完整响应的RTT，不依赖两机时钟同步。
3. 两种运行分开：客户端独立观测用于网络结论；服务端诊断计时用于解释。若同时记录服务端时间会增加请求间扰动，测其代价并另做关闭诊断的确认，不将服务端信息交给客户端分析器。
4. 必做场景：回环作为协议开销基线；Mac客户端到授权Ryzen服务器的真实连接；Linux受控链路的低/中/高抖动。抖动候选为单向延迟/标准尺度0.1/0.02ms、1/0.2ms、10/2ms，均在预试点后按网络可承受范围冻结；这些是设计参数，不是已经测到的网络特征。
5. 受控抖动使用内核网络队列机制，位于密码计算窗口之外；不在算法里加sleep或随机延迟。`netem`支持延迟分布与随机种子，但配置值仍须以实际RTT验证。[netem手册](https://man7.org/linux/man-pages/man8/tc-netem.8.html)
6. 网络隔离不得污染共享网卡或管理SSH：优先匿名进程网络命名空间和自有veth，禁止会在`/run/netns`创建项目句柄的默认具名流程。进程、配置、日志、缓存和临时文件都留在Cry；建立单独恢复合同并先做空任务恢复。该设计尚未运行，也不预先声称可用。
7. 有/无预定背景网络流量作为次级场景；记录实际RTT分布、丢包、重传可见性、超时和队列设置。超时单列为删失/缺失，禁止静默删除后只分析快速成功响应。
8. 同一场景比较参考、人工分支、掩码和deployable；使用客户端RTT进行冻结统计。报告同预算检出结果和不能分辨的效应范围；网络没有检出时不改变算法来放大信号。

**验收：** 必须有真实两端通信及受控噪声的原始客户端数据，不能只有给本地CSV叠加随机数的模拟。固定响应语义、功能等价、网络恢复和限流预算通过；至少三档噪声的结论与失败边界可复算。允许结论是“在本预算下均未检出”，但不允许称“没有远程泄露”。

**交付：** RTT/本地差异对照、噪声—检测预算图、超时/丢失表、网络威胁模型与恢复记录。真实广域网可作为追加场景，不是所有公网环境的覆盖承诺。

### W6 编译器优化影响

**目标：** 分清源码、构建约束、实际执行机器码与检测结果的关系。

主平台上必须完成：

| 形态 | 编译器 | 优化配置 | 数量与用途 |
|---|---|---|---|
| reference、deployable | GCC、Clang | O0、O1、O2、O3、O2+LTO | 20个构建，研究真实优化/内联影响 |
| vulnerable、hardened | GCC、Clang | 外层O2，保留已有函数级固定约束 | 4个构建，同优化机制控制 |

共24个普通构建，每个均做功能资格、实际链接审计和基础计时；O2两编译器共8个形态重点确认，其他优化各至少5个完整会话作范围观察。普通构建的sanitizer资格另算，sanitizer数据不进计时表。

1. 在CMake内提供明确配置项，核对最终`compile_commands.json`和链接命令，防止`RelWithDebInfo`追加-O2覆盖用户-O0。当前目标显式关闭IPO，LTO配置必须同时核查目标属性与实际链接结果。
2. 保存最终可执行文件的反汇编、符号、内联信息/调试映射与摘要。现有单一`kernel.c.o`审计不能独自代表LTO最终代码。
3. 检查解封装实际可达路径，包括消息编码、压缩、比较/拒绝选择及W4候选；无调用点的离线符号不作实际执行证据。
4. 编译器版本/目标架构/优化参数/函数固定属性逐项列明。人工分支即使外层-O3，目标仍受-O0约束，不能写成对目标函数完成了O3测试。
5. LTO不支持、指令分类不支持和符号映射失败保留为失败/unknown并修复工具；不能按未发现分支判阴性。先保留编译器生成的真实产物，不能人为加回noinline来使正式产物易审计。

**验收：** 24格均有成功证据或明确未闭合原因；必做可用配置需实际补完，不能只用N/A消除工作。结论逐配置列出产物机制、端到端效应、性能与覆盖盲区。不开启LTO的构建不能代替O2+LTO。

**图表：** 编译配置×机制×检测矩阵、实际内联路径例图、功能与性能表。

**目标：** 在真实不同处理器上复测同一方案，并解释一致与不一致之处。

| 平台 | 本轮用途 | 当前条件 |

## 7. 采样、时间与存储预算

以下均为初始规划数，M2试点完成后在正式数据产生前冻结最终值。

| 批次 | 规划规模 | 用途 |
|---|---|---|
| 开发小试点 | 每配置2会话、每类1000次 | 确认测量与估算资源；仅探索 |
| 单平台主确认 | 20会话×4变体×5类×5000次=2,000,000次完整调用 | 主检测、防护及会话重复性 |
| 第二处理器确认 | 同上，另2,000,000次 | 跨平台结论；不合并主平台样本 |
| 主平台Clang O2确认 | 20会话×4变体×5类×5000次=2,000,000次 | 与GCC主确认一起覆盖8个重点形态 |
| 编译矩阵其余16格 | 每格5会话×5类×5000次，共2,000,000次 | O0/O1/O3/O2+LTO各4格；不重复计O2 |
| 函数追踪 | 先每格每类1000次；按事件数与开销限流 | 总事件量单独预算，不能仅按解封装次数估算 |
| 网络 | 每场景5会话×4变体×2个主组×5000请求=200,000请求 | 5场景起步约1,000,000请求，主组构成/密钥配平同本地 |

可用历史约30—50微秒/次仅估算量级：两平台主确认合计400万调用的纯内核累计约120—200秒，另有编译矩阵400万次；O0和其他平台可能明显更慢。这不包含生成/KAT/预热/切换/写盘/分析/回滚和追踪，不能据此承诺几分钟完成整套实验。新采集按唯一run_id记账，能共享的主确认原件只计一次。

网络通常决定墙钟：200,000次请求在平均RTT 1/10/20ms且单在途时，纯等待分别约200/2000/4000秒，尚未计入超时、间隔和软件。按每场景90分钟软上限、总体8小时首轮网络预算预留；若试点显示5000请求/组无法在预算内完成，先冻结统一新预算或降低可选噪声强度，不能在确认途中删高噪声数据。达到上限保留未完成和删失结果。

建议本地/服务器各预留20—50GB磁盘，先测每事件/样本实际大小再冻结；上限不是最终分发包大小。CPU足够，无GPU需求。各新模块运行前按计算资源检查流程核验真实可用CPU、负载和空间，不能因为历史机器信息存在就视为当前可用。
