# 单物理核预留与恢复的管理预演合同

2026-10-09。前置为main的09034bf及其原始只读记录。用户允许必要实验重跑，并提出只预留几个CPU的路线。本合同只处理一个物理核的可恢复管理路径，不启动密码实现、历史活跃变体、计时、统计检验或新性能确认；R02/R04及真人材料的完整目标继续保留。

对象为nss-m、Linux6.17、systemd255/cgroup v2、在线CPU0-31，CPU2和18仍为同一物理核。实验预留这两个逻辑CPU，只让一个/bin/true空任务使用CPU2；其他普通任务在其余30个逻辑CPU上继续运行。普通任务预留不称内核isolated partition，也不证明零干扰或实际执行轨迹。

只使用标准库的管理编排脚本，复用已封存第二版元数据清单。它不替换任何C11算法、实验CLI、生成器、测试、计时、统计或运行校验，不建立通用CPU管理框架。源码只在本仓库维护；远端源码及输出使用/home/nss-marker/yhr/Cry下的新目录，实际控制脚本和恢复状态复制到本次root拥有的/run新目录，保留原source/run。口令只用于交互认证，不进入源码、配置、命令或日志。

## 严格限定的原状态

新检查须满足原CPU请求全部为空、有效CPU为0-31或继承，预留CPU在线且拓扑仍一致，无普通线程亲和性交集冲突、读取或身份缺口。现有十个顶层单位与约定集合相同；非根partition均为member，根无isolated集合。StartupAllowedCPUs、AllowedMemoryNodes、StartupAllowedMemoryNodes及非根原始cpuset.mems为空，系统不处于启动/停止过程。任何不同状态均停止本次预演，不临时扩展为通用恢复器。

保存实际拓扑、元数据原件、单位属性/配置来源、各组CPU与内存节点/控制器状态及普通TID的启动时间/cgroup/亲和性。十个原顶层单位两处候选50-AllowedCPUs.conf须原先不存在，记录父目录原存在状态；不接受覆盖原文件的路线。恢复必须回到原属性及原文件不存在的形状，不能仅以命令返回0验收。

## 固定顺序与停止边界

1. 新检查和原状态快照通过，源码及输入摘要登记。先创建本次独立标记计时器，实际观察其自主触发并读取标记/单位状态，验证后清理标记单位；此时不改变CPU限制。
2. 在配置变化前建立独立恢复服务及45秒触发计时器。显式设置计时器精度与零随机延迟；45秒是管理故障回退候选时间，不是硬实时承诺或科学计时精度。恢复服务另有300秒执行预算，外部启动等待315秒，覆盖逐项5秒命令上限与核对余量；不把触发时间误作恢复完成期限。工具观察保持短轮询，不因观察超时重启任务。正常路径也启动同一个恢复服务，由systemd合并执行，避免两个恢复器并行。恢复先同步停止本次控制器并核对其进程组为空，不能与控制器互相等待。
3. 控制器限定20秒启动窗口，子命令有超时；只用systemd的运行时AllowedCPUs。无连字符的唯一实验slice置于根层，CPU集合2,18；十个其他顶层单位限定到0-1,3-17,19-31。每次发送设置前先记录“可能已修改”，超时或丢失回执也进入恢复。回读实际内核集合、配置归属及顶层变化；任何差异停止依赖的任务。
4. 空任务为Type=oneshot、RemainAfterExit=yes、CPUAffinity=2、AllowedCPUs=2；不使用会等待其停用的--wait。记录公开退出状态和管理配置，不能由/bin/true成功推出实际CPU执行轨迹。没有睡眠、空转或新测量载荷。
5. 正常与异常均进入独立恢复服务。逐项处理所有“可能已修改”的单位；原属性恢复为空，仅删除原先不存在且内容/归属匹配本次受限或重置值的文件。仅移除本次新建且为空的父目录，再重新加载并回读。出现同期第三方修改时保留差异，不盲目覆盖。逐项失败汇总，不因一项失败跳过其余恢复；每次恢复尝试单独留原件，当前结果只作指向最新尝试的入口。检查与写入之间仍有无法原子锁定的管理竞态，不把本预演宣称为并发管理员操作下的无条件保证。
6. 核对原单位属性、实际CPU/内存节点、控制器与原文件存在状态；对仍存活且启动身份/cgroup一致的普通线程只检查亲和性，不写回。退出或同期变化另列，不重启他人任务。全部恢复核对通过后才停止恢复计时器并清理本次单位；失败则保留root状态和恢复路径，明确报告，不开始正式采集。

源码须先通过无配置写入的自检及独立审查，再提交固定准备模块，之后仅执行一次管理预演。失败原件保留，不自动循环或启动正式实验。实际执行、配置、恢复及清理各自出具回执；准备通过不写成预演通过。

保留源摘要、前置检查、标记触发、单位设置及原值、空任务退出、可能已修改清单、恢复回读、全部失败和本次单位清理状态。结果只回答管理路径能否在该次状态下建立并恢复普通任务CPU预留；不签收频率锁定、期间无干扰、正式数据或统计前提。频率控制仍按[原候选](../aris-linux-math-software-20261009/FREQUENCY_CONTROL_PROPOSAL.md)，下一研究协议和人员材料缺口不因本预演消失。
