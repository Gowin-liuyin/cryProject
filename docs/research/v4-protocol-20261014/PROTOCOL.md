## 1. 沿用的判定

分组、ABBA、Holm 族、方向一致性、空窗协变量、覆盖率定义、调用预算和交替对照的配对规则，仍以 `v4_group_confirmation_20261013` 为准。下面只写相对那份文件必须替换的部分。

- 带仍是闭区间 `4257000..4343000` kHz。
- 覆盖率仍是带内区间长度除以首尾时间跨度。一次读数代表直到下一次读数的区间。
- 每条确认会话和每一轮交替计时的覆盖率阈值仍是 `0.99`。低于阈值时主令牌是 `not_run`。
- 确认会话数仍是开发阶段已经导出的 `S=40`，每条密文重复数仍是 `R=2`。这里不重新估计功效，也不改族水平 0.01。
- 3.7.6 与 3.7.7 仍是探索性记录，不转入 Holm 族。3.7.5 仍只是固定长度网络交互的可行性记录。
- QQ 图、Shapiro-Wilk 和会话内滞后 1 自相关仍只在确认会话集合形成之后作为描述输出。探测失败或确认未跑完时不编造这些数值。

## 2. 新的频率请求

`v4_window run` 保持 20261013 的行为：只写计时 CPU 及其唯一 SMT 兄弟的 `scaling_min_freq` 和 `scaling_max_freq`。确认和交替对照不再使用这个子命令。

本规则的计时进程使用 `v4_window run-held`。它只碰两个逻辑 CPU，外加一个全局 boost 文件：

1. 先读并保存 `/sys/devices/system/cpu/cpufreq/boost`，以及 CPU2 和它的唯一兄弟的 governor、EPP、min、max。兄弟列表不是恰好两个 CPU，或 boost 文件不能读，则不写任何字段并停止。
2. 把 boost 写成 `0`。
3. 把这两个 CPU 的 min、max 都写成 `4300000` kHz，顺序仍是先 min 后 max。
4. 把这两个 CPU 的 `scaling_governor` 写成 `performance`。
5. 把这两个 CPU 的 `energy_performance_preference` 写成 `performance`。
6. 读回上述字段。有任一字段与请求不一致，就恢复基线并停止，状态是 `stopped_policy_readback`。不改请求字符串，也不改去试另一个 governor、EPP 或 boost 值。

不写其他 CPU 的 governor、EPP、min、max，也不做 cpuset 隔离。boost 文件是全局的，所以写 `0` 会影响整台机器；退出路径必须把它设回进入时读到的原值。

请求落地前不启动计时子进程。落地后每 20 ms 读一次 CPU2 的 `scaling_cur_freq`，最多 100 次。连续 3 次落在带内才启动子进程。这 3 次和其间的等待记在 `precondition-samples.csv`，不计入覆盖率。2 秒内没有连续 3 次带内，就恢复基线并停止，状态是 `stopped_precondition`，不消耗确认种子。

任何写过字段的退出路径都把 boost、governor、EPP、min、max 设回基线。恢复后的读回必须与基线一致，否则状态是 `RESTORE_FAILED`，后续探测和会话都不再开始。

## 3. 探测

在任何一把新确认种子或交替测量种子之前，先做 12 次空转探测。空转只占着 CPU2 读钟，不做密钥封装或解封装。

- 前 8 次每次 40 ms。
- 后 4 次每次 2000 ms。
- 顺序就按上面这 12 次，不改时长，不追加次数。
- 每一次都要 `sample_count>=2` 且 `coverage_fraction>=0.99`，并且窗口退出码为 0。
- 12 次全部通过，并且 32 路 CPU 的 governor、EPP、min、max 以及全局 boost 与进入时一致，探测才算通过。
- 任何一次未通过就停。失败目录原样保留。不放宽 0.99，不放宽带，不改第 2 节的请求，不开始确认，也不开始交替对照。

这 12 次不是正式解封装，不计入 5120 的确认预算。

## 4. 通过之后才使用的种子

探测通过之后，确认会话 `s=1..40` 使用 `20261016000+s`。交替对照的顺序种子是 `2026101707`，第 `r=1..5` 轮两侧共用的测量种子是 `20261017000+r`。splitmix64 的三个常数仍是 `0x9E3779B97F4A7C15`、`0xBF58476D1CE4E5B9`、`0x94D049BB133111EB`。最低位为 0 时先测分支再测掩码。

这些种子只在本规则的 `run-held` 窗口里使用。探测未通过时一个都不使用。

确认和交替对照的其余停止条件仍按 20261013 协议：覆盖率低于 0.99、窗口退出码非 0、完整性不符或墙钟超过封顶，都保留已写出的文件并停止，不换种子补抽。
