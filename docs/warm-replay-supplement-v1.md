# 精确复算启动成本敏感性补充 v1

在新增测量和实现前冻结。本补充沿用 controlled-comparison-v1 的备用方向，
不改变旧合同、阈值、数据或成功条件，也不增加第三条研究路线。

原完整进程比较纳入 Python 启动与 SciPy 导入。补充回答：在给予强基线预先导入的条件下，
相同精确复算是否仍有有限任务效率增量。已见过的八个文件只作成本边界敏感性复核，
不冒称新独立确认集合、不调参、不外推总体速度。

| 项目 | 冻结规定 |
|---|---|
| 数据 | evidence/controlled-comparison-20261007/confirmation-data 的全部八组 CSV/plan，原字节及摘要保持；null/effect/ties/drift 各两份 |
| 平台 | 与旧比较相同的本机 Apple M5/ARM64 macOS；真实记录本次系统、编译器、源码、二进制和负载，不跨平台合并 |
| 强基线 | 现有 SciPy1.16.3/NumPy2.3.5 脚本及相同完整 2^20 成对交换、abs(sum)、上尾、向量化、batch4096；参数不改 |
| 预导入协议 | Python 完成所有模块导入及版本核验后用 SIGSTOP 宣告就绪；C 观察器用 waitpid 确认 SIGSTOP，读取 CLOCK_MONOTONIC，再 SIGCONT。就绪前不得读取、解析、校验或计算任务数据 |
| 基线指标窗口 | 从 C 发出继续前的时钟读数到子进程完成，包括文件读取、摘要核验、解析、全部交换、输出及退出；Python 导入在窗口外，单独逐次记录其就绪耗时 |
| 候选指标窗口 | 保持原 C CLI 完整进程窗口，包含 fork/exec、读取、摘要核验、解析、全部交换、输出及退出。候选仍承担自身启动成本，此非纯内核比较 |
| 次数/顺序 | 八份各三次两方法，共48次复算，沿用旧合同按文件和重复序号交替顺序；每个基线进程单独预导入。无额外预热、数据缓存或尾计数复用 |
| 指标 | C 候选窗口/基线就绪后窗口的24个比值、中位数、范围；每份候选最大/基线最小；完整比较墙钟、两种窗口合计和24次就绪合计 |
| 资格 | 48次全部成功，所有尾计数及分母逐项相同，CSV与plan摘要前后不变，版本严格一致；任何准备失败、超时或数值不一致为证据不足 |
| 有限效率条件 | 每份候选最大耗时均小于基线最小耗时，且24比值中位数≤0.5；不满足则明确未成立，不换任务或放宽条件 |
| 预算 | 本补充正式运行一次，包含24次就绪、复算与观察器管理的全部墙钟最多120秒；软件检查和文档制作另列，不宣称完整研发成本闭合 |
| 不确定性 | 固定八任务、每份三次观察；不构造总体置信区间，不评估密码总体误报/检出能力，合成任务不等于秘密泄露 |
| 失败产出 | 保存退出码、部分账本、日志和输入摘要；不覆盖旧输出，不用缺失准备记录补成完整结果 |

本补充至多支持专用 C11 精确复算在此任务集中的流程效率。Gray 更新、成对随机化、
精确枚举均为既有方法；不称方法首创、不比较正确配置 dudect/RTLF 的灵敏度，
不称 ML-KEM 解封装加速、防护有效性或全部竞赛要求达标。
