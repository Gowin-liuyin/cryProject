# 固定统计检验与正式确认

采集程序只保存原始时间、不做判定；判定由独立的 `analyze` 完成。
该程序是单一用途的固定检验工具，不是统计平台：没有可调参数、没有绘图、不读取网络、
不改写输入数据，也不会按数据选择检验方法。

```sh
mkdir -p runs
run_directory=$(mktemp -d runs/stats.XXXXXX)

build/cmake/reference/measure stats-reference 20260930 5000 \
    "$run_directory/reference.csv" "$run_directory/reference.meta"
build/cmake/analyze "$run_directory/reference.csv" "$run_directory/reference.report"
```

参数为 `analyze CSV_FILE REPORT_FILE`。报告路径必须是新文件，不覆盖已有结果。
退出码 0 为成功，2 为参数个数错误，1 为读取、校验或写入失败。
`analyze` 与实现变体无关，只有一个产物；报告中的 `implementation` 来自 CSV 内容。

## 预先规定的内容

以下全部固定在 `src/analyze.c` 中，采集数据之前即已确定，不按结果调整：

- 比较族为五类输入的全部 10 个无序类别对，顺序固定，其中
  `message-zero:message-ones` 标记为 `primary=yes`，对应分支方向假设。
- 族显著性水平 `alpha_family=0.001`，Bonferroni 校正后单比较水平 `1e-4`。
- 主统计量为并列修正、带连续性校正的 Mann-Whitney U 正态近似；判定只依据它。
- 辅助统计量为 Welch t 及其 Welch–Satterthwaite 自由度，同样用正态近似给 p 值。
- 分位点按排序后最近秩取值，不插值；不删除离群值，不裁尾，不做任何平滑。
- 效应量报告 `effect_size_first_greater = U1/(n1·n2)`，即第一类取值更大的成对比例。

判定标签只有四种：`significant`、`not_significant`、`degenerate_no_variation`
（方差为零）、`insufficient_samples`（任一类不足 2 个样本）。

## 输入校验

`analyze` 逐行严格校验，任一不符即拒绝并且不创建报告：固定表头；每行恰好六列且各列非空；
`run_id` 与 `implementation` 全文件一致且字符集受限；类别名必须是登记的五类；
`sample_index` 必须等于行序号；耗时为非零十进制无符号整数；单位必须为 `ns`；
末行必须以换行结束；记录数上限 200000。负数、溢出、尾随字段、截断尾行、
跨行改变的运行编号和实现名都会被拒绝。

报告记录被分析 CSV 的 SHA3-256（`csv_digest`），可用
`openssl dgst -sha3-256 <csv>` 独立核对，用于把统计结论绑定到具体数据文件。

## 已知的数值边界

`rank_p` 与 `welch_p` 由 `erfc` 计算；`|z|` 超过约 38 时结果下溢为 `0`，
此时应以报告中的 z 值为准，不应把 `p=0` 读作精确零。
正态近似在每组样本较少时偏乐观，报告同时给出 n1、n2 和自由度供判断。
时钟分辨率记录在 `.meta` 中；本机为 1000ns，因此单次取值是量化后的结果，
秩检验对这种量化更稳健，但不能把量化后的中位数差当作真实差的精确估计。

## 独立正确性检查

CTest 的 `analysis` 项用解析上可算出答案的合成数据检查统计实现，预期值不由本程序产生：

- 两组完全分离（20 个 1000ns 对 20 个 2000ns）：`rank_u1=0.0`、效应量 `0.000000`、判显著。
- 两组分布完全相同（各 10 个 1000ns 与 10 个 2000ns）：`rank_u1=200.0` 正好等于期望值，
  连续性校正后 `rank_z=0.0000`、`rank_p=1`、判不显著。
- 全部取值相同：方差为零，输出 `degenerate_no_variation`，不给显著结论。

同一项还检查上述全部拒绝场景、报告不覆盖已有文件，并在两版真实采集数据上跑完整流程。

## 本机确认结果

证据目录 [evidence/statistics](evidence/statistics/README.md)，源码提交 `d322cbf`，
Apple M5 / ARM64 macOS，两个公开种子各采集两版、每版 25000 条（五类各 5000）。

- 参考版两次采集均为 0/10 显著，最大 |z|=1.74，类别间均值差不超过 23ns。
- 缺陷版两次采集均为 7/10 显著。其中 6 项是「恒定消息类」与「变化消息类」之间的比较，
  均值差 711–800ns，效应量 0.819–0.844，|z| 在 62–67 之间。
- 缺陷版三项「变化消息类之间」的比较（valid、bit-flipped、random 互比）不显著，
  与这三类的解密消息位分布相同这一预期一致。
- 缺陷版主比较 `message-zero:message-ones` 两次分别为 p=5.33e-05 和 p=1.36e-06，
  均值差 -83.2ns 与 -55.8ns：方向一致但幅度远小于主效应，且跨运行不稳定。

## 机制解释与其边界

缺陷版编码函数按解密消息位执行 `if/else`（见 [缺陷说明](defect.md) 与实测反汇编）。
`message-zero` / `message-ones` 的 m' 为全 0 / 全 1，256 个分支方向恒定；
`valid` / `bit-flipped` / `random` 的 m' 位分布接近均匀，分支方向逐位变化。
观察到的主要差异出现在「方向恒定」与「方向变化」之间，与分支可预测性的解释一致，
而不是两条分支本身代价不同；主比较只呈现次级差异，也符合这一解释。
m' 由私钥参与的解密产生，因此分支条件具有秘密依赖。

这一因果解释仍是解释：本实验没有分离分支预测、指令缓存与前端取指的各自贡献，
也没有测量单次分支代价。参考版与缺陷版使用同一采集程序、同一种子、同一类别顺序和
同一输入构造，两版的缓存与序列效应因此受控，但这只支持「差异由编码补丁引入」，
不支持「参考版恒时」。
在同一函数级优化控制下把分支换成掩码选择后，同一固定检验判定为 0/10 显著，
这把归因进一步收窄到分支本身，见 [防护说明](mitigation.md)。

## 不包含的内容

没有未知密钥攻击、没有密钥恢复、没有单条密文的判定过程。
两个固定消息类在同一密钥下重复同一密文，不能当作独立随机密文总体的样本。
结论限于 Apple M5 / ARM64 macOS 的这两次采集；真实 x86_64 Linux 主机的同组采集与确认
仍未执行，`.meta` 中记录的未固定亲和性与频率也未改变。
恒时编码补丁的对照实验见 [防护说明](mitigation.md)，使用的是同一套固定检验。
