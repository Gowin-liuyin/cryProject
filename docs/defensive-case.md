# 人工机制防御案例档案

对象为固定mlkem-native/ML-KEM-768的公开人工消息编码回归，不是上游新发现的部署漏洞。
机制来源clangover指向旧Kyber，FIPS203身份属于本项目所用新库，不替换旧案例原身份。
来源、许可、补丁及固定向量见sources.md、patches和tests/vectors；本輪摘要及历史复算见
[案例核验](evidence/defensive-case-20261007/README.md)。

| 层次 | 对应证据 | 可解释范围 |
|---|---|---|
| 算法环节与源依赖 | defect.md及三个原补丁 | 解封装解密得到消息，隐式拒绝所需重加密进入消息编码；人工if条件具有秘密依赖 |
| 数学语义 | Decompress_1把位映射为0或1665；掩码对照 | 目标编码输出保持；比较、J(z∥c)及隐式拒绝不改；不能靠跳过验证获得恒时 |
| 历史实际产物 | mitigation/deployable/Linux模拟档案及各自摘要 | 区分独立符号与内联段；分支存在/消失只覆盖该对象，不能推出全库恒时 |
| 新实际产物 | native-final-20261007三个正常/掩码benchmark及人工CLI静态反汇编 | 新Linux构建身份可核查；人工CLI不是新计时证据，地址不能跨构建复用 |
| 输入及权限 | timing.md、statistical-audit.md | 公开种子白盒夹具；固定消息组反复两个密文，时间记录不等于独立密钥/密文数 |
| 历史观察 | 五种子四版原CSV与两套名义报告 | H1人工回归4/5；H2回归5/5、参考/正常优化未检出各5/5，掩码对照1/5残差显著 |
| 防护与功能 | 原掩码/值屏障补丁；本轮四版KAT/差分 | hardened同优化控制；deployable正常优化形态；上游编码已无分支，不宣称新上游修复 |
| 复测与限制 | 历史同平台前后；新原生普通性能 | 新普通性能不代替新的受控机制前后重采，R05–R07因果/防护闭环仍部分 |

同一类别顺序不等于物理缓存、预测器、频率和调度状态相同。并列修正不处理序列依赖，
两轮不同假设及1e-4/1e-3阈值不能相互当更强证实。hardened残差、H1失败、未归档动机值
及旧措辞审计均保留；只读复算没有新增受控时序证据。

威胁模型：操作者有本地源码、编译及执行权限，控制公开测试输入，种子可重建测试私钥；
观测公开运行状态与时间，未输出私钥/共享密钥/内部验证标志。不是未知密钥攻击、远程网络
攻击或密钥恢复。人工回归有工程教学价值，无法自动满足部署漏洞发现或完整安全认证。

后续防御性补证需先固定对象、平台、同负载与运行单位、控制条件、方法及停止规则，
重新取得受控防护前后数据并功能回归；无法满足依赖、成本或完整性则停止并保留不足。
本轮不构建新的主动漏洞复现或密钥恢复流程。
