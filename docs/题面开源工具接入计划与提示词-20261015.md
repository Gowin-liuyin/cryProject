# 题面开源工具接入计划与执行提示词（2026-10-15）

## 2. 总体计划（按周）

### 第 0 步：冻结身份（半天）

- 工作根：内网已有 `.../liboqs010-historical-20261015-86131c2` 或同步后的 cryProject。  
- 证据基线：`docs/evidence/liboqs010-locked-20261015/`（未修 CI 不含 0；982c762 CI 含 0）。  
- 新建目录：`docs/evidence/tooling-strengthen-20261015/`（或按执行日改名）。  
- 第三方源码建议放：`third_party/{RTLF,dudect,mona-timing-lib,ctgrind,Microwalk}/`（gitignore 或 submodule，勿改其上游逻辑冒充阳性）。

### 第 1 步：P0 统计三器（1–2 天）—对应题面第 4/7 条

1. 从锁频 CSV 抽出两类：`message-zero` / `message-ones` 时间列。  
2. **RTLF**：α 预冻结（建议 `0.01`）；对未修、已修各跑一次。  
3. **dudect**：写 thin harness 调 `mlkem_decapsulate` 或复用 measure 输出；固定迭代预算（写入协议）。  
4. 与已有正态近似 CI 并表：三器在未修应一致「可区分倾向」，已修应一致「不拒绝/转阴」（若不一致，记分歧，不择优隐瞒）。  
5. （可选）Mona 同数据对照一行。

### 第 2 步：P0 动态定位（1–2 天）—对应题面第 5 条

1. **ctgrind / TIMECOP poison**：poison 解密消息或私钥相关缓冲；未修 historical-clangover 应报秘密相关分支；已修应消失或仅剩可解释公开依赖。  
2. **（可选同周）KyberSlash Valgrind 补丁**：编一份带补丁的 Valgrind；对当前 `*_ref` 主阳性预期以**分支**为主（除法未必命中）；对 mlkem-native / 修后做阴性对照。  
3. 反汇编证据继续保留（已有 `bt/jae` vs `cmov_int16`）。

### 第 3 步：接函数级插桩（1 天）—题面增强

- historical 变体接既有 8 阶段包装；看消息编码/重加密是否进前三。  
- 明确：插桩改变时序，排名只作候选，不替代无插桩端到端三器。

### 第 4 步：P1 Microwalk（可选，2–3 天）

- 仅 x86、有 Pin 许可时做；输出泄漏点排名对照 `poly_frommsg`。  
- 无 Pin 则跳过并在证据写「环境不具备」。

### 第 5 步：报告与 R12（1 天）

- 正文增加「开源检测器复算」小节：仓库 URL、commit、命令、α/预算、未修/已修表。  
- R12 候选表述：在相同锁频样本上接入 RTLF，并与既有 CI、dudect 一致完成防护前后对照（**不**夸大成检测灵敏度世界第一）。

- [ ] Valgrind/ctgrind：未修有秘密分支类报警，已修对应项消失或可解释

```text
# 角色
你是 cryProject 内网执行 agent。任务：按「题面开源工具接入计划」在 nss-marker（或已锁频的等价 x86）上，把开源检测/定位工具接到已有 liboqs 0.10.0 historical 阳性证据上，产出可复算目录。用中文阶段性汇报。

# 硬约束
- 不做密钥恢复、不跑 clangover 的 key-recovery PoC 作为交付。
- 不修改 vendor/liboqs-0.10.0/ 源码来制造阳性。
- 未修与已修必须同锁频规程、同 seed/样本口径对比。
- 阳性构建必须关 AVX2 分发（OQS_DIST_BUILD 不够；还需 OQS_USE_AVX2_INSTRUCTIONS 与 OQS_ENABLE_KEM_ml_kem_768_ipd_avx2，见 docs/historical-liboqs-0.10.0.md）。

# 工作步骤

## A. 准备
1. 确认锁频证据目录存在；记录未修/已修二进制路径与 SHA。
2. mkdir docs/evidence/tooling-strengthen-$(date +%Y%m%d)/
3. clone 上述 P0 工具到 third_party/，写入 REPOS.md（URL + commit + 日期）。

## B. RTLF
1. 从锁频 CSV 导出两类时间（message-zero vs message-ones）为 RTLF 可读格式。
2. 预冻结 α=0.01（若改值必须先写进协议再跑）。
3. 对未修、已修各分析一次；保存完整命令与输出。
4. 若环境缺 R，先安装再跑；不要用“环境不便”省略而不记原因。

## C. dudect
1. 最小 harness：两类输入调用同一解封装入口（或对接现有 measure 流水线）。
2. 预算写入 META（迭代次数、亲和核、是否锁频）。
3. 未修/已修各跑；保存判定与关键统计量。

## D. Valgrind / ctgrind
1. 标准 Valgrind + poison：标记消息/私钥相关缓冲；跑未修 historical 与 982c762 修后。
2. 期望：未修出现秘密相关条件跳转类报警；已修对应报警消失。
3. 有余力再打 KyberSlash varlat 补丁编 Valgrind，跑一次除法类检查（预期本主阳性以分支为主；除法结果照实记）。

## E. （可选）插桩排名
对 historical 诊断构建跑既有 localize/trace；保存前三阶段；注明插桩扰动。

## F. （可选 P1）Microwalk
仅当 Pin 可用；否则在 RESULT.md 写跳过原因。

## G. 汇总 RESULT.md
表格列：工具 | 未修结论 | 已修结论 | 命令/路径 | 与锁频 CI 是否一致
明确三句结论：
1) 定位（汇编 + Valgrind）
2) 统计（CI + RTLF + dudect）
3) 非密钥恢复；R02/R04 其他开放项不因此自动关闭

# 禁止
- 把 clangover 跑通密钥当作作品成功标准
- 未锁频数据与锁频数据混并
- 只报对作品有利的检验、隐瞒 RTLF/dudect 分歧
- push 远端；本地 commit 可，需用户明确才 push

# 汇报格式
每完成 A–G 一步：阶段、命令、结果摘要、证据路径、阻塞。
全部完成后给出 HANDOFF_DONE.md 路径与 8 条以内 bullet。
```
