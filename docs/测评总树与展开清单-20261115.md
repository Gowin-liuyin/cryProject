# 测评总树与展开清单（2026-11-15）

本页把 ML-KEM-768 侧信道测评空间组织成一棵七维树，标明现有资产的坐标、范式内可拓展的节点、只做边界声明的节点与竞赛红线节点，并给出一份可直接开工的展开清单（含题面合规对照与执行纪律）。本页是规划文档，不改动任何既有证据；清单执行时每项另立新证据目录与新提交。

**状态标记**：★ 已有实证资产（给出证据路径）｜◇ 范式内可拓展（复用现有臂与工具链）｜△ 只做边界声明｜✕ 竞赛红线排除。

**与现有文档的关系**：R11 威胁模型（`docs/evidence/r11-threat-20261016/THREAT_MODEL.md`）回答"本轮假设了什么攻击者"；R05 排查表（`docs/R05-全流程排查表.md`）回答"解封装五步 × 六类来源查到哪"；附录 A 表 T26 回答"题面 12 条满足到哪"。本页是三者的统一骨架：先定位（我们在树上的坐标），再展开（剩余节点怎么补）。

## 2. 展开清单（详细版）

编号沿用 R 序列顺延（R17 起为占位号，执行时以实际证据目录为准）。每项给：目标、树节点、题面归属、复用资产、新增工作、对照臂、判定口径、产物、成本与风险。

### R0a（P0）M2 `poly_frommsg` 分支自研修复闭环

- **目标**：把 R05 实锤的 M2-c 缺口（KyberSlash 修复 `272125f` 只除除法、`poly_frommsg` 的 `bt/jae` 分支原样保留，两侧指令字节相同）用**掩码选择**自行修复，走完"改 → 同环境重采 → 前后对比 → 泄露降低"全闭环。
- **树节点**：B1.1 × E1 × F1；**题面归属**：直接闭第 6 条缺口①（题面明文列举"掩码选择"）+ 第 7 条（自研防护闭环落在真实 ML-KEM 上）。
- **复用**：kyber 两棵 vendor 树与既有构建链；1000 例等价 harness（500 随机 + 500 逐字节篡改）；100 例 round3 KAT；秘密标记 Memcheck、反汇编、锁频采集与 Holm 家族全链。
- **新增**：修复补丁（新提交，打在 vendor 副本；参照 M3-c `message-constant-time.patch` 的位掩码 + ct 选择写法移植到 kyber ref 的 `poly.c`）；修复臂的完整前后对比批次。
- **对照臂**：未修 a621b8d / 上游已修 272125f（仍含分支）/ 自研修复（预期 0 分支）。
- **判定口径**：①产物层——反汇编 0 个秘密相关条件跳转；②定位层——秘密标记 Memcheck 0 contexts（对未修臂的既有阳性）；③语义层——KAT 100/100、1000 例等价 diff 全空、隐式拒绝逐例等于规范值；④统计层——修复臂主类对锁频家族 CI 含 0 且 Holm 不拒绝；如实分层记录（参照 M2 教训：端到端未检出≠无泄漏，定位层阳性是主证据）。
- **产物**：`docs/evidence/rXX-m2-branch-fix-<日期>/`，报告表 T18 M2-c 行改判、附录 A 第 6/7 条状态更新。
- **成本/风险**：中。风险是端到端仍测不出分支代价（几十 ns 量级效应 vs MDE 25–67 ns）——预注册时就按"定位层为主判据"写死，避免事后解释。

### R0b（P0）vendor 树泄露渠道审计

- **目标**：把 R06 的静态/动态泄露面审计扩到 M1/M2 真实防护链所在的 vendor 快照（第 6 条缺口②：现有审计只覆盖自有实现与 harness）。

- **新增**：扫描范围限定为四棵 vendor 树内**防护补丁实际触碰的文件及其调用链**（`poly.c`、`indcpa.c`、`verify.c`/`kem.c` 的 cmov、错误与日志路径），逐文件登记 `abort`/`fprintf`/`errno`/返回码中接触秘密或验证结果的面。
- **判定口径**：A 类（秘密内容）/B 类（验证结果）计 0 条为通过；非零条如实登记并修复（修复须回上游写法核对，不私改 vendor）。
- **产物**：`docs/evidence/rXX-vendor-noleak-<日期>/AUDIT.md`。
- **成本/风险**：低，纯软件、无采集。风险是范围蔓延——只审防护链文件，不做 vendor 全树扫描。
