# 配对执行器成本边界补充 v1

本文件补充已提交的执行规约，不改写原合同或规约；本轮没有正式开发/确认数据。
每方法CLOCK_MONOTONIC窗口覆盖预留账写入、fork/exec、阻塞等待、数据和摘要核验。
子程序自己的成本文件保留阶段边界；其最后一次成本写入由父进程窗口覆盖。

独立父观察进程另外测量执行工作进程从fork前到退出后的完整墙钟。
扣去两个方法已记录窗口之和，剩余是计划检查、库/产物核验、日志、结算账、清单及
流程开销，按共同成本平分。这里仅从完整流程差额分配共同成本，不扣空计时窗口，
不改动任一密码解封装原始时间。

观察结果最后的记账与发布也有成本：以1秒截止覆盖，按共同成本区间[0,1秒]计入
上界和两方法墙钟预算；超时或写入失败不能发布成功上下文。
该上界故意保守，5%成本判定必须用共同成本区间中的最不利比值，不能借大共同上界
稀释方法开销。精确成本标记因此降为bounded，未闭合的外部准备成本仍是unclosed。
所有数学报告注明模型及条件，不能由bounded成本和软件夹具推导平台收益。

工作账用独立锁和原子替换维护聚合值，原始尝试文件、退出码和失败输出独立保存。
调用前把N+100调用以及该方法剩余墙钟作为未结算预留写盘；正常完成按实数结算。
信号终止或进程消失留下预留，后续拒绝继续，必须先审计。失败尝试按保守调用上界
扣入辅助预算；不自动重试。开发K4和K16必须复用同一本账，不给参数各开独立预算。
