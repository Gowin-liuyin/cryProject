# Mac 到 10.144.144.5 的直接 TCP 尝试

2026-10-11 从这台 Mac 直接连接，没有使用 SSH 隧道，也没有给本地 CSV 加噪声。

`nss-m` 上的现有 `network_server` 曾监听 `0.0.0.0:18021`。同一台主机上的本机探测可以连上。Mac 上的 `network_client` 连接 `10.144.144.5:18021` 后没有写入数据行。`client-header-only.csv` 只有表头 `request_index,elapsed_clock_counts,clock_path`，应答文件长度为 0。这不是一次 RTT 样本。

随后从同一台 Mac 探测 2730 个 TCP 端口。完成握手的只有 22、9010、9100 和 9400。连接被拒绝的个数是 0，其余 2726 个超时。22 是 SSH。9010 是别人的 uvicorn，没有关闭或占用。9100 和 9400 已有监听，没有改绑。没有修改防火墙。

因此没有保存到行数大于 0 的直接 RTT，也没有完成第二条单请求核对。客户端成功时用 `CLOCK_MONOTONIC`，差值单位是该时钟的纳秒计数。这次没有成功行，所以没有实测 RTT。三档 veth 记录不能代替这条路径。
