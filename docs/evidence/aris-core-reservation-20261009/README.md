# 少量CPU预留的只读可行性核查

2026-10-09，针对用户提出的“CPU的几个核应该不影响吧？不能独占吗？”核查裸金属主机的拓扑、cgroup和现有权限。原始工具返回见[feasibility.json](feasibility.json)，候选实施范围见[单物理核预留方案](../../research/aris-linux-math-software-20261009/CORE_RESERVATION_PLAN.md)。

实际CPU2的thread_siblings_list为2,18，可选择一个物理核的两个逻辑线程，其他30个逻辑CPU继续使用。目标机为Linux6.17、systemd255、cgroup v2；普通会话没有cpuset委派，普通账号不能写频率或根cgroup文件。sudo策略列出ALL命令权限，但免交互true返回1并提示需要密码；本次没有做sudo密码认证，不把免交互失败解释为没有管理权限。

本次没有修改CPU集合、频率、SMT、IRQ或运行配置，没有停止其他任务，没有开始新计时。SSH控制连接已正常关闭，自己的空临时目录已移除；仓库、证据及命令文本不保存口令。

拓扑和策略快照只支持预留路线的可行性判断，尚未检查全部任务的实际亲和性冲突，也没有证明核心已经预留。其他任务少一个物理核及共享缓存、内存和功率温度的影响不能假定为零。正式采集仍须核对实际设置、冲突、恢复和研究协议；R02/R04保持部分签收。

独立同模型复核读取候选方案及原始核查记录，确认修订文本没有把可行性、sudo策略或普通任务预留升级为已执行、已认证、严格隔离或零干扰。该复核不包含远端实施或外部同行评审。
