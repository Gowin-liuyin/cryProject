## 1. 方法

### 1.1 统计量

- 分位数：`p10 / p50 / p90 / p99`，`numpy.quantile(..., method='linear')`（numpy 默认口径）。
- **分位数差 = class0 分位数 − class1 分位数**，与既有证据的 Δ = mean0 − mean1 同向、同命名。
- 每类的经验分布用同一份 CSV 的逐次原始值，不做截尾、不去长尾、不重排。

### 1.2 bootstrap 95% CI

- **百分位法**：对两类**各自独立**做有放回重抽样（每次重抽 n = 10000），
  复算同一分位数并相减，取重抽样分布的 2.5% / 97.5% 分位作为区间端点。
- **次数 B = 10000**（≥10000），按 250 个重抽样一块分块生成索引以控制峰值内存。
- **固定种子**：`numpy.random.default_rng([20261016, <数据集序号>])`，
  序号就是 POWER.md 主表里的 `#`（1–41），与登记表顺序绑定，重跑逐位可复现。
- 均值差的 95% CI 沿用既有证据口径（正态近似，z = 1.96，方差除数 n−1），
  只用于「与分位差是否一致」的对照，不改写既有结论。
- 每个主类对都是 `n0 = n1 = 10000`。

### 1.3 「与均值差一致」的判定

对每个（主类对，分位数）记录两个**互相独立**的判定：

1. **方向**：分位差与均值差的关系分三类——
   `同向`（两者符号相同且都非零）、`反向`（符号相反且都非零）、`零`（分位差恰为 0，无方向）。
2. **判定**：`(分位差 95% CI 排除 0) == (均值差 95% CI 排除 0)`。
   只要出现「分位差 CI 排除 0 而均值差 CI 含 0」（或反向），就算**判定翻转**。

§4 把所有翻转、反向与零差条目逐条列出，不做任何隐藏或选择性汇报。

### 4.4 为什么会有这么多零差与翻转：有效计时粒度

对每个主类对把两类的取值合起来看：

- 相邻**不同取值**的间隔中位数：全批 41 个主类对合起来的中位数是 **9 ns**（各主类对的范围 9–10 ns）。
- 相邻不同取值的最小间隔：全批都是 **1 ns**。
- 取值本身是整数 ns（所以最小间隔是 1 ns），但在实际聚簇区间上，**不同取值之间的典型间隔是 9–10 ns**；
  也就是说，本平台这批数据的**有效计时量化尺度约 10 ns**——
  均值可以靠 n = 10000 平均出 1 ns 以下的差异，但**分位数只能落在约 10 ns 的格点上**。

这一条直接解释了两类现象：

1. **分位差恰为 0**（63 条）：两类的同一个分位点落在同一格点上。
2. **判定翻转 / 方向反向**：格点跳一格就是 ±10 ns，而这个跳格的行为
   （中心质量在相邻格点之间搬家）与均值（受长尾支配）可以给出不同甚至相反的读数。

## 5. 分位数差是否与均值差一致？

**结论：方向层面多数一致（88/164 同向），但有 13 条方向反向、24 条判定翻转，全部如实列在 §4。**

### 5.1 逐模块读法

- **M4 vulnerable（最需要注意的一条）**：均值差是 -4.102, -4.351, -3.515 ns（3/3 次 run 的 CI 不含 0，Holm 拒绝），
  但 p10/p90/p99 的分位差**恰好是 0.0**，只有 p50 是 −10.0 ns。
  原因是 M4 这一臂的取值**几乎只有 {20, 21, 30, 31, …} 几个格点**
  （`M4-vuln-s1` 未修臂：`20` 出现 6922/10000、`30` 出现 2659/10000；
  已修臂：`30` 出现 6513/10000、`20` 出现 2983/10000）。
  泄漏体现为**质量在 20 与 30 两个格点之间搬家**：搬家约 40% 的质量就会把均值推动约 4 ns，
  而分位点只在 20 → 30 之间整格跳变，所以分位数**分辨不出**这个 4 ns 的均值移动。
  → 这一条是**测量粒度导致的不一致，不是统计矛盾**，但它意味着：
  **不能用 M4 的分位数差去复核 M4 的均值结论**，两边都只能用各自的口径表述。
- **M2**：判定翻转 13/24、方向反向 6/24，都集中在 M2。最典型的是 `M2-fixed-s1`——
  p10/p50 的分位差为 **-10.0 / -19.0 ns**（CI 不含 0），而均值差是 **+21.657 ns**（CI 含 0）：
  中心与均值**反向**。这与 `platform-collection-20261016/README.md` §5 记录的
  **M2 臂间漂移**一致：重尾把均值拖走，而分布中心往相反方向移动。
  这**不改变** M2 家族 Holm 不拒绝的结论，也不构成泄漏声明。
- **M3 on/off**：15/24 条分位差恰为 0，其余 |分位差| ≤ 10 ns，与均值差（|Δ| ≤ 10.7 ns）同为「不可区分」；
  但仍有 1 条方向反向、0 条判定翻转；两者都落在 ±10 ns 的边缘格点上，
  且 CI 都含 0。M3 是**人工构造校准**。
- **M5**：0 条判定翻转、2 条方向反向（都在 p99，CI 都很宽、都含 0），
  中心与均值一致地「不可区分」。
- **M1 未修**：p10/p50/p90 与均值同为正向且 CI 都不含 0；p99 差值为正但 CI 含 0，
  长尾段不足以复现均值层结论。**M1 已修**：4 个分位数与均值同为「不可区分」。
  两者都**族外**（`tooling-strengthen-20261015/PROTOCOL.md`：没有 Holm）。
- **R03**：对照 A 的 36 条里有 1 条判定翻转（`R03-valid-malformed-m1unfixed-s2` 的 p50 = +1.0 ns，
  远小于本批数据的有效计时粒度中位数 9 ns，属离散化边界效应）；
  对照 B 的 36 条里判定翻转 0 条、方向反向 0 条，全部与均值同向且 CI 不含 0。
  分位数与均值在这两个族外对照上一致：A 不可区分、B 是接口层数量级差。

### 5.2 可以引用的一句话

> **分位数差与均值差在本批数据上多数同向，但两者并不等价：在有效计时粒度约 10 ns 的条件下，
> 分位数只能整格跳动，而均值能靠 n = 10000 分辨到 1 ns 以下。**
> 因此 M4 vulnerable 出现「均值差 3/3 显著、分位差 p10/p90/p99 恰为 0」的分歧，
> M2 出现「中位数与均值反向」的分歧；两者**都不推翻**已提交的 Holm 判定，
> 也**都不**构成新的泄漏结论。

## 7. 边界

- **bootstrap 假设类内样本可交换**。本批样本在 run 内按固定种子的平衡乱序产生，
  这是为了抵消时间漂移；但 `platform-collection-20261016/README.md` §5 记录的 **M2 臂间漂移**
  说明同一台机器上仍可能有慢漂移。若漂移存在，bootstrap 区间会偏窄（偏乐观）。
  本页因此**只把分位差 CI 当作描述性区间**，不把它升级为新的显著性判定。
- **有效计时分辨率约 10 ns**（§4.4）与 M2/M3/M4/M5 关心的 4–30 ns 效应同量级，
  分位数在这个尺度上只能整格跳动。任何「分位数不显著/显著」的读法都必须带上这条限制。
- 分位数差是**描述性统计**：它不改变任何已提交的 Holm 判定，也不构成恒时证明、
  物理泄漏界或总体检出率。
- **M3 / M4 是人工构造校准**（M3 为 LUT 机制校准，M4 为人工提前退出比较夹具），不是上游 CVE。
- **R03 两个对照与 dudect / RTLF 一律族外**：它们不进任何 Holm 家族，本页也不把
  dudect 的最大 t 转成伪 p。
- 不做密钥恢复，不运行 exploit demo，不给出真实总体误报率。
- 本页只读已有证据；没有新增采集，没有修改任何已有证据文件。

（本页 bootstrap 参数固定：B = 10000，基础种子 20261016，分块 250；同一份输入重跑得到逐字节相同的本文件。）
