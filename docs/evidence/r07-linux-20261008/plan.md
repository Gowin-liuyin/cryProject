# R07 同一环境防护前后计划

写于采集之前。源码为采集时的 Git 提交，构建前不得再改测量程序。本计划不回溯到旧的 Apple M5 数据上。

## 对象

- 防护前：vulnerable，已有来源的人工消息编码分支，编译定义 BASELINE_VULNERABLE。
- 防护后：hardened，同一优化控制下的掩码对照，编译定义 BASELINE_HARDENED。
- 对照：reference 与 deployable，使用相同种子、样本数和顺序。deployable 只是正常优化形态，不单独当成防护后。
- 上游固定实现原本无此分支。本轮不称新发现或新修复的上游漏洞，不做密钥恢复或利用。

## 环境与构建

授权 Ubuntu 24.04.4、x86_64、KVM、4 vCPU。正式计时使用 GCC、RelWithDebInfo、sanitizer 关闭、A113_ARCHIVED_CASE_ONLY=OFF，从而生成四套 measure。动态检查不与这套正式二进制混合。每次计时使用 taskset -c 2。不配置宿主频率，该限制写入记录。

功能检查使用同一构建的公开向量、等价和随机源失败测试，先于正式计时。

## 样本

预定种子，按此顺序，全部执行，不因中途结果增删：31337、90210、20261111、8675309、141421356。
不跑历史上未预定的 777。

变体顺序：reference、vulnerable、hardened、deployable。
每类 5000 次，五类共 25000 次正式解封装。程序自带 100 次预热。保留全部原始值和长尾。

## 分析

沿用现有 analyze 与 analyze_groups，不新写统计方法，不删除不显著或残差。单比较阈值仍为分析器原值。不显著不等于恒时证明。旧 ARM 分布不与本次 Linux 分布拼接。

## 停止

构建失败、功能检查失败或某次 measure 非 0 时保留已有输出和退出码。功能检查失败则不开始正式计时。
