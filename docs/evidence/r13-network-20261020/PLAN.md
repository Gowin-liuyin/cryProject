## 1. 目的与不可越界的东西

### 1.1 目的

在**真实两端**的 TCP 通信上，量化「本地解封装耗时差异」经网络传输后是否还能被客户端分辨，
以及检测预算如何变化。

### 1.2 不可越界（硬约束）

- **只测自有测试端点**：客户端与服务端都是本工程的 `network_client` / `network_server`，
  运行在同一台裸金属的 veth 两端。**不涉及第三方服务、不涉及公网、不做互联网攻击推断。**
- **不写密钥/秘密进网络**：请求是固定长度（1104 B）密文 + 公开请求号；应答是固定长度
  确认（32 B）。共享密钥、内部接受标志、服务端耗时不进网络。
- **不写攻击程序、不做密钥恢复**。
- **不把网络未检出写成「没有远程泄露」**：允许的结论上限是
  「在本预算下未检出」；必须同时给出失败边界（预算、超时、丢失、删失）。
- **不进入既有 Holm 家族**：本任务是族外描述性对照，不改变 M1–M5 任何既有判定。

## 2. 拓扑与三档

### 2.1 拓扑（匿名网络命名空间 + 自有 veth）

```
[主命名空间]  cry7a (10.88.11.1/30)  <--veth-->  cry7b (10.88.11.2/30)  [匿名 netns]
   ^ tc qdisc netem 挂在 cry7a 上（位于密码计算窗口之外）
```

- **用 `unshare --net` 建匿名进程网络命名空间**，**不在 `/run/netns` 建项目具名句柄**
  （`run_ryzen_network.sh` 的既有做法，理由见 `docs/research/seven-capabilities-20261011/EXPERIMENT_PLAN.md` W5 第 6 条）。
- 抖动用 `tc qdisc ... netem delay <d> <j>` 挂在 veth 主端，**不在算法里加 sleep 或随机延迟**。
- 拓扑必须在 CPU2/CPU6 之外组织：绑核用 `taskset -c 0,1,3`（与 R06 动态 diff 同一组），
  **不占用**主控锁频采集用的 CPU2/CPU6。

### 2.2 三档 + 两个基线

| 档 | 路径 | netem 延迟/抖动 | 作用 |
|---|---|---|---|
| `direct` | 本地直调（不走 socket） | 无 | **本地基线**：单次完整解封装耗时的可分辨下界 |
| `loopback` | 回环 TCP | 无 | **协议开销基线**：TCP + 固定长度帧的额外开销 |
| `low` | veth + netem | 100 µs / 20 µs | 低抖动档 |
| `mid` | veth + netem | 1 ms / 200 µs | 中抖动档 |
| `high` | veth + netem | 10 ms / 2 ms | 高抖动档 |

抖动档的数值沿用 2026-10-11 七期线已实测过的三档（`run-network/levels.txt`），
**先做预试点确认网络可承受范围，再冻结本表**；预试点结果单独记录，若与本表不符则
以修正文件说明后重新冻结，不静默改参数。

### 2.3 输入类别

客户端按 `request_index % 5` 轮转五类输入（`src/network_client.c:53`）：

| index % 5 | 类别 | 语义 |
|---|---|---|
| 0 | valid | 合法密文，接受路径 |
| 1 | bit-flipped | 位翻转，同长度 |
| 2 | random | 随机密文，同长度 |
| 3 | message-zero | 选定消息全零的合法密文（接受路径的另一类） |
| 4 | message-ones | 选定消息全一的合法密文（接受路径的第三类） |

这与平台的输入分类体系一致，**每档的请求数取 80 的整数倍**，保证五类各 16 次。

## 3. 测量口径

### 3.1 两个独立观测量（必须分开，不混用）

1. **客户端 RTT**（`CLOCK_MONOTONIC` 纳秒，从 `connect` 后每次 `send` 前到 `recv` 完整应答后）：
   这是**网络结论的唯一依据**。客户端观测与服务端内部状态完全隔离。
2. **服务端诊断计时**（仅用于解释，不给客户端分析器）：服务端在解封装窗口内的耗时。
   若同时记录会增加请求间扰动，**其代价单独测一次**（开/关诊断的对照），不并入主分析。

### 3.2 预算

- 每档每臂 **80 请求**（五类各 16 次），**两次独立运行**（换种子）→ 每档每臂 160 请求。
- 客户端 RTT 原始值**全部落盘**，不删尾、不截尾；超时/丢失**单列为删失**，禁止静默删除后只分析成功响应。
- 记录：实际 RTT 分布、丢失、重传可见性、超时、队列设置、CPU 亲和、频率状态。

### 3.3 臂

| 臂 | 服务端实现 | 意义 |
|---|---|---|
| `m1unfixed` | liboqs 0.10.0 未修（`bt` + `jae` 教科书形态） | **真实历史阳性对象**：机制存在 |
| `m1fixed` | liboqs 0.10.0 + 官方修复 982c762 | 修复后对照 |
| `m5ref` | mlkem-native b3ba7b3 参考 | 阴性对照 |

**M1 两版用 `network_server` 的解封装路径替换实现**（M1 的 `mlkem_decapsulate` 变体）；
M5 用仓库默认的 `mlkem_reference`。**M3/M4 不进本任务**：它们是人工构造校准，
网络场景下不构成可归因的差异来源，只增加噪声。

### 3.4 统计（族外）

- 主统计：客户端 RTT 的**逐类别**分布对比（message-zero vs message-ones 为接受路径内对比；
  valid vs bit-flipped 为异常输入对比），Welch 检验 + 正态近似 95% CI。
- **不做 Holm、不进任何既有家族**（本任务全族外）。
- 主口径是**分布可分辨性**：报告在每档抖动下，本地基线的可分辨差异是否还超过该档 RTT 噪声。
  允许的结论是「在本预算下未检出」。
