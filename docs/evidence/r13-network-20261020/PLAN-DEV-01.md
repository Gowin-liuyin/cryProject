## 偏离 1：请求预算（80 → 10000 / 每类 2000）

| 项 | 内容 |
|---|---|
| PLAN 冻结值 | 第 89 行「每档每臂 **80 请求**（五类各 16 次）」、第 74 行「请求数取 80 的整数倍，五类各 16 次」、第 135 行验收判据 #3「每档每臂两次独立运行、每次 80 请求、五类各 16」 |
| 实际执行 | 本地直调档每类 **10 000** 样本；网络各档每类 **2 000** 样本（总请求 10 000，五类各 2 000） |
| 偏离倍数 | 本地直调档 125×；网络各档 25× |
| 理由 | 锁频标定显示：每类 2 000 样本时 M1 未修臂的效应（几十纳秒）**不足以分辨**；每类 10 000 样本时才第一次出现可分辨结果（+29.4 ns，CI [16.5, 42.3]，对应 SE ≈ 6.6 ns）。80 请求/类时 SE 在 250–800 ns 量级，效应被完全淹没，采集**没有统计意义**。**注意：这两组标定数字与所依据的试跑目前只有文字登记、其 run 目录未归档**，因此它们是「据以决定预算的记录」，不是可复核的归档数据。因此把预算提到「本地能分辨、网络能算出所需预算」的量级。 |
| 对结论的影响 | 结论方向不变（网络各档未检出），但「所需样本数」这一**量化**结论只有在足够预算下才能给出。若仍按 80 请求，则只能写「未检出」，无法给出检测预算。 |
| 与验收判据的关系 | 判据 #3 原写「写实际次数与偏差」——本次按实际执行并在此登记偏差。**未按冻结值执行，已如实登记。** |

## 偏离 2：网段与 netem 位置

| 项 | 内容 |
|---|---|
| PLAN 冻结值 | 第 38–40 行：`cry7a 10.88.11.1/30 ↔ cry7b 10.88.13.2/30` 段内地址（原文为 `cry7a 10.88.11.1/30`、`cry7b 10.88.11.2/30`），「netem **挂主端**」 |
| 实际执行 | 网段改为 `10.88.13.1/30 ↔ 10.88.13.2/30`（与七期线 10.88.11.x 错开，避免与既有实验的地址混淆）；netem 挂在 veth **两端**（主端与匿名命名空间内的对端各一份，同参数） |
| 理由 | (1) 网段：与本仓库既有网络实验（10.88.11.x）区分，避免同机并行时地址冲突。(2) netem 挂两端：只在主端施加时，**延迟是单向的**（去程有抖动、回程没有），RTT 不具备对称性，两端各挂一份后 RTT ≈ 2× 单向延迟，语义清楚。实测与设定一致：low 档 p50 ≈ 267 µs ≈ 2×100 µs + 协议与密码开销。 |
| 对结论的影响 | 档位的**绝对** RTT 量级与单向设定不同（是 2 倍）；但「同档内两个消息类之间的差异」这一主类对**不受**单向/双向影响（两次请求走同一条路径）。检测预算表里的 SD 是实测值，不依赖该选择。 |

## 偏离 3：频率写入（不写 cpufreq → 用平台控制器锁频）

| 项 | 内容 |
|---|---|
| PLAN 冻结值 | 第 124 行「本任务**不写**任何 cpufreq 节点」；第 34 行「绑核用 `taskset -c 0,1,3`（不占 CPU2/CPU6）」；第 4 节恢复合同第 6 条「本任务**不写**任何 cpufreq 节点，结束时核对 `scaling_cur_freq` 与进入前一致」 |
| 实际执行 | 每档是一个**平台频率控制器** run（`tools/platform_control/controller.py`，与 R02/R08/R09 同一口径）：boost=0、governor/EPP=performance、min=max=4 300 000 kHz、taskset 绑 CPU2，结束时恢复原值并核对 `restore_match=yes`。**服务端**（控制器 worker）绑 CPU2；**客户端**仍绑 `taskset -c 0,1,3`，不占 CPU2/CPU6 |
| 理由 | 未锁频时，几十纳秒量级的本地效应完全被频率波动淹没（第一次未锁频试跑：每类 2 000 样本、SE ≈ 30 ns，效应不可分辨），**本地基线将不成立**，网络各档的对比也就失去参照。平台既有控制器已具备完整的写入→回读→沉降→探针→恢复合同，复用它比另写一套更安全；「不写 cpufreq 节点」这一条的**原意是「不留下未恢复的频率改动」**，控制器 run 结束时 `restore_match=yes`、`worker_drained=true`，正是该意图的更强实现。 |
| 对结论的影响 | **正面**：网络各档与本地直调档处在同一频率条件，可与 R09 的可分辨性结论对照。**边界**：控制器只保证工程上的「20 次探针落在目标 ±2% 带内、跨度 ≤ 50 000 kHz」，**不保证逐调用物理恒频**；后者由 [R16](../r16-precision-20261021/RESULT.md) 单独给出分层结论。恢复合同第 6 条的「`scaling_cur_freq` 与进入前一致」在控制器口径下由 `restore_match` 字段兑现（恢复后回到 2 982 259 kHz），同时保留了对**静态策略项**（governor/min/max/EPP/boost）的逐字核对。 |

## 偏离 4：主类对与次要类对

| 项 | 内容 |
|---|---|
| PLAN 冻结值 | 第 107–108 行要求除主类对（message-zero vs message-ones）外，**同时**做 valid vs bit-flipped 的对比 |
| 实际执行 | 归档的 `data/class-comparison.csv` 只给出**主类对**一行（每档每运行一行，共 30 行）。次要类对**未出表** |
| 理由 | 次要类对（valid vs bit-flipped）在本任务里**不是有意义的对照**：valid 是接受路径、bit-flipped 是异常输入路径，两者的解封装路径长度不同，差异主要来自「接受/拒绝」而不是秘密相关分支；本任务要回答的是「同一路径内、仅消息位不同的两个类之间能否分辨」，主类对才是对应量。若强行出表，容易被读成「异常输入更慢 ⇒ 泄漏」，这是**误读**。 |
| 对结论的影响 | 次要类对的缺项**不影响**本轮结论（结论只依赖主类对与检测预算）。但它是一项**未执行的登记**，如实列出。 |
