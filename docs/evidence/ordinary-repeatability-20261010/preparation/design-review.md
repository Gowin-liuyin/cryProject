# 普通参考完整调用运行间描述：独立实验设计复核

2026-10-10。本文件是提交 `22a7b9065984cb1f2c6361c4553b23589f88d1fb` 后的本地只读研究意见，不是已经冻结的最终合同或执行结果。本代理未SSH、未采集、未改源码、未commit，也未读取`.agents/`。已读取当前README、官方要求复核及R02/R04验收状态、G2和RAW实际结果、现有参考构建与公开向量资格代码；知识图谱工具当前未提供，按已知文件路径阅读。

## 核心建议

可以执行两次连接执行批次，每批三个顺序的新进程，固定同一普通reference ELF、同一公开测试密文、同一CPU2亲和性和计时合同。总计六个进程层面的观察单位。这个设计补足“原G2只有一次完成进程”的具体事实缺口，能够报告六次完整调用时长分布的实际接近程度和实际跨度；它本身不能认证独立同分布、长期稳定性或全部R02。

SSH断开再登录改变的是连接与管理生命周期，不会自动重置CPU、内核、系统负载、缓存、温度或频率状态。建议把E1/E2明确命名为“连接执行批次”，图表使用`E1-P1`至`E2-P3`，避免把“不同SSH会话”写成独立实验环境。新进程确实是新的执行单位，但仍共享主机与近邻时间背景；不同PID也不等于独立随机单位。

## 固定研究问题和最小主张

问题一：同一固定普通参考产物在该主机、公开单一有效测试输入、CPU2自身亲和性条件下，六个新进程是否均能完成固定次数的完整解封装、保持预期结果并保存可复算的原值？

问题二：六个进程分别观察到的主阶段均值、中位数、P90、P99、最大值、MAD及原序四段有什么差异？其中哪些变化发生在同批进程之间，哪些发生在两批之间？只描述现有六个值和实际时间间隔，不估计总体方差成分，不将近邻进程差异解释成会话因果效应。

主要证据是每进程完整原序CSV、过程元数据、严格C离线检查和整数时间账。程序成功只等于观测协议完成；“差异是否足够小”另需要预定应用差异量级和适用误差模型。当前不以未经依据的1%、100ns或空窗20ns阈值认证稳定/等价，也不以接近结果自动签收R02。

## 输入与功能资格

1. 仅链接原`src/kernel.c`、`src/mlkem.c`、`src/random.c`、固定`baseline_config.h`及原vendor；若需要公开fixture，复用`src/inputs.c`的公开测试种子派生。不构建、运行或改变其他变体，不打补丁，不按秘密位/密文类别分组。
2. 推荐固定一个明示的公开确定性测试场景：`test_seed=42`、`sample_index=0`、正常`valid`封装。通过既有公开种子函数得到密钥对，用对应公开封装随机种子生成密文和预期共享结果；所有fixture准备都在计时和阶段开始前。封装得到的预期结果只用于逐调用完整性比较，不称独立标准正确性证明。可输出公开种子、固定ciphertext摘要及fixture合同身份，不输出私钥、共享结果或消费累积值。
3. 另一可行路线是直接使用一个来源固定的公开有效NIST decapsulation向量及其外部预期答案，但需要额外固定该case身份和可信提取过程。若为此新建通用向量解析器，收益有限；优先复用既有测试派生路径，并用独立公开KAT资格分开证明功能。两种路线须在首个采集前选定，不在成功数据之后换输入。
4. 普通、ASan/UBSan分树编译，分别运行独立公开NIST 80用例、已有公共参数边界和参考OS随机往返检查，以及新collector/analyzer纯软件夹具。实际登记CTest的条目、用例范围、日志、退出码、编译参数和ELF摘要，不把一项包含80用例的CTest写成80项CTest。只用普通ELF采集；资格检查中的密码调用另计，不能混入300000次计时调用。
5. 每次完整`mlkem_decapsulate`返回后立即结束计时，再在窗外比对32字节输出与固定预期结果。比较每次执行，防止未消费的结果被优化掉；只记录通用调用返回状态和公开测试完整性是否通过，不输出内部重加密接受标志。这些比较保证该已知测试任务的结果一致，不能取代独立KAT、穷尽标准或恒时证明。
6. ELF/静态库及反汇编核对确实调用完整公共封装和原参考内核，LTO关闭，无缺陷分支或自造延迟。动态资格不用于正式性能数字。新入口设置并回读进程自身转储禁用，外部core限制为零；不把进入C入口前的加载器阶段列入此保证。

## 次数和预算建议

推荐事前固定每进程25000次预热和25000次主调用，共50000次；两批各三个进程，共300000次计时调用、600000次采样读钟。预热也完整保留，不混入主阶段统计。固定次数避免按“直到稳定”停采或根据结果追加；阶段时长以实际原值为准，不声称严格1秒。

旧G2普通调用约40µs，只支持规划量级：每阶段约1秒、每进程约2秒，六进程约12秒采样，尚未包含准备、结果比较、间隙、输出及管理。这不是运行上限，更不是新产物预计值保证。25000主值使经验P99由实际次序统计量明确给出、尾部仍有约250个观测位置，但不能由此声称P99估计精度或独立样本量25000。

这是一个有意有限的描述研究，不存在由现有证据可推导的“统计上最少六次”。选择两批×三进程的理由是：每批能看到新进程间范围，第二批能另观察一次连接执行后的范围，总成本低且不靠一个进程代表全部。它不是功效计算或正式等价检验。更少的次数会减小这些可观察对照，但更多逐调用值不会增加进程/批次数；若未来目标是长期重现性，另设跨日/冷热启动等预定采样合同。

每collector建议GNUtimeout 15秒，TERM后至多2秒KILL，管理者至多20秒等待和核实回收；仅管理自己登记的PID/startticks/进程组。每批总工作软预算300秒、另30秒封存导出，包含资格和管理；若实际构建预算需要增加，应在首个运行前修改冻结合同。每进程输出文件硬限64MiB，批次阶段边界256MiB预算及足够可用磁盘，完整两批原归档另有总空间预算。256MiB边界预算不是全局硬quota。固定调用上限和timeout同时生效，任何失败不补进程、不延长成功数据、不降低次数。

同ELF空窗不是本研究必要项。现有RAW空窗属于另一新程序；若本轮不测同ELF空窗，直接说明完整调用时长包含本入口计时机制且不做开销扣除。增加空窗不能自动获得绝对误差界，反而扩充测试及计数协议；不建议在这个最小描述研究中增加。

## 两批的时间间隔与执行次序

顺序固定为：E1预检/资格→P1、P2、P3→C复算与封存→回收核验→断开控制连接→重新密码认证→E2重新只读预检→P1、P2、P3→C复算/封存→回收核验和关闭SSH。复用同一个普通ELF的固定字节；E2不是再次编译新身份。E2原件建新目录，不覆盖E1。

不为制造“独立性”安排没有依据的固定10分钟等待，也不在代码里插入sleep/空转。执行协议本身形成的间隔原样记录。至少保存每次实际连接尝试、认证成功、批次/进程开始结束的UTC记录及来源，控制连接身份，远端boot_id和每进程第一/最后RAW读数。管理跨度与采样跨度分别报告。若同机同boot、时钟合同一致，可用两批相邻有效RAW边界给出实际采样间隙；同时报告时间源，不能把管理UTC显示位数当成准确度。重连若紧邻发生，应直说“近邻两批”，不包装成跨时段长期复现。

如E2未发生，只有E1三个进程的真实结果，E2保持未执行；不能以已退出的旧控制socket或计划文件当运行证据。连接失效但helper尚未启动的失败记录不增加采样次数；重新认证可继续同一个尚未执行的固定case。case已启动后无论失败、丢失输出还是管理观察超时，不可因此重新采集；先检查同一PID/实际句柄是否仍在运行，unknown不当terminal。

## 时钟、原值和几何账

采样继续使用RAW及原G2两读顺序：before读→完整`mlkem_decapsulate`→after读，纳秒转换、完整性比较、记录写入在after以后；准备、分配、fixture生成、日志和I/O均在窗口外。可用编译器栅栏维持采样位置，须以普通ELF核对顺序。全记录先分配并触页，缓冲容量固定，在循环内不输出。生成前设置自身CPU2亲和性并读回；阶段前后记录当前CPU及亲和性。

每个记录保存：全局序号、warmup/main及阶段内序号、operation_performed、before/after尝试和有效性、原timespec秒/纳秒分量、转换后uint64 ns、立即保存errno、通用调用返回状态、测试结果完整性状态和elapsed_ns。错误/未尝试/未知用独立标志与null表示；零纳秒保持有效零，不拿零补失败。禁止只保存elapsed而丢绝对相邻关系。

对每一阶段固定用第一before至最后after定义已保存调用跨度：

`phase_span_ns = Σ(after_j − before_j) + Σ(before_j − after_(j−1))`。

第二和只含阶段内部相邻间隙，数量为N−1。预热至主阶段的`first_main_before−last_warmup_after`单列，不并入任何内部间隙；两阶段总跨度等于预热跨度+阶段边界+主跨度。这样不必额外加阶段锚点读钟，600000次采样读钟计数清楚；管理开始/结束、metadata中的读钟另计且明示。若实现选择额外阶段锚点，则须保存它们并在几何账增加头尾项，不能隐式漏掉。

C分析器先严格核对原头、字段数、顺序、phase固定数量、原timespec范围、转换/减法/求和溢出、时钟单调、逐调用elapsed与记录一致、EOF及完整摘要。分布保留全部普通长尾；每进程分别输出warmup/main和主原序四等数量段，后者每段6250次，是同一进程的原序描述，不是四次新运行。分位口径建议沿用RAW的固定索引`floor(P*(N−1)/100+1/2)`，偶数P50上中位数，MAD同法，不误称标准nearest-rank。

主表单位ns，显示count、sum、min、P50、P90、P99、max、MAD；均值权威形式sum/count，显示小数只作排版。增加每阶段内部gap分布/和、phase_span、边界和总跨度，检查上述全部整数恒等式。跨进程表按E1-P1…E2-P3排列，另列六个P50及六个精确均值的min/max/range，不对300000条或主150000条混池计算“六次重复”的总体区间。

如果需要比较批次的摘要，可列每批三个进程摘要的完整三个值、范围和描述中位数；不以每批75000条调用替代批次样本量3，不用未经证明的t区间或显著性星号。

## 错误停机、元数据和资源边界

一旦before读钟失败，不再调用密码函数；一旦after失败、时钟逆序、通用调用非零、结果不符、容量或整数检查失败，停止新调用，保留所有已发生原值、已实际完成调用数和失败记录。不补采、不丢普通长尾。输出/关闭失败同样非零；summary不覆盖真实退出码。缓冲只在结束输出时，SIGKILL造成的空输出保持unknown，不能从预定容量恢复已完成数量。

每进程收集source/未提交摘要、compiler/options、ELF/静态库SHA、host/kernel/架构/UID、boot_id、PID/startticks、原及实际亲和性、CPU2拓扑/SMT同胞、clocksource和RAW声明分辨率、可见调频请求/boost前后值和当前资源上下文。读取频率文件的相同值只是快照描述；单纯task affinity不等于CPU2或SMT同胞独占，不证明实际瞬时频率锁定。不要继承旧G2管理窗口的4300MHz或几何资格为本轮资格。无root、MSR、cgroup/IRQ或调频写入，简化生命周期和恢复面。
