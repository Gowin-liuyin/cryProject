# 有限批次测量贡献审查

Google Benchmark官方指南已经介绍重复迭代、预热、重复运行统计、随机交错、手动计时及
防止计算被优化删除的设施。这些属于成熟基准测量做法，本项目不声称批次、乱序或
bootstrap本身是首次提出。[官方用户指南](https://google.github.io/benchmark/user_guide.html)

本轮实现的增量是把这些测量原则约束到C11/ML-KEM-768普通负载的可审计比较：同一参考
内核及有序公开输入摘要、保留实际批次总时间和调用数、有限两候选、共享预算、全部失败
材料、运行级配对分析及成本/中心/依赖资格。没有引入C++基准框架或改变密码算法。

目前只有功能、接口、数学及失败路径的软件证据，没有目标平台开发或20对确认。
因此本轮支持“比较工具和复算入口已经实现”，不支持“复现离散度已改善”“检测灵敏度
提高”“低开销防护成立”或“密码更安全”。仅超过自己的逐次入口也不足以证明新颖性。

批次平均损失单次分布信息，混合窗口不能还原类别耗时或单次P99。
K会改变缓存、间隔及消费节奏，中心差异筛查不等于证明估计对象相同。
配对bootstrap的99%区间仍依赖运行块假设；20对及局部诊断不保证精确覆盖。
完整成本保守上界和负结果不能为了获得好看比值而删除。

R12仍为证据不足。下一项最有价值的工作是获得经核实原生x86_64 Linux机器，完成同源码
前置和有账的两个K开发比较；若基线MAD退化、中心偏移、依赖或成本不合格，则停止路线。
即使以后确认改善测量质量，仍须证明它转化为题面允许的检测/防护效率增量，不能换目标
宣布竞赛创新达标。真正第三方复现也须由另一位执行者留下独立日志。
