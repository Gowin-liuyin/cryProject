# 下一轮普通性能测量改进合同（待执行）

本合同只检验参考版普通负载的**测量质量与成本**，不提出上游安全修复声明。
比较前须有经确认的原生x86_64 Linux环境，固定源码、编译器、选项、CPU控制与产物摘要。
本轮ARM64描述数据仅用于制定计划，不进入下一轮确认集合；本文不是已完成的确认结果。

| 合同项 | 预先规定的比较 |
|---|---|
| 要改善的指标 | 相同普通负载和调用预算下，重复运行均值的相对离散度 `S=MAD(run_means)/median(run_means)` 至少降低20%；总运行成本不增加超过5%。这衡量复现稳定性，不等于更准确地知道“真实耗时” |
| 具名强基线 | `reference/benchmark` 的 `reference_ordinary_v1`：未修改 mlkem-native `b3ba7b32773e657dd37f6f87bce82528459ad8a4` 便携C参考内核，逐次完整解封装、固定1:1:1、相同输入顺序。不得以保留optnone的hardened为性能强基线 |
| 候选与相同权限 | 候选仅为“每窗口有限批次完整解封装”的测量方式；所有方法有相同公开种子、三类输入知识、测试密钥、运行权限和编译条件。不能改变密码计算或获得额外内部标志。批次产生的缓存/顺序变化须视为混杂，不预先假定有益 |
| 全成本预算 | 每方法上限200000次完整解封装：开发/探索40000，独立确认120000，预热/自检/失败重试最多40000；同时上限30分钟，先到即止。计入输入生成、分配、读钟、日志、开发编译与确认用时；共同准备成本均摊并另列，不只报正式窗口 |
| 开发与确认边界 | 开发可读本轮全部资料，仅在开发预算内选一个固定批次数。确认前冻结候选、20个新种子、输入表、执行顺序及分析程序摘要，排除本轮及所有历史种子。确认20对运行块，每方法每块6000次、三类各2000；每对共享输入，方法先后随机且平衡，保留所有原始窗口和失败尝试 |
| 正式比较与错误控制 | 唯一主比较为 `S_candidate/S_baseline`。以运行块为重采样单位，成对bootstrap10000次、固定公开分析种子20261029，报告99%区间；上界小于0.8且本次成本账增加不超过5%才允许稳定性改进声明，成本约束不外推为总体性能非劣。类别分位数为描述性辅助，不另给告警；不池化逐次记录制造样本量。运行块独立性/环境稳定性不足时，区间只作探索，不能确认 |
| 否定或阻止声明 | 区间上界≥0.8、成本增加>5%、密码功能不一致、原始记录不完整、预算超限、批次改变了应比较的负载含义，任一发生都不支持改进。基线MAD为0或量化导致主指标退化时报告不可识别，不换指标挑结果 |
| 失败后的有用产出 | 保留目标平台参考功能、读钟/空窗记录、普通负载原始数据、实现和产物身份、完整预算账及负结果。能交付可信基线即有价值，不以新安全改进或攻击能力包装测量工程 |

批次方法目前只是待检验候选，尚未实现；在同输入、同预算比较前，不能依据更平滑的结果
认定估计更准确或性能提升。若目标平台本身量化很小、现有重复记录已稳定，开发预算内可
直接否定该路线并保留基线，不能为完成创新指标堆新实现。

输入选择/测量预算路线另作候选的必要性检查：当前缺乏证据证明候选在规定普通任务上有
稳定不同效果；固定输入是否不能覆盖最佳效果、有限探索能否识别候选、收益能否覆盖探索
成本也均未证明。历史人工机制类与普通类的差异不能回答这些问题。因此该路线**尚无依据**，
本轮不构建选择器，不启动自动漏洞复现或不断尝试编译条件；先用普通测量合同决定去留。

本合同对应R02测量质量的候选改善，不自动满足R12：若没有转化为题面允许的检测/防护
效率增量，应保留测量工程成果并继续将R12标为证据不足，不改变创新评价目标来宣布成功。
