---- M1-6 第 2 条：binaries.sha256 另算，不与 executable_digest 比对 ----
binaries.sha256 由 shasum -a 256 生成，算法为 SHA-256，与 .meta 的 SHA3-256 是不同算法，
两者的值不可能相等；本目录只用它满足 0.4 第 3 条的清单要求，不做任何跨算法比对。

---- 0.4 第 6 条：证据提交前的 .gitattributes 机械步骤 ----
第一次执行（.gitattributes 尚未加本目录的任何条目）：
$ git add docs/evidence/deployable
$ git diff --cached --check
$ echo "exit=$?"
docs/evidence/deployable/deployable.meta:32: trailing whitespace.
+link_flags=  
docs/evidence/deployable/hardened.meta:32: trailing whitespace.
+link_flags=  
docs/evidence/deployable/reference.meta:32: trailing whitespace.
+link_flags=  
docs/evidence/deployable/vulnerable.meta:32: trailing whitespace.
+link_flags=  
exit=2

（上面四行成对的报警来自四份 .meta 的第 32 行 link_flags= 后面两个空格，
 与 docs/evidence/mitigation 的 *.meta 同因；*.log 一条都没报。）

因此按「按需添加、不发明新模式」补条目。实际加了两条：
  /docs/evidence/deployable/*.meta whitespace=-blank-at-eol
  /docs/evidence/deployable/record-checks.txt whitespace=-blank-at-eol

两条的理由分开记：
1. *.meta 条目与既有 docs/evidence/{cmake,completion,linux-gcc,mitigation,review,statistics}/*.meta
   的条目完全同型，覆盖机器生成的 link_flags 行尾空格。
2. record-checks.txt 条目是设计预期清单之外的一条，必须说明：0.4 要求把
   git diff --cached --check 的输出（含空结果）**逐字**写入本文件，而上面那四行输出本身
   就带行尾空格，于是本文件在第二次检查时自己被报警。保留逐字输出优先，
   因此为本文件单独加一条路径限定的条目。**不**用 *.txt 通配，
   以免顺带把本目录的反汇编 .txt 也从空白检查里豁免掉。
设计预期的 *.log 条目**未添加**：实测不需要。
以上以 git diff --cached --check 的实测输出为准，不是按预期填写。

补两条条目后重跑：
$ git add .gitattributes docs/evidence/deployable
$ git diff --cached --check
exit=0
