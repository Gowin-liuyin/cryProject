# 设计报告补充：固定库三类时序机制的产物审计

编号 CACR2026EA16XZ。本页是 2026-10-11 对固定便携 ML-KEM-768 解封装的补充，不替换已封存报告页，也不改已封存证据。

题目要求在真实解封装上检查有来源的时序差异，并把确实存在的秘密依赖时序改成常数时间选择，同时保持密码语义和隐式拒绝。
本轮对照文献里与题目直接对应的三类机制：KyberSlash 的变延迟除法、clangover 的消息编码秘密分支、FO 重加密比较或拒绝选择的秘密分支。
缓存、调频、端口争用、功耗、电磁、故障注入和 key mismatch 不在这轮。

正式检查在 `nss-m` 裸金属、GCC 13.3.0、RelWithDebInfo、`-O2 -g -DNDEBUG -std=c11` 上完成。
参考内核 `kernel.c.o` 摘要为 `3ce202eebcc590f02b401dadd09f81fa79eb6d74da820f5ef701a4543d649224`。
原文在 [审计记录](../../../docs/evidence/mechanism-audit-20261011/README.md)。

KyberSlash 若存在，时序观察者看到的是消息比特。该产物的消息编码和压缩符号中没有整数除法，状态为不存在。
clangover 若存在，观察者看到的也是消息比特。`poly_frommsg` 只剩两条循环边界跳转，秘密条件分支数为 0，状态为不存在。
FO 比较或拒绝选择若存在，观察者看到的是比较或拒绝标志。解封装里的全长比较和 32 字节条件搬运是循环边界，秘密条件分支数为 0，状态为不存在。
因此这三项没有防护前后计时，也没有由计时得出的统计结论。原始样本这一项为空，因为没有可配对的修复前机制。

自有审计入口会把上述论文形态标为存在。当前固定库没有这些形态，所以没有打补丁。
历史人工消息分支仍按原案例保留，不记成新的上游漏洞。R02 与 R04 保持部分签收。
本补充不声明整库恒时、全国一等奖或 FIPS 模块认证。
