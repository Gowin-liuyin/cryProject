\section{作品功能与性能说明}

\subsection{问题背景与赛题定位}

赛题把本作品定位为工程实践，题面给出的部署场景是服务器与物联网网关等真实环境。在这些场景里，ML-KEM 解封装进入每一次握手的请求热路径：TLS 密钥交换、安全固件更新等流程都会反复执行同一份密钥的解封装。工程部署意味着攻击者不需要物理接触设备，只要能观测或间接测量处理耗时，就可能把与密钥相关的信息从时间通道带出。因此，解封装的常数时间性质按部署层面的工程问题处理：必须对着实际编译产物、实际运行环境逐层检查，才能支撑“可以上线”的结论。

ML-KEM（模格密钥封装机制，Module-Lattice Key Encapsulation Mechanism）由 CRYSTALS-Kyber 标准化而来（FIPS 203\cite{fips203,kyber2018}）。在实际工程部署中，其解封装过程的安全难点不仅在于格密码数学问题本身，更在于软件实现能否真正做到”常数时间（Constant-Time）”——即使 C 语言源码避免了显式分支，编译器优化仍可能在最终机器码中引入依赖秘密数据的时间差异。Fujisaki-Okamoto 变换，简称 FO 变换，是将公钥加密转换为密钥封装机制的标准方法。解封装在 FO 变换下依次执行解密、重加密、比较与隐式拒绝，其中重加密、密文比较与隐式拒绝均由 FO 变换规定，四步都接触秘密。任何一步出现依赖秘密的分支、访存或可变时延指令，处理耗时就会随秘密值变化，秘密信息便进入攻击者可以观测的时间通道。

\textbf{而ML-KEM解封装恰是这一威胁的重点目标。}

这些威胁并非理论假设，而有真实攻击案例支撑，按泄漏发生的层次可分为三类：

\textbf{算法设计层}，FO 变换中的比较与拒绝步骤可泄漏足以恢复密钥的信息。Guo 等对采用 FO 变换的密钥封装机制（KEM）给出密钥恢复的计时攻击\cite{guo2020}。

\textbf{实现机制层}，特定指令的可变时延可转化为可测量的纳秒级差异。KyberSlash 将 Kyber 中的秘密除法转化为可复现的计时差\cite{kyberslash}。

\textbf{编译产物层}，编译器优化可能在机器码中重新引入秘密相关分支。clangover 揭示：即使源码采用了无分支掩码，编译器在特定优化级别下仍可能将其还原成依赖秘密的条件跳转\cite{clangover}。

这三类案例共同说明：源码层的防护并非终点，最终产物的验证才是常数时间判定的关键依据。

M1 与 M2 是真实历史漏洞版本（M1 消息编码分支泄漏、M2 秘密除法泄漏）检验真实漏洞检出能力与官方补丁效果；构造 2 个可控缺陷靶标（M3 秘密查表靶标、M4 提前返回比较测试函数）检验分析工具对特定泄漏机理的识别灵敏度；并以 1 个常数时间标准参考实现（M5）作为阴性对照，检验测试平台在合规代码上是否会产生误报。

FO 变换把解密得到的消息重新加密，再与输入密文比较，比较结果决定输出真密钥还是假密钥。这条选择必须由常数时间比较与掩码完成，不能出现依赖秘密的分支。隐式拒绝的设计目的，是让失败路径与成功路径在外部不可区分。一旦比较或拒绝的路径依赖秘密，这个目的就落空：攻击者不需要私钥，只凭每次解封装的耗时，就能判断解封装走到了哪一步。

以 liboqs 0.10.0 的消息编码分支案例（M1）为例：未修复版在 57 µs 的完整解封装均值上多出 32.311 ns，95\% 置信区间 [20.282, 44.339]，只占均值的 0.06\%。% A-01 % B-01
这里比较的是全 0 消息与全 1 消息生成的两类合法等长密文，后文简称”主类对”。单次调用看不出这个差别——本机计时最小步进为 10 ns，32 ns 只相当于 3 个步进，一次调用的随机起伏就把它盖住了。把每类 10,000 次调用、三次独立运行的样本合起来，差异才从噪声中分辨出来。% A-30
因此，报告”未检出泄漏”时，还需要交代样本量和噪声水平，并给出最小可检测效应（Minimum Detectable Effect, MDE），可理解为当前实验条件下检测方法能分辨的最小时间差异。在指定检验水平和检出概率（功效）下，这套测量方案预计能分辨的最小时间差。

机器码中的分支形态由源码与编译选项共同决定。以 M1 为例，liboqs 0.10.0 的开发者用算术掩码代替条件分支，避免执行路径随秘密消息位变化。然而，在 x86\_64 上使用 clang 18 的 \texttt{-Os}（以缩小代码体积为目标的优化）编译时，这段掩码代码被改写成了依赖消息位的条件跳转。该问题已登记为 CVE-2024-36405\cite{ghsa-f2v9}。相同源码在 ARM 64 位架构（aarch64）上生成的是位域提取和条件选择指令，没有出现这一秘密分支。% A-26 % A-27
因此，常数时间评估必须检查最终生成的机器码，并针对该编译产物进行测量。

换编译器、优化级别或目标架构都会改变产物，因此每次判定都绑定实际二进制与编译条件。

单工具下结论的可靠性需要交叉核对。dudect 与 RTLF 只回答两类耗时是否可区分\cite{dudect,rtlf}，Memcheck 与 Microwalk 只回答哪里依赖秘密\cite{ctgrind,microwalk}，Binsec 只回答给定边界内是否常数时间\cite{binsec}，三类结论回答的问题不同，需要各自使用、相互补充。第二个被测对象 M2（pq-crystals Kyber768 历史快照里的秘密除法）是最直接的例子：定位工具找到了三处操作数含秘密的整数除法，但完整解封装的合并耗时差为 $+4.58$ ns，95\% 置信区间为 [$-$3.08, 12.25] ns，跨过 0，表示数据尚不能将均值差与零区分。单独测量除法所在函数，合并差为 $+0.044$ ns，区间 [$-$0.430, 0.517] ns 也跨过 0。也就是说，代码里存在秘密相关指令，在当前机器和样本量下却未必能测出相应时间差。% A-03 % A-04
只用一个工具，M2 可能被读成存在泄漏，也可能被读成没有问题。同一份 M2，RTLF 在未修复版和已修复版均报告两类分布差异；dudect 的最大 $t$ 值落在已修复版，而采集前规定的均值检验在两个版本上均未检出显著差异。不同工具关注均值、分布形态或内部秘密依赖，结论需要结合各自检查的问题来解释。

还有一重困难在读者一侧。未检出常被当成常数时间，但阴性阴性结果仅在给定条件下成立。不写检测预算，读者就不知道这个阴性排除了多大的效应。RTLF 在 42 个数据集上给出 30 个未检出、12 个检出\cite{rtlf}，% A-16
同一批数据换一种统计口径就可能换一种读法；判定必须写明口径，只报检出状态不足以支持引用。

M2 的检测预算为 24.7--67.1 ns，大于除法可能产生的效应。在这个预算下，未检出表示现有样本未提供足够的差异证据，不能说明除法本身没有时延。% A-15

这四类困难彼此牵连：效应相对总耗时越小，测量就越依赖严格控制与重复采样；源码层的写法只有经过实际编译产物核验，才能支撑产物层判断；不同工具给出的定位、统计与有界证明各自回答不同问题；检测预算若不公开，未检出结果便无法说明排除了多大的差异。因此，评估必须贯通检测、定位、防护与复测四个环节，并将每项结论绑定到具体产物与检测预算。

赛题要求覆盖标准接入、高精度计时、差异统计、泄漏定位、常数时间防护、同环境复测、性能开销与跨环境验证。平台将这些要求组织为”检测—定位—防护—复测”四环节，各环节对应的章节与测试数据见附录 A 表 A1。判定目标为两类耗时是否可区分，每次判定绑定编译产物，阴性结果同时报告该预算下的最小可检测效应。

\subsection{作品功能与系统组成}

平台围绕五个被测对象，打通“检测—定位—防护—复测”四个环节。统一计时、CPU 锁频、统计分析与定位结果登记四个公共模块，使每次运行都能追溯到具体对象、编译产物、测量环境和判定依据。

平台对外提供六项功能。首先是受控输入生成：按公开种子构造两类合法等长密文，使解密后的消息分别为全 0 和全 1，这两组主要比较对象称为“主类对”；篡改、格式破损和截断等扩展输入另行测试。其次是受控测量：固定 CPU 频率工作点，在预热后随机交错两类密文，逐次测量完整解封装并保存全部原始值。第三是统计检测：采集前写定输入类别、样本量和共同校正的检验集合（Holm 家族），再用 Welch 检验、Holm 逐步校正（一种多重比较的统计校正方法，用于控制多组检验同时进行时的整体假阳性率）和逆方差合并分析差异，同时报告 MDE。

另外三项是函数级定位、防护与审计、可复现。函数级定位用反汇编、秘密标记、可变时延检查、轨迹互信息与有界验证把阳性落到函数与指令。防护与审计覆盖七类手段，并在产物层核对目标机制是否真的消失。可复现把计划、产物摘要、原始表与重算脚本打包成一键入口；复现机制、验证方式与结果见第 4.13 节。

\textbf{这些功能围绕五类对象展开。}

五个被测对象分三类。M1 与 M2 是真实历史案例：前者是 liboqs 0.10.0 在 x86\_64 上被编译器引入的消息编码分支，后者是 pq-crystals Kyber768 历史快照里的秘密除法。M3 与 M4 是人工校准夹具，分别埋入秘密下标查表与提前返回比较，用来检验检测器能否识别已知机制。M5 是 mlkem-native 阴性对照，用来检查工具会不会误报。M1 对应 FIPS 203 初始公开草案（ipd），M2 是历史 Kyber768，两者按各自版本记录。五类对象的结果按角色各自使用。

五类对象覆盖三种角色，是为了让同一套规程同时面对真实缺陷、已知机制与阴性对照。真实案例回答能否修复，人工夹具回答检测器能否识别，阴性对照回答会不会误报。一类对象的各角色结论独立评价。

四个共享层是计时入口、锁频控制器、统计与功效、定位工具与结果登记。计时入口统一读钟与窗口，锁频控制器统一工作点与恢复核对，统计层统一家族、合并与预算口径，定位层统一工具版本与结果字段。四段链是检测、定位、防护、复测：检测回答能否分开，定位回答差异来自哪，防护回答改什么，复测回答改动是否生效。同一份原始数据可以供多层引用，各层结论按其自身口径评价。总体架构见图~\ref{fig:architecture}。

平台把判定用的二进制与计时用的二进制绑定为同一个。每次运行记录源摘要、产物摘要、编译器与选项，定位工具读的产物和计时窗口跑的产物是同一份。换编译选项等于换被测对象，必须重新登记：产物形态一变，基于旧产物的判定即失效，需要在新产物上重新判定。这条约束把“源码改了”与“产物变了”分开，也是后面所有分层结论的前提。

\subsection{主要工作与创新点}

现有侧信道评估面临三个挑战：工具结论孤立、源码与机器码脱节、阴性结论缺乏量化边界。平台将统计检验、动态污点分析与形式化验证组织进同一流程，每一步都绑定编译产物与检测预算。针对第 1.1 节所述的四大工程挑战，在证据建模、受控测量、多工具交叉定位与跨环境边界评估四个维度（与现有代表性工作的详细对比见第 5.1 节表~\ref{tab:compare}）：

第一，分层证据模型：把机制存在、热点可测、端到端可测与防护有效分为四层登记，并用最小可检测效应量化未检出。传统评估往往将”工具扫出可疑代码（定位阳性）”与”外部能测出时间差（计时阳性）”混为一谈。M2 的实测表明：尽管动态分析工具定位到三处依赖秘密的整数除法，但在本机完整解封装和函数级微基准计时中均未测出显著时间差。为此，平台将所有结论细分为”检出、未检出（附带 MDE）、未执行、不适用”四种明确状态，避免将”当前样本量下未测出差异”夸大为”绝对无泄漏”。该方法需要在每次采集前冻结检验计划并记录产物摘要，增加了约 15\% 的实验管理开销。五个模块的四层结论对比（表~\ref{tab:modules}）、防护前后对比（表~\ref{tab:beforeafter}）与各家族 MDE（表~\ref{tab:mde}）分别见第 4.3、4.6、4.7 节。

第二，预注册与可审计的锁频协议：采集前冻结检验计划，控制器校验计划摘要并核对频率恢复，使每次判定可追溯、可复算。主类对、样本预算、停止条件与 Holm 家族在采集前一次冻结，事后不再调整。放行前做 20 次频率探针，退出核对恢复。三个对象的不锁频/锁频变异系数比分别为 0.964、1.006、1.089，说明本机的相对噪声水平接近；锁频的作用以频率工作点的可核对、可恢复性评价。% A-29
该协议增加了计算资源与登记成本（3.5、3.6 节），但保证了每次运行都能回溯到具体的频率设定。锁频核对与跨级别复现见第 4.10 节，与现有计时实践的对照见表~\ref{tab:compare}。

第三，多工具交叉与 90 格排查：用 9 工具 $\times$ 5 模块矩阵和 90 格排查，把定位阳性与计时阳性分开，并识别官方修复后残留的同源分支。每个存在格给出函数、指令与触发输入，每个不存在格写明检查手段与覆盖输入。90 格中 5 格存在、75 格不存在、10 格不适用、0 格未检查。% A-22
平台定位到三处依赖秘密的整数除法（函数名、指令地址见 4.4 节），避免了单一统计工具无法定位代码、单一动态工具无法评估本机实际时延的局限。
90 格排查还发现，KyberSlash 官方修复提交后的产物仍保留与 clangover 同源的消息编码分支，说明消除除法之后，整个产物中的秘密相关机制仍需逐格核验。该项是全流程排查方法的超额发现，逐指令时序归因列入后续工作。该方法需要工具安装、版本固定与人工核对（4.5、4.12 节）。90 格明细见附录 D（表 D1--D4），9 工具 × 5 模块矩阵见图~\ref{fig:tools}。

第四，产物与环境的依赖对照：把同一源码在优化级别、架构、虚拟化与网络条件下的产物形态与可检出性并列，界定结论的适用边界。12 格优化级别、12 格 aarch64、三台 WSL2 与 5 档同机网络分开登记，时间证据按环境分别归档。直觉是分支越多越容易测到，实测 -O2 与 -O3 的命中位置更多，计时却未检出。M1 的机制在 aarch64 上不复现。% A-26 % A-27
跨环境实验按环境独立记录（4.10、4.11 节）。12 格优化级别、12 格 aarch64 与 5 档同机网络的结果见图~\ref{fig:opt}、图~\ref{fig:boundary}。

以上四项工作回答同一个问题：
\textbf{同一份源码在不同产物上可以有不同结论，
证据必须逐层、逐产物、按预算记录。}
每条结论都能回到一个具体的产物、一个明确的证据层和一组可复算的数字。

\subsection{关键结果与性能概览}

五个模块在同一套测量与统计规程下形成了不同层次的结论：M1 的分支差异在修复后未检出，M2 虽在定位层命中但计时层未检出，M4 提供脆弱实现与常数时间实现的前后对照，M5 在既定预算内未误报。表~\ref{tab:modules} 展示五个模块在定位层、端到端计时层与防护复测层的横向结果。

M2 在不同运行批次间呈现不稳定的测量结果：旧版本倾向于慢 12.35 ns，新版本反而快 11.20 ns，这种"翻转"说明环境噪声超过了除法本身的效应。
\textbf{异质性指标 $I^2=58.3\%$（类似多次称重时天平基线的波动率，第 2.4 节）表明六轮测试间存在明显的环境漂移}，因此跨版本合并值只用于概括观测，正式判定仍采用采集前规定的逐次 Holm 检验，两版均未检出。% A-03
M4 的脆弱实现区间不含 0，常数时间实现区间含 0，前后对照因此在同一张表上完成。% A-06 % A-07

未检出的格子都附了预算：M2 的 MDE 为 24.7--67.1 ns，M3 为 17.7--33.7 ns，M5 为 13.5--28.3 ns。% A-15
五个模块的结论按证据层分别解读：M1 与 M4 在定位层和计时层都发生变化，构成前后对照；M2 虽在定位层命中，计时层修复前后均未检出；M3 的开启查表版与消除查表版用于验证检测器能否识别已知机制；M5 是阴性对照。M4 是唯一在定位层与计时层均阳性、且常数时间实现均未检出的正对照，可据此检查检测链路对已知机制的响应。

M1 的三次运行区间均不含 0，Holm 家族中只有这一项被拒绝，这是唯一在端到端层被判阳性的真实案例。% A-09

上述结果共同印证了一个核心认识：“源码或机器码中的缺陷已消除”与“外部计时测不出显著差异”属于不同层面的结论，必须分别验证。对于 M1，官方补丁消除了机器码中的条件分支，端到端耗时差异也同步回落至统计不可区分范围（置信区间包含 0）；对于 M2，补丁虽在机器码层面彻底消除了三处除法指令，但无论修复前后，其耗时差异本身就小于本机测量噪声的分辨下限；对于阴性对照 M5，未检出任何异常同样仅代表在当前样本规模与分辨精度下未发现侧信道。

性能开销按成对分块测。M1 修复使完整解封装 $+1.51\%$，M2 修复 $-2.92\%$：修复的开销方向因实现而异，“变快”与“变安全”是两个独立维度，独立记录。% A-25
