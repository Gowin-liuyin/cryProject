\reportabstract{%
\linespread{1}\selectfont
\textbf{ML-KEM-768}（FIPS 203）的解封装在 Fujisaki-Okamoto（FO）变换下依次执行解密、重加密、密文比较与隐式拒绝，四步均接触私钥或解密消息。一次完整解封装耗时在 \textbf{50 $\mu$s} 量级，而内部消息位引起的泄漏时延仅数十纳秒，单次测量完全淹没在系统噪声中，须靠 \textbf{每类 10,000 次调用、三次独立运行}及采样前预先冻结的多重检验规则才能可靠分离。同时，C 源码无分支不等于编译后的机器码无分支，单一检测工具无法互相替代，“未检出泄漏”也必须附带当前测量噪声下的最小分辨量程——\textbf{最小可检测效应（MDE）}。为此，本作品面向 ML-KEM-768 便携 C 实现构建“\textbf{检测—定位—防护—复测}”一体化平台，覆盖五类代表性被测对象：liboqs 0.10.0 消息编码分支（M1）与 pq-crystals Kyber768 秘密除法（M2）两个真实历史案例；秘密下标查表（M3）与 32 B 提前返回比较（M4）两个人工校准夹具；以及 设计为常数时间的 mlkem-native 阴性对照（M5）。平台通过 CPU 锁频固定测量工作点，采样前冻结全 0 与全 1 消息密文对比组（主类对）、样本量与 Holm 检验家族；统计层采用 Welch 检验、Holm 校正、多轮逆方差合并与 MDE 预算量化每项结论；定位层联合反汇编、Memcheck、varlat、Microwalk 与 Binsec 多工具交叉验证，并按“3 实现 $\times$ 5 步骤 $\times$ 6 类来源”完成 \textbf{90 格}全流程排查，所有判定均严格绑定 \textbf{同一份编译产物}。\par
实验表明：M1 未修复版主类对均值差为 \textbf{+32.3 ns}（仅占 57 $\mu$s 总耗时的 \textbf{0.06\%}），三轮独立运行方向一致，引入官方补丁后置信区间跨 0（未检出），解封装开销仅增加 \textbf{1.51\%}；M2 三处秘密除法在定位层稳定命中、修复后归零，而端到端与热点微基准均未检出，端到端 MDE 为 \textbf{24.7--67.1 ns}，实证了 \textbf{定位阳性不等于计时阳性}；M4 脆弱实现显著可区分，改造为常数时间实现后未检出；M5 在本机预算下未检出，\textbf{7 种工具误报为 0}。此外，90 格全流程排查发现了 KyberSlash 官方除法补丁未消除的同源消息编码分支；同一份 M1 源码在 aarch64 架构上编译为无分支条件选择指令；同机网络各档在当前样本预算下均未检出。本作品通过“真实历史案例的官方补丁与机器码核验、人工夹具的自主常数时间改造、平台 \textbf{1,048 个调用点}审计与退出码修复”形成 \textbf{三层防护闭环}，赛题 \textbf{12 项}技术要求全部满足（见附录 A）。%
}
