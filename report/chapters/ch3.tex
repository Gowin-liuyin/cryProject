\section{设计与实现方案}

这一章讲检测平台怎么搭。起点不是工具，而是解封装流程本身：先弄清哪些步骤接触秘密，测量、判定、定位和防护才有依据。本作品要分辨的差异只有几十纳秒，单次测量看不出来，所以测量、统计和定位必须一起设计。下面从解封装流程与泄漏面讲起，按测量、判定、定位、防护的顺序说明每一步的做法与取舍。

\subsection{解封装流程与泄漏面}
% A-17--A-23 机制与定位证据，A-22 90 格
% B-06 90 格分解

ML-KEM 解封装在 Fujisaki--Okamoto 变换下完成解密、重加密、比较与隐式拒绝四步计算，每一步接触的秘密并不相同。解密接触私钥与解出的消息，重加密把消息重新送进编码、数论变换、压缩与序列化，比较同时接触真密钥与假密钥，隐式拒绝决定失败时输出什么。把这条链笼统称为“实现有侧信道”，后续的测量与定位就没有落点。泄漏面必须按步骤拆开，才可能落到函数与指令。\cite{fips203}

\begin{algorithm}[H]
\caption{ML-KEM 解封装与隐式拒绝}
\label{alg:decaps}
\begin{algorithmic}[1]
\Require 密文 $c$（1088 B），解封装密钥 $dk=(dk_{\mathrm{PKE}},h,z)$
\Ensure 共享密钥 $K$（32 B）
\State $m' \gets \mathrm{K\text{-}PKE.Decrypt}(dk_{\mathrm{PKE}}, c)$ \Comment{解密，使用私钥}
\State $(K', r') \gets G(m' \parallel h)$ \Comment{派生候选密钥与重加密随机数}
\State $c' \gets \mathrm{K\text{-}PKE.Encrypt}(dk_{\mathrm{PKE}}, m', r')$ \Comment{重加密}
\State $\bar K \gets J(z \parallel c)$ \Comment{隐式拒绝的假密钥}
\State $K \gets \mathrm{Select}(c' = c,\ K',\ \bar K)$ \Comment{常数时间比较与掩码选择}
\State \Return $K$
\end{algorithmic}
\end{algorithm}

算法 1 回答的是标准结构中哪些数据接触秘密，不表示任何具体实现编译后的样子。M1 的对象是 FIPS 203 初始公开草案（ipd），M2 是历史 Kyber768，二者都不等同于最终标准。标准伪代码也不记录实现选择：消息编码可以逐系数写，也可以批量写。压缩可以原地进行，也可以先拷贝。实现选择决定一条分支落在哪个函数、哪条指令。后面排查表里的“步骤”因此只是第一层坐标，第二层坐标必须是函数与指令。

第 1 步解密的秘密是私钥与解出的消息。消息解码函数里的一次整数除法，就是 M2 三处秘密除法中的第一处。除法指令的时延随操作数变化时，私钥系数会进入耗时。\cite{kyberslash} 第 3 步重加密把消息重新送进消息编码、数论变换、压缩与序列化：M1 的分支出现在消息编码，编译器把源码中的掩码选择还原成按位测试后条件跳转。M2 的另两处除法出现在多项式压缩与向量压缩。M3 的人工秘密下标也插在这条路径上。\cite{clangover}

第 4 步比较对应 M4 的提前返回夹具。第 5 步的隐式拒绝必须由常数时间比较与掩码选择完成。只要实现让分支或提前返回依赖比较结果，成功与失败两条路径就可以从耗时上分开，隐式拒绝的设计目的就落空。图~\ref{fig:decaps} 把这条对应关系画在同一张流程图上。M5 不挂在单独一步上，它作为整条链的阴性对照。图中“是/否”表示密钥的逻辑选择，实际实现同时计算拒绝密钥，再用掩码选择输出。

泄漏来源按题面第 5 条分为六类，每一类都在解封装链上有明确的作用点。

\begin{enumerate}
\item 敏感条件分支：消息位或比较结果决定执行路径，两条路径的指令数或访存不同。
\item 提前返回：比较在发现第一个不同字节时结束，函数返回时刻取决于失配位置。
\item 可变时间比较与可变时延指令：逐字节比较提前退出，或整数除法等指令的时延随操作数变化。
\item 秘密下标访存：查表下标含秘密位，不同下标落在不同缓存行。
\item 数据相关循环：循环次数或迭代上界随秘密变化。
\item 异常处理路径：成功与失败走不同的分支、日志与返回码。
\end{enumerate}

六类来源的检查手段不同：前三类靠反汇编与秘密标记，第四类靠执行轨迹与秘密的互信息，第五类靠控制流核对，第六类靠泄露渠道审计。工具放在 3.7 节，这里只固定分类口径，避免同一现象被两个名字重复登记。

这六类不是互斥的标签，而是按“秘密以什么方式影响执行”划分的检查口径。同一条指令可能同时属于两类，例如逐字节比较既是可变时间比较，也可能带提前返回。排查时按“最早把秘密带入可观测差异的那一步”归类，避免同一现象在两格重复计数。归类规则写进排查表的使用说明，换人核对时按同一口径。题面列出的六类来源覆盖了从控制流、访存到错误处理的主要通道。功耗、电磁这类物理通道不在本作品范围内，因为平台只测时间。

把这六类来源分别放到三个实现、五个解封装步骤上，就得到 $3\times5\times6=90$ 格的全流程排查表。五个步骤是解密、哈希派生、重加密、密文比较与隐式拒绝。三个实现是 M1、M2 与 M5，人工夹具 M3、M4 不进入这张表。每一格只允许四种判定：存在、不存在、不适用、未检查。判定规则在排查前写定：判“存在”必须给出可指认的函数、指令或源码位置以及触发它的输入。判“不存在”必须写明用了哪种检查、覆盖了哪些输入。判“不适用”要求该机制在这一步骤上不可能出现，例如该步骤没有异常处理。判“未检查”单列，不得并入阴性。

逐格结论与证据编号见 4.5 节与附录 F，本节只定义方法与判定规则。

每一格的记录不只写判定，还要写证据。字段包括：实现与产物摘要、步骤、来源类别、判定、函数名或指令地址、触发输入、使用的检查手段、证据编号。判“存在”的格子必须有触发输入。没有触发输入的“存在”只能算“疑似”，在汇总时降级为“未检查”。判“不存在”的格子要写覆盖了哪些输入。只跑过一个输入的阴性不足以支撑“不存在”。这套字段让 90 格既是排查表，也是审计清单：换一个人按同样字段复核，结论应当一致。

五步的划分比算法 1 多出“哈希派生”一步。算法 1 把派生与重加密写在一起，排查时若合并，哈希路径上的问题会被记到重加密名下。拆开后，派生步骤只检查哈希调用本身，重加密步骤只检查编码、变换、压缩与序列化。代价是排查表多出一列，但定位结论可以直接落到“哪一步、哪个函数”。

如果不按步骤拆，M1 的消息编码分支与 M2 的压缩除法都会被归到“重加密有问题”这一个大类里。重加密路径覆盖编码、变换、压缩与序列化多段代码，定位只能停在这一层，修复也无法核对到底改了哪条指令。90 格把每一格绑定到“实现 × 步骤 × 来源”，任何一格判“存在”都附一个可复核的代码位置，修复后同一格可以被复查为“不存在”。修复后按同一张表复查，目标格从“存在”变为“不存在”，其余格保持不变，修复的副作用也能被看见。代价是排查前要为每个实现准备五步的证据口径，排查后要维护 90 条带证据编号的记录。这部分工作量换来的是定位结论可追溯。

\subsection{泄漏机理与攻击可行性}
% A-01--A-08 主结果，A-13 dudect M2
% B-01 效应占比，B-07 样本账

输入类与重复调用遵循第 1.2 节的威胁模型：评估者选择密文类别与调用次数，观察完整解封装耗时。主检验比较两类合法等长密文的耗时分布，并报告样本量与检测预算。

一次解封装的耗时可以写成
\[
T = T_0 + \delta(\text{secret}) + \text{noise},
\]
其中 $T_0$ 是公开路径的平均耗时，$\delta$ 是秘密相关部分，noise 来自调度、频率、缓存与地址对齐。M1 未修版本在 57 µs 的均值上只多出 32.3 ns，$\delta/T_0$ 约为 0.06\%。本地锁频压住的是噪声中的频率项，压不住 $\delta$ 本身。要在噪声里分出 $\delta$，只能靠大样本与预注册检验。每类 10,000 次、三次独立运行，是把可检出下界压到几十纳秒量级的直接原因（3.5、3.6 节）。图~\ref{fig:adversary} 把观测模型与泄漏方程画在一起：左侧是攻击者控制的输入，上方是固定密钥的解封装预言机，右侧保存耗时样本，下方给出统计判定与泄漏方程。 % A-01 % B-01 % B-07

主类对在固定解封装密钥对 $(pk,dk)$ 下构造。由公开种子派生封装随机数，分别将内部 32 字节消息 $m'$ 固定为全 0（\texttt{0x00...00}）和全 1（\texttt{0xFF...FF}），再经合法封装流程生成长度均为 1088 字节的有效密文 $C_0$ 与 $C_1$。两类输入在解封装时均经过解密、重加密、密文比较和隐式拒绝选择代码；固定密钥、种子派生流程与长度一致，实验自变量是预设消息位，密文其他字段由标准算法随之派生。

\begin{algorithm}[H]
\caption{攻击者的计时观测与可区分性实验}
\label{alg:distinguish}
\begin{algorithmic}[1]
\Require 解封装预言机 $\mathcal{O}$，两类合法等长密文 $C_0,C_1$，每类样本 $n$，显著性 $\alpha$
\Ensure 可区分 / 未检出（附效应量与区间）
\For{$b \in \{0,1\}$}
  \For{$i=1$ \textbf{to} $n$}
    \State $c \gets \mathrm{Sample}(C_b)$ \Comment{由公开种子派生，长度合法}
    \State $t_{b,i} \gets \mathrm{Time}(\mathcal{O}(c))$ \Comment{只测一次完整解封装}
  \EndFor
\EndFor
\State $\Delta \gets \mathrm{mean}(t_0) - \mathrm{mean}(t_1)$
\State $CI \gets \Delta$ 的 95\% 置信区间
\If{$CI$ 不含 0}
  \State \Return 可区分 $(\Delta, CI)$
\Else
  \State \Return 未检出 $(\Delta, CI, \mathrm{MDE})$
\EndIf
\end{algorithmic}
\end{algorithm}

四类机理可以用最小形态写清楚。代码 1 到代码 4 只保留结构，不写完整实现，也不构成可直接复用的攻击代码。

\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[caption={秘密相关分支的最小形态},label={code:branch}]
/* 消息位决定走哪条路径；两条路径的指令数或访存不同 */
int16_t select_coeff(const uint8_t *msg, size_t i)
{
    if ((msg[i / 8] >> (i % 8)) & 1)
        return COEFF_ONE;
    return 0;
}
\end{lstlisting}
\end{minipage}

代码 1 对应 M1 的消息编码：源码本用掩码，编译器在特定选项下把它还原成按位测试后条件跳转。边界是：这段代码只说明机制，不代表上游源码的原样写法。分支是否出现取决于编译器与优化选项，必须看实际产物。

\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[caption={秘密相关除法的最小形态},label={code:divide}]
/* x 来自解密消息；整数除法的时延可能随操作数变化 */
int16_t compress_coeff(int16_t x)
{
    return (int16_t)((((int32_t)x << 4) + (Q / 2)) / Q);
}
\end{lstlisting}
\end{minipage}

代码 2 对应 M2 的三处除法，$Q$ 为公开模数。边界是：除法是否真的有可测时延取决于处理器与编译选项。本作品在特定产物上定位到三处整数除法，但端到端与热点微基准都未检出。

\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[caption={秘密下标查表的最小形态},label={code:lookup}]
/* 下标来自消息位；不同下标落在不同缓存行 */
int16_t lookup_coeff(unsigned secret_index)
{
    static const int16_t table[16] = { /* 16 个公开常数 */ };
    return table[secret_index & 15];
}
\end{lstlisting}
\end{minipage}

代码 3 对应 M3 的人工校准夹具：查表插在常数时间基线的重加密路径上，开启查表版（on版）与消除查表版（off版）的输出逐字节相同，用于检验工具对秘密下标访存的识别能力。

\noindent\begin{minipage}{\linewidth}
\begin{lstlisting}[caption={提前返回比较的最小形态},label={code:early}]
/* 发现第一个不同字节就返回；耗时取决于从哪里开始不同 */
int compare_bytes(const uint8_t *a, const uint8_t *b, size_t len)
{
    for (size_t i = 0; i < len; i++)
        if (a[i] != b[i])
            return 0;
    return 1;
}
\end{lstlisting}
\end{minipage}

代码 4 对应 M4 的比较夹具：脆弱实现（vulnerable版）发现首个不同字节即返回，常数时间实现（ct版）逐字节异或累积并在固定长度结束后统一判断。两版输出保持逐字节相同。

可区分性是侧信道分析链中的一环，机制是否存在、计时是否可区分、攻击是否可利用需要分别评估。M2 是典型例子：三处除法在定位层稳定命中，端到端完整解封装与除法热点微基准均未检出；同一份实现中，dudect 的最大 $t$ 还落在已修复版上。证据因此按机制、计时与可利用性分层登记。

主类对只让解密消息的位全 0 或全 1 不同，其他条件相同。这样两类的路径长度接近，差异只能来自消息位。随机密文、逐字节篡改、格式破损与截断属于族外对照：随机密文检验一般路径，篡改与破损检验隐式拒绝，截断检验公开长度检查。它们不进入主家族，因为输入路径长度或返回位置不同，混入会把路径差异误读为秘密泄漏。族外对照只作描述，不进入 Holm 家族，用于检查主类对之外的输入行为。

冻结计划层在采集前写定主类对、样本量、停止条件与 Holm 家族，并生成计划摘要。测量层每次运行校验摘要，防止采集开始后改规则。被测模块层固定五个对象，记录源摘要、产物摘要、编译器、选项与反汇编，判定与计时使用同一个二进制。测量层执行计时循环与锁频控制，每次调用逐次落盘，失败样本单列。分析层三路独立：统计判定回答“是否可区分”，定位工具回答“哪里依赖秘密”，族外检验回答“换个统计口径是否还成立”。结果登记层把每条结论写成四种状态之一，附运行编号与证据编号，未执行与不适用不并入阴性。图~\ref{fig:architecture} 给出五层的顺序与共用的规程。

五层的顺序不是排版顺序，而是防篡改顺序。计划在最前，后续每一层都只能按计划执行。被测模块在测量之前固定，避免测到一半换产物。分析在测量之后，三路互不覆盖。登记放在末端，任何一条结论都必须带运行编号与证据编号。探索性分析可以做，但不能进主家族，只能作为族外观察或后续工作登记。

登记层的每条记录都有唯一编号，编号由运行编号、证据编号与计划版本三段拼接。引用时只写编号，不再复述结论。这样第 4 章引用第 3 章的方法时，读者可以顺着编号回到原始记录，而不必在两章之间寻找同一句话。

计划摘要还有一个副作用：任何一次运行都能被独立复算。审计者拿到计划文件、运行记录与原始值，可以重算摘要、重跑统计、核对恢复记录。不需要信任报告里的叙述。被拒绝的运行同样登记，编号连续，审计时能看到“尝试过但没通过”的记录，而不是只看到成功的样本。

四层证据是登记时的四个层次。机制层看源码、反汇编与动态标记能否指出秘密相关行为。热点层看函数级微基准或工具定位到的热点是否显示时间差。端到端层看完整解封装的类对检验。防护复测层看修复后在同一规程下重测的结果。

四层的判据不同：统计层的“检出”是预注册检验拒绝，“未检出”是预先规定的检验未拒绝零假设。定位层的“检出”是工具稳定命中且能归因到函数、指令或源码行，动态工具的“未检出”只覆盖执行过的输入。防护复测层的“检出”是修复后目标机制仍在或计时差仍可区分。四种状态互斥：检出、未检出、未执行、不适用。未执行是没做，不适用是机制与步骤的组合不可能出现。

四种状态里最容易混淆的是“未检出”和“未执行”。未检出有样本、有检验、有 MDE；未执行则记录缺少的条件与受影响条目。附录 A 与第 6.2 节列出这些记录，不计入阴性。

如果不分层，M2 的“定位阳性、计时阴性”会被写成自相矛盾的一句话。分成机制层与端到端层登记后，两句话分别属于不同层，可以同时为真，而且各自带各自的判据与预算。代价是同一模块要做多次登记，报告必须保留“未执行/不适用”行，篇幅增加。分析层三路还要各自维护输入清单，换工具就要重跑对应格。换来的是任何一条结论都不会被另一层的证据误读。

M1 与 M2 是真实历史案例。M1 的可移植 C 路径在特定编译器与选项下被还原出分支，M2 的历史 Kyber768 参考实现出现三处秘密除法\cite{kyber2018}。两者都有上游修复可比对，因此能同时回答“检出”与“修复后是否消失”。代价是真实案例不能任意控制变量：M1 的构建要额外处理运行时分发，M2 的除法只在特定优化级别出现。

M3 与 M4 是人工校准夹具：M3 在常数时间基线的消息编码路径上插入秘密下标查表，M4 用独立的 32 B 比较函数对比提前返回与常数时间两个版本。两版输出逐字节相同，确保校准的是检测器而不是算法语义。人工夹具回答“工具能不能识别目标机制”，不回答“真实库有没有这个缺陷”。M5 是阴性对照，设计为常数时间，用来估计工具误报。它在七种工具上的误报为 0，这个数字只说明这七种工具在这个对象、这些输入上没有报假阳性，不说明 M5 已达到常数时间。

人工夹具的设计要点是“只差目标机制”。M3 的开启查表版（on版）与消除查表版（off版）除查表外完全相同，M4 的两个版本除比较方式外完全相同。输出逐字节相同是先决条件，否则计时差异可能来自语义变化而不是泄漏。代价是夹具只能覆盖一种机制，不能代表完整解封装的交互。真实案例补上这一点，但真实案例又不能任意开关机制。三类角色合起来，才覆盖“能检出、能识别、不误报”三个问题。

选择历史 Kyber768 而不是最终标准作为 M2 的对象，是因为 KyberSlash 的两处修复提交落在历史代码上。最终标准改了消息编码与压缩的实现细节，同一机制在最终标准里可能已被间接消除。要检验平台能否识别这个机制，必须在机制存在的版本上做。把 M2 写成 ML-KEM-768 会把对象描述弄错。

判定用的二进制与计时用的二进制必须相同。每次运行记录源摘要、产物摘要、编译器版本、选项与反汇编摘要。采集前核对产物摘要，分析时再核对一次；M1 前期封存批次的来源在运行台账中单独标注。分析脚本拒绝没有摘要的输入，避免手工拷入的数据混入统计。

复现历史案例时，有两项编译配置直接决定待测机制是否真正执行。第一，liboqs 会根据 CPU 能力在运行时选择实现；只调整可移植构建选项，仍可能调用 AVX2 优化路径。因此需要同时关闭 AVX2 指令与对应实现开关，再用反汇编确认调用的是目标 C 函数。第二，M2 在本作品选定的 \texttt{-Oz} 体积优化构建中保留硬件 \texttt{div} 除法指令，换用其他优化配置可能被改写为乘法与移位。采集程序因此记录并核对二进制摘要，产物一变就拒绝沿用旧结论。

版本固定还意味着第三方代码只读：上游文件不改，修复以补丁形式叠加，补丁前后的源摘要与产物摘要都登记。这样一来，“官方修复”与“团队修改”不会混在同一次构建里，审计时可以分别核对。两次构建核对都进运行记录，缺一份就不能出具判定。

M1 的对象是 FIPS 203 初始公开草案，不是最终标准。草案与正式版的密钥生成采用不同的哈希输入，正式版增加了用于区分参数集的域分隔字节。KeyGen 测试专门核对这一标准演进差异，避免把版本不匹配误判为算法实现错误。对象版本必须与期望向量一致，功能结果和侧信道结论才能正确解释。

如果不绑定产物，就会出现“判定的是 A 二进制、计时的是 B 二进制”的情况：定位工具在带调试信息、未优化的构建上命中，计时却在发布构建上采集，两条结论无法拼到一起。产物绑定把每次判定压到一个摘要上，任何一次重跑都能回答“当时测的是哪个文件”。代价是每换一次编译器或选项都要重新构建、重新记录摘要，跨环境实验的构建次数因此成倍增加。

\subsection{测量层设计}

受控测量采用六项措施：将采集进程绑定到 CPU2 或 CPU6；关闭睿频并将频率上下限请求设为 4.30 GHz；将调速策略设为性能模式；在窗口外预热 100 次；按公开种子随机交错两类密文；将内存分配、日志和 I/O 全部移出计时窗口。各项配置及频率探针随运行保存，结束后恢复原设置。

% A-29 锁频对照，A-30 计时精度，A-31 运行批次
% B-07 样本账，B-08 运行批次合计

测量层的目标不是“跑得快”，而是让每次调用的耗时都能被复算、被追溯，并且每一步的边界都清楚。计时窗口里多放一次内存分配或一行日志，32 ns 量级的效应就会被淹没。窗口外少做一次预热，前几百次调用会把缓存与分支预测的冷启动写进均值。

\begin{algorithm}[H]
\caption{单次解封装的计时循环}
\label{alg:timing}
\begin{algorithmic}[1]
\Require 被测二进制，类别集合 $\mathcal{C}$，每类样本 $n$，种子 $s$，CPU 核 $k$
\Ensure 逐次记录与元数据
\State 生成输入流。按 $s$ 做可复现的类别乱序。记录输入流摘要
\State 在计时窗口外预热 100 次
\For{每个（类别，密文）按乱序}
  \State $t_0 \gets \mathrm{Clock}()$
  \State $\mathrm{Decaps}(\text{密文})$ \Comment{窗口只包住一次完整解封装}
  \State $t_1 \gets \mathrm{Clock}()$
  \State 写入运行编号、实现、类别、序号、$t_1-t_0$ 与单位
\EndFor
\State 记录元数据：源摘要、产物摘要、编译器、选项、时钟、频率、CPU、计划摘要
\State 失败样本单列。不删普通长尾。不扣读钟开销
\end{algorithmic}
\end{algorithm}

算法 3 回答的是一次调用的耗时怎样被测到、怎样被落盘。它不回答这个耗时是否可区分，也不回答测量环境是否受控，后者由算法 4 与独立运行设计负责。

计时循环还有一个容易忽略的约束：每次调用后返回值必须被用掉。编译器可能把没有用到的解封装调用整个删掉，或者把循环折叠成一次调用。把返回值写入一个随后被校验的累加器，才能保证每次调用真的发生。代价是多一次内存写，但它在窗口之外。

输入生成、内存分配、结果处理、日志与 I/O 全部在窗口外，窗口内只有一次完整解封装。类别乱序按种子生成，避免“先测完 A 再测 B”时环境漂移造成假差异。预热 100 次让缓存与分支预测进入稳定状态。原始值全量落盘，普通长尾保留，异常样本规则在计划中预先写定，不在看到数据后删点。代价是每次运行产生的逐次记录与样本量同阶，存储与整理成本随运行次数线性增长。收益是任何一次判定都能从原始值复算。

读钟开销不扣：扣掉一个常数不改变两类均值差，却会让原始值失去可复算性。读钟开销约 17.4 ns，已在分辨率说明里单列。窗口内的调用返回值必须被用掉，窗口外的日志与内存分配全部移走。这两条比“换一个更快的时钟”更能决定数据质量。预热次数也是计划里写定的。它只负责让缓存与分支预测进入稳定状态，继续增加预热不会改变分布，只会增加机时。

\begin{algorithm}[H]
\caption{锁频控制与恢复核对}
\label{alg:frequency}
\begin{algorithmic}[1]
\Require 目标频率 $f_0=4.30$ GHz，CPU 核 $k$，探针次数 $m=20$
\Ensure 放行 / 拒绝。进入、采中、退出三段记录
\State 保存睿频开关、调速策略、能效偏好与频率上下限的原始快照
\State 关闭睿频。调速策略设为性能模式。能效偏好设为性能模式。频率下限与上限均设为目标频率
\State 用绑核工具把被测进程绑定到核 $k$
\State 等待 1.0 s
\For{$i=1$ \textbf{to} $m$}
  \State 读当前频率。间隔 50 ms
\EndFor
\If{全部 $|f-f_0|/f_0 \le 2\%$ 且 $\max-\min \le 50000\text{ kHz}$}
  \State 放行
\Else
  \State 拒绝，恢复快照，记录原因
\EndIf
\State 采集结束后恢复快照。读取并比较恢复核对结果
\end{algorithmic}
\end{algorithm}

算法 4 回答的是“这次采集的频率工作点是否可核对、可恢复”。它不回答物理频率是否在每次调用中恒定，也不回答后台服务是否影响了单次调用。

探针的判据有两个：全部采样落在目标频率 ±2\% 内，且最大值与最小值之差不超过 50,000 kHz。前者防止工作点偏到另一个频率档，后者防止采集期间来回跳档。任一条不满足就拒绝本次采集，恢复快照并记录原因。拒绝的运行同样进台账并保留原因。20 次探针、50 ms 间隔覆盖约 1 s，这个窗口足以看到调速器是否稳定，但不足以保证整段采集不变频。采中的跨度因此单独记录。

放行判据作用于 20 次探针，不作用于采集中的每一次调用。采集中记录频率跨度，单独登记。恢复核对只证明设置恢复到进入前的状态，不证明物理恒频。不锁频与锁频的 A/B 对照里，变异系数比为 0.964、1.006、1.089，方向不一致。锁频提供统一、可核对、可复算的工作点。本机未配置 isolcpus，SMT 开启，后台约 39 个服务在运行。这些条件如实记录，量化尺度约 10 ns。 % A-29 % A-30

计时精度决定了什么样的效应可以被讨论。读钟开销约 17.4 ns，最小步进 10 ns。时间戳计数器的分辨率下界为 42--43 个计数、约 9.8--10.0 ns。计数器速率为 4,291,962 kHz。32 ns 的效应只有 2--3 个分辨率单位，单次调用不可分辨，必须靠每类 10,000 次、三次运行的大样本。1 ms 短区间的频率极差为 348 kHz，相对极差 $8.1\times10^{-5}$，相对标准差 $5.4\times10^{-6}$，说明短窗内频率稳定。长期稳定性未认证，只测了短区间与逐次运行中位频率。 % A-30

M4 的比较调用改用不做频率调整的原始单调时钟，窗口只包住一次 32 B 比较。它与完整解封装使用不同的时钟与不同的窗口，数值不可直接比较，所以表~\ref{tab:metrics} 不把 $-4.09$ ns 与 $+32.3$ ns 放在同一把尺子上。

每个模块做三次独立运行：r1 种子 31337、CPU2。r2 种子 424242、CPU2。r3 种子 31337、CPU6。换种子检查结论是否依赖特定输入，换核检查是否依赖特定物理核。每类 10,000 次、三次运行合计 30,000 条。两个版本合计 60,000 条，M5 单版本 30,000 条。 % B-07

三个编号不是三次重复同一件事：r1 与 r2 同核不同种子，r3 同种子不同核。三者一致说明结论不依赖输入与物理核；三者不一致则提示环境漂移或输入依赖，按预注册规则登记，不选取对结论更有利的一次。CPU2 与 CPU6 共享内存控制器与电源域，核间一致只能说明结论不依赖某个核的局部状态。

主类对是同一份确定性密文的 10,000 次重复，单次运行的区间反映的是测量噪声，不是密文间的变异。跨种子复测部分弥补这一点，但不等价于在每类内部使用大量不同密文。如果不锁频、不核对，频率漂移可以伪造类间差异：按 57 µs 的均值换算，1\% 的频率偏差约对应 570 ns 的均值移动，比 32 ns 的效应大一个数量级以上。锁频协议把工作点固定并留下可复核的记录。如果 I/O 留在窗口内，一次日志写入的微秒级开销同样会淹没信号。窗口设计把这类开销全部移到计时之外。

失败样本的来源分三类：调用返回错误、读钟异常、进程被调度打断。前两类单列。第三类不删，但按计划中写定的规则标记，敏感性分析时分别用截尾均值与中位数复核。规则在采集前写定，看到数据后不再改。这条约束与统计层的预注册是同一条纪律在测量层的体现。失败率与失败原因一并进台账，便于判断采集是否整体失效。

\subsection{统计层设计}
% A-09--A-16 统计判定与族外检验
% B-13 MDE 公式

统计层的目标不是“找到一个 $p$ 值”，而是让“检出”和“未检出”都有可比较的含义。一个只报 $p$ 值的实验，看到不显著可以加样本，看到显著可以停。这条路径最终一定通向“显著”，却说明不了效应大小与可检测下界。

每个模块的检验在采集前归为一个家族，全族 $\alpha=0.05$，做 Holm 校正：M1、M2、M3、M4 各 6 项（3 次运行 × 2 个版本），M5 3 项，共 21 项。主类对、样本量、停止条件与家族成员一次冻结，控制器每次运行校验计划摘要。停止条件固定为每类 10,000 次 × 3 次运行，不因中间结果延长或缩短。M1 的家族沿用前期封存计划，其余四份计划在采集前由同一提交冻结。

预注册的载体是一份计划文件：主类对的定义、每类样本量、三次运行的种子与核、家族成员、停止条件、异常样本规则都写在里面，采集前生成摘要。控制器每次启动校验摘要，摘要不符就拒绝运行。审计时独立复算摘要，确认计划没有被改过。计划文件与运行记录一起归档，任何一条判定都能回答“当时按哪份计划做的”。三次独立运行而不是一次，是为了估计运行间异质性：单次运行只能给测量噪声，三次才能算 $I^2$，并在合并时看出漂移。运行次数再增加会提高机时，按预注册的停止条件不再延长。

\begin{algorithm}[H]
\caption{统计判定与合并}
\label{alg:stats}
\begin{algorithmic}[1]
\Require 两组样本 $t_0,t_1$。家族大小 $m$。$\alpha=0.05$。功效 $1-\beta=0.80$
\Ensure $\Delta$、95\% 区间、$p$、Holm 判定、合并 $\Delta$、$I^2$、MDE
\State $\Delta \gets \mathrm{mean}(t_0)-\mathrm{mean}(t_1)$
\State $SE \gets \sqrt{\mathrm{var}(t_0)/n_0+\mathrm{var}(t_1)/n_1}$
\State $t \gets \Delta/SE$。自由度按 Welch--Satterthwaite 计算
\State $p \gets 2(1-T_{df}(|t|))$。$CI \gets \Delta \pm z_{1-\alpha/2}SE$
\State 家族内 $m$ 个 $p$ 值升序排序。Holm 逐步比较 $\alpha/(m-i+1)$
\For{每次独立运行 $i$}
  \State $SE_i \gets (CI_{\mathrm{high}}-CI_{\mathrm{low}})/(2z)$
  \State $w_i \gets 1/SE_i^2$
\EndFor
\State $\Delta_{\mathrm{pool}} \gets \sum w_i\Delta_i/\sum w_i$。$SE_{\mathrm{pool}} \gets \sqrt{1/\sum w_i}$
\State $I^2 \gets \max(0,(Q-(k-1))/Q)$，$Q$ 为 Cochran 异质性统计量
\State $\mathrm{MDE} \gets (z_{1-\alpha/2}+z_{1-\beta})\sqrt{s_0^2/n_0+s_1^2/n_1}$
\end{algorithmic}
\end{algorithm}

算法 5 回答的是给定样本如何得到均值差、区间、校正后的判定、合并估计与检测预算。它不回答输入类是否设计得对，也不把统计显著自动翻译成“可利用”。

选 Welch 而不是合并方差的学生 $t$，是因为两类的方差不一定相等：主类对只让消息位不同，路径长度接近，但缓存与分支预测的状态可能让两个版本的方差拉开。Welch--Satterthwaite 自由度不假设方差相等，代价是自由度略小、区间略宽。在每类 10,000 次下，这个代价可以接受。

统计量包括均值差 $\Delta$、Welch $t$ 与自由度、95\% 正态近似区间、Holm 逐步校正、逆方差固定效应合并、$I^2$ 与 MDE。区间与 $p$ 值用大样本正态近似（$z=1.9599639845$），不称为有限样本精确的 Student-$t$ 区间。三次运行按逆方差固定效应合并。M2 的 $I^2$ 为 58.3\%，说明六次运行的结果一致性较弱，此时合并区间只作描述，判定以预注册的 Holm 结果为准。MDE 按 $(z_{1-\alpha/2}+z_{1-\beta})\sqrt{s_0^2/n_0+s_1^2/n_1}$ 计算，Holm 口径取 $\alpha/m$。MDE 用于说明给定样本量下的检出能力，正式判定由预注册检验给出。 % A-03 % A-15 % B-13

Holm 是逐步下降的校正：把家族内 $m$ 个 $p$ 值升序排序，第 $i$ 个与 $\alpha/(m-i+1)$ 比较，一旦某个不拒绝就停止，后面的全部不拒绝。它比 Bonferroni 少牺牲检验功效，同时仍然控制全族第一类错误。家族按模块划分，不把五个模块混成一个大家族：模块之间的效应机制不同，混在一起会让门槛过严，也会让一个模块的阳性掩盖另一个模块的问题。M1 的家族大小为 6，最小 $p$ 的门槛是 $0.05/6\approx0.00833$。门槛在计划里写定，不随观测到的 $p$ 值变化。

逆方差固定效应合并把三次运行看成同一真值的三次估计，权重取标准误平方的倒数。它假设运行之间只差抽样噪声。$I^2$ 衡量这个假设是否成立：M2 的 58.3\% 说明运行间还有未受控漂移，此时合并值只作描述，不能拿来替代单次判定。合并的代价是它会把异质性平均掉，所以每次合并都同时报告 $I^2$。

报告里同时给 $\Delta$、区间与 $p$ 值，是因为三者回答不同问题：$\Delta$ 给效应大小，区间给估计的不确定度，$p$ 值只回答“在零假设下观察到这么大数据有多罕见”。只给 $p$ 值，读者无法判断效应是否值得修。只给 $\Delta$，读者无法判断它是否超过噪声。

各家族的 MDE（Holm 口径）为：M1 31.39 ns，M2 25--67 ns，M3 18--34 ns，M5 14--28 ns，M4 最坏 1.47 ns。MDE 是事后功效描述，不改变已提交的判定。它回答的是“这个样本量下能看见多大的效应”，不是“真实效应有多大”。 % A-15

MDE 与样本量的平方根成反比：要把 MDE 减半，样本量要翻四倍。每类 10,000 次、三次运行的选择，是在机时与可检测下界之间取的折中。M2 的 MDE 25--67 ns 大于除法可能带来的效应，这是“定位阳性、计时未检出”的直接解释，也是 6.2 节把 M2 列为局限的原因。

族外检验不并入 Holm 家族。RTLF 在 $\alpha=0.01$、固定种子 2026101605、bootstrap 10,000 次的设置下对 M2--M5 的 42 个数据集给出 30 个未检出、12 个检出\cite{rtlf}。dudect 报告在线最大 $t$\cite{dudect}。Mona 用箱体分离比较两类样本的分布是否重叠。三者与 Welch 检验比较的对象不同：Welch 比较均值，RTLF 比较分布（含分位与尾部），dudect 与 Mona 是二值判据。它们的二值结论、最大 $t$ 或箱体结论都不转换成 $p$ 值参与校正，只作独立交叉印证。 % A-16 % B-04

族外检验的二值结论不转成 $p$ 值，原因有三：零假设不同（分布差异对均值差异）、错误控制方式不同（RTLF 用 bootstrap 控制第一类错误，dudect 用最大 $t$ 的经验阈值）、样本使用方式不同（在线检验与固定样本）。把三者并入同一个 Holm 家族，会得到一个既不是 0.05 也不是 0.01 的混合错误率。它们的位置是交叉印证：与主检验同向时增加信心，反向时提示输入类或环境有问题，而不是投票。

样本量不是先验拍定的：每类 10,000 次是在预实验中按观测标准差与目标 MDE 反推后冻结的，冻结之后不再调整。这样做的代价是方差估计本身也有不确定性，MDE 只能当作量级参考，不能当作精确的边界。正文提到 MDE 时都给区间或“最坏”值。

正态近似不是有限样本精确 $t$ 区间。MDE 是事后描述。$I^2$ 高时合并区间只作描述。这三条限定贯穿全文，4.7 节解释结果时仍按它们解读。如果不预注册，看到不显著就加样本、换分组，最终一定能“显著”。预注册把这条路径堵死，代价是失败尝试也要登记、机时成本上升，而且不能在看到更好结果时改计划。

另一条代价是探索性发现进不了主结论：90 格里后来注意到的现象只能作为族外观察登记，等下一轮计划再升级为正式检验。预注册的另一个效果是让阴性结果可以比较：未检出不是失败，而是带预算的结论。统计层的输出全部落成表格，任何读者都能用附录 C 的公式与原始值复算。

\subsection{定位层设计}
% A-17--A-21 定位工具输出

定位层把可疑行为落到函数、指令或源码行，并登记工具、输入、命中位置与上下文数量；机制命中和计时判定分别记录。

\begin{algorithm}[H]
\caption{秘密标记动态检查}
\label{alg:memcheck}
\begin{algorithmic}[1]
\Require 被测二进制，私钥 $dk$，秘密片段 $S=dk[0{:}1152]\cup z[0{:}32]$，公开输入集合
\Ensure 错误数、上下文数、源码位置或指令
\State 在动态检查工具下启动被测程序
\State 把 $S$ 标记为未初始化（秘密）。公开输入保持已初始化
\State 运行完整解封装，覆盖接受与隐式拒绝两类路径
\State 收集“以秘密值为分支条件”与“以秘密值为访存下标”两类报告
\State 收集进入可变时延指令的秘密操作数报告
\State 归因到函数、源码行、调用栈与指令地址
\State 对未修与已修两个版本重复。比较错误数与上下文数
\end{algorithmic}
\end{algorithm}

算法 6 检查秘密是否进入分支条件、访存下标或可变时延指令，并记录对应源码位置。秘密标记范围为私钥中参与解密的 1152 B 与隐式拒绝秘密的 32 B；公开输入保持已初始化。运行覆盖接受与隐式拒绝两类路径，报告按上下文归并：同一函数、同一源码行的多次命中记一个上下文，上下文数比错误数更能说明问题分布。

\begin{algorithm}[H]
\caption{Binsec 有界常数时间检查}
\label{alg:binsec}
\begin{algorithmic}[1]
\Require 抽取内核，入口与终点，秘密数组 $s$，公开数组 $p$，公开长度范围 1--16 B
\Ensure 不安全（附反例）/ 有界安全 / 未知
\State 固定目标架构、优化级别与编译选项。记录二进制摘要
\State 声明 $s$ 为秘密。$p$ 与长度为公开
\State 做关系符号执行，检查控制流与访存是否只依赖公开输入
\State 若存在反例，输出反例地址与路径
\State 检查待定、截断、中止与求解器未知四类状态是否为 0
\State 负对照：同一配置下已知脆弱内核必须判为不安全
\end{algorithmic}
\end{algorithm}

算法 7 回答的是给定入口、终点与长度范围内，控制流与访存是否只依赖公开输入。它不覆盖范围外的输入，也不检查运行时时序。有界验证的结论只在入口、终点与公开长度范围内成立。路径完整性要单独检查，搜索被截断时工具可能返回未知而进程仍然正常退出。负对照用同一配置下的已知脆弱内核，确保工具不会把脆弱代码判成安全。工具版本、补丁与调用参数在环境表里固定。换版本要重新跑受影响的格子，不能把旧结论直接搬过来。

五类工具各自回答不同的问题。反汇编回答“机器码里有没有目标指令形态”，不回答运行时是否真的触发。秘密标记的动态检查沿用 ctgrind 的思路，回答“秘密是否进入分支条件或访存下标”，不回答可变时延指令\cite{ctgrind}。可变时延检查回答“秘密是否进入除法等指令”，不回答缓存与分支。轨迹互信息回答“哪些指令与秘密的关联最强”，不回答时序可利用性\cite{microwalk}。有界符号执行回答“给定范围内是否存在秘密相关路径”，不回答范围外的行为\cite{binsec}。工具的版本在环境表中固定，输出摘要进附录 E。

五类工具的输出先归一化成同一种证据记录：工具与版本、输入集合、命中位置、上下文数、处置结论。归一是为了交叉：同一位置被两类工具命中记两条证据，只有一类命中时保留但不升级为“确认”。处置结论只取四种状态，与 3.3 的登记口径一致。

归因要求可复现：同一位置至少在三次运行中的两次出现，且换种子后仍出现。只出现一次的命中记为“待复核”，不进入结论。反汇编命中的指令地址要与源码行对上，动态工具命中的源码行要与反汇编对上。对不上时保留两种坐标，不强行合并。

9 种工具 × 5 个模块共 45 格，31 格有真实运行产物，14 格未运行。未运行的格子写明原因，不填阴性。M5 上运行过的 7 种工具误报 0。这个数字支持“阴性对照没有被冤枉”，不支持“M5 已达到常数时间”。定位结论与计时结论分开登记：M2 的三处除法在定位层命中，端到端与微基准未检出。M1 的分支在定位层命中，端到端可区分。M4 的比较在定位层与计时层都命中。 % A-24 % B-05

如果只用一个工具，M2 会被读错两次。单看 dudect，未修版最大 $t$ 为 4.68、3.05、3.66，已修版反而为 36.27、30.94、61.91，阳性落在已修版上。单看 RTLF，两个版本都可能被判为可区分。只拿其中一个结论写报告，会得出“修复引入泄漏”或“两个版本都有泄漏”，与端到端 Welch 检验的未检出冲突。交叉后才知道 M2 是定位阳性、计时未检出，dudect 的阳性不能归因于除法。多工具交叉的代价是安装、版本固定与人工核对。14 格未运行也必须保留。另一条代价是工具之间的结论可能冲突，冲突本身要写进报告，不只保留对结论有利的一条。

工具覆盖的输入、入口与验证范围见附录 E；局限统一汇总于第 6.2 节。

\subsection{防护设计与泄露渠道审计}
% A-36 泄露渠道审计
% B-10 审计覆盖占比

防护不是“改源码”，而是“改完以后在机器码、功能、计时三个层面都能核验”。源码里把分支写成掩码，编译器仍可能还原成分支。功能测试全过，日志或退出码仍可能泄露验证结果。


\begin{algorithm}[H]
\caption{常数时间防护与产物核验}
\label{alg:mitigation}
\begin{algorithmic}[1]
\Require 脆弱实现，目标机制（分支、除法、查表、提前返回或错误路径）
\Ensure 修复后二进制，定位层、功能层与计时层记录
\State 选择防护：掩码选择替换分支。乘法与移位替换秘密除法。去掉秘密下标。比较遍历全部字节。成功与失败走同一路径
\State 编译。记录编译器、选项与二进制摘要
\State 反汇编：检查目标分支、除法或查表是否消失
\State 动态检查：目标错误数应降为 0
\State 功能核验：修复前后输出逐字节一致。隐式拒绝仍然生效
\State 同规程复测：端到端可区分性、族外检验与性能开销
\end{algorithmic}
\end{algorithm}

算法 8 回答的是“改了什么、在产物里是否生效、功能是否仍等价、同规程复测是否完成”。它不回答修复是否在所有编译器与所有输入上都成立。表~\ref{tab:mitigation} 把七类手段与对应的产物级核验并排列出。七类手段对应题面第 6 条列出的方向：消除数据相关分支、掩码选择、消除数据相关除法、消除数据相关访存、常数时间比较、固定循环上界、统一错误处理。每一类都给出实现方式与产物级核验，避免“源码改了就算防护”的写法。

M1 的防护用掩码选择替换分支：先清零系数，再由 16 位条件传送辅助函数按消息位在 0 与公开常数之间选择。辅助函数以取负、异或、与、再异或完成选择，不产生依赖秘密的跳转。M4 的常数时间比较把逐字节异或按位或累积，循环始终遍历公开长度，结束后统一判断。

r->coeffs[8*i + j] = 0;

void cmov_int16(int16_t *r, int16_t v, uint16_t b)
{
    b = -b;
    *r ^= b & ((*r) ^ v);
}

本作品的防护分为三层：对 M1、M2 真实历史案例引入上游官方补丁，核对反汇编与动态秘密标记结果，确认目标机制消失；对 M3、M4 人工夹具自主实现常数时间改造，并完成定位与计时复测，其中 M4 另有有界形式化验证；对平台自身开展输出与返回调用点审计，定位并修复退出码信息泄露。

常数时间改造还需要配合输出渠道检查。赛题第 6 条要求防护过程不能通过日志、异常或返回值泄露私钥和中间信息，因此本作品在代码改造后继续检查平台的可观察输出。对 128 个源文件中的 1,048 个输出或返回调用点做静态扫描，其中 122 个接触秘密相关数据，占 11.6\%。秘密内容泄露 0 条。审计发现 1 条低危问题：功能自检分支使计时程序在不同构建下退出码不同，构成可观察信号。修复后该类问题由 1 条降为 0 条。动态差分对 7 种输入模式各运行 120 次，返回码、标准输出与标准错误逐字节一致。 % A-36 % B-10

那条低危问题的修复方式是把功能自检改成仅在显式参数下执行：计时模式下标准错误恒空，退出码只反映参数、I/O 或内存分配失败。修复后重新跑动态差分，7 种输入模式各 120 次的返回码、标准输出与标准错误逐字节一致。静态扫描负责找调用点，动态差分负责验证可观察行为。两者都过，才把该类问题记为 0。

审计不覆盖上游第三方代码、网络路径以及进程级元数据（打开的文件描述符、内存映射、资源用量），这些需要单独专项检查。M1 所用版本的掩码辅助函数未带值屏障，在本作品主构建的解封装函数体内未观测到由此产生的分支，但在其他编译器与选项下仍是未经验证的可移植性隐患。官方补丁的产物核验、人工夹具的自主改造与平台自身的输出审计共同构成上述三层防护。

如果只看源码，编译器可能把掩码还原成分支：M1 的源码本来用掩码，特定编译器选项下仍被还原成按位测试后条件跳转，只有反汇编与动态标记才能发现。如果只看功能测试，日志与退出码仍可能泄露验证结果：那条低危问题就是功能自检留下的可观察信号，功能测试全过并不能排除它。防护核验因此必须在机器码、功能与计时三层同时留下记录。

\subsection{运行结果}
% A-31 运行批次
% B-08 运行批次合计

运行结果只交代“跑了多少、频率是否受控、失败是否登记”，统计结论留给第 4 章。M1 的数据为前期封存：同一台机器、同一套锁频规程，但不是与 M2--M5 同一批采集。M2--M5 的正式采集共 54 次控制器运行，另有 6 次 M2 微基准。收尾阶段 117 次控制器运行（格式破损对照 18 次、性能开销 54 次、优化级别对照 36 次、锁频对照 9 次），三类合计 177 次。 % A-31 % B-08

“控制器运行”指一次经过计划校验、频率放行与退出恢复的采集单元。一次运行包含若干次调用，不等于一次解封装。M1 的封存数据不计入 177 次，统计口径仍按当时封存的家族。如果把拒绝的运行从台账里删掉，频率核对就只剩成功样本。本作品保留原编号与原因，批次按全部运行计。

以性能开销实验的 54 次运行为例，逐次实测中位频率的中位数为 4,309,722.5 kHz，相对名义 4.30 GHz 的偏差为 +0.005\%。其中 1 次运行在采集期间的频率跨度为 50,310 kHz，略超 50,000 kHz 的跨度阈值，20 个采样值仍在 ±2\% 带内，已如实登记。全部正式采集通过放行探针与恢复核对。失败尝试与异常样本单独登记，不并入阴性。频率偏差 +0.005\% 是按逐次运行中位频率的中位数与名义值比较得到的，不是单次采样。频率核对的记录分进入、采中、退出三段，任何一段缺失都视为该次运行不合格。三次独立运行的原始值、失败样本与元数据一并归档。性能与优化级别的运行各自成批，不与主家族混算。 % A-31
