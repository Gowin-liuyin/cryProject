\reportabstract{%
\linespread{1}\selectfont
ML-KEM-768（FIPS 203）解封装在 Fujisaki-Okamoto 变换下依次执行解密、重加密、密文比较与隐式拒绝，四步均接触私钥或解密消息。完整解封装耗时约 50 $\mu$s，内部消息位泄漏仅数十纳秒，单次测量淹没在噪声中，需每类 10,000 次调用、三次独立运行及采样前冻结的检验规则才能分离。判定须针对实际编译产物（C 源码无分支时机器码仍可能出现分支），检测工具按回答的问题分工使用，”未检出”须附带最小可检测效应（MDE）。本作品构建检测—定位—防护—复测一体化平台，覆盖五类对象：liboqs 0.10.0 消息编码分支（M1）与 pq-crystals Kyber768 秘密除法（M2）两个真实历史案例；秘密下标查表（M3）与 32 B 提前返回比较（M4）两个人工构造靶标；mlkem-native 阴性对照（M5）。平台通过 CPU 锁频固定工作点，采样前冻结全 0 与全 1 消息密文对比输入、样本量与 Holm 检验家族；统计层用 Welch 检验、Holm 校正、多轮逆方差合并量化结论；定位层联合反汇编、Memcheck、varlat、Microwalk 与 Binsec 交叉验证，按 3 实现 $\times$ 5 步骤 $\times$ 6 类完成 90 格全流程排查，每项判定绑定同一编译产物。\par
实验表明：M1 未修复版主类对均值差 +32.3 ns（占 57 $\mu$s 总耗时 0.06\%），三轮方向一致，引入官方补丁后置信区间跨 0，解封装开销增加 1.51\%；M2 三处秘密除法定位层命中、修复后归零，端到端与微基准均未检出（端到端 MDE 24.7--67.1 ns），实证定位阳性与计时阳性分属两类证据；M4 脆弱实现可区分，常数时间实现未检出；M5 本机预算下未检出，7 种工具误报为 0。90 格排查发现 KyberSlash 官方除法补丁中残留同源消息编码分支；同一 M1 源码在 aarch64 编译为无分支条件选择指令。本作品通过历史漏洞补丁机器码核验、人工靶标自主常数时间重构、1,048 个调用点静态与动态审计构建完整三层防护闭环，全面支撑 ML-KEM 解封装常数时间工程落地。%
}
