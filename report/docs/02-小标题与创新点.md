## 三、创新点定稿

四条创新点，每条给一句**定位句**（摘要、1.4、结论三处逐字相同）与一张四问表。四条都不是“新攻击/新原语”，而是“新的证据组织方式”。

### 创新点 1：分层证据模型

**定位句**：把机制存在、热点可测、端到端可测与防护有效分为四层登记，并用最小可检测效应量化未检出。

| 问 | 答 |
| --- | --- |
| 相对谁 | 单工具、单层结论的评估方式：dudect/RTLF 只回答“是否可区分”，Memcheck/Microwalk 只回答“哪里依赖秘密”，Binsec 只回答“给定边界内是否常数时间” |
| 改了什么 | 在同一个被计时的产物上同时登记定位层、热点层、端到端层与复测层；每个阴性结论附 MDE；每个“未执行”单列，不并进阴性 |
| 为什么不显然 | 直觉是把“定位到泄漏”当成“能测到泄漏”，或把“计时未检出”当成“没有泄漏”。M2 正好相反：三处除法定位阳性，端到端与热点微基准都未检出；M1 在 `-O2`/`-O3` 的分支更多，计时反而未检出。分层登记让两种误读都不成立 |
| 实测支撑 | 表 2（五模块分层结论）、表 9（防护前后）、表 10（MDE） |
| 代价 | 需要更多采集与工具运行；报告必须保留“未执行/不适用”状态，篇幅增加 |
| 禁用表述 | 只在定位层阳性时写“检测到泄漏”；只在计时层未检出时写“安全” |

### 创新点 2：预注册与可审计的锁频协议

**定位句**：采集前冻结检验计划，控制器校验计划摘要并核对频率恢复，使每次判定可追溯、可复算。

| 问 | 答 |
| --- | --- |
| 相对谁 | 事后选检验、只看 p 值的计时实验；以及“锁频必然降噪”的常见直觉 |
| 改了什么 | 主类对、样本预算、停止条件、Holm 家族一次冻结；控制器每次运行校验计划 SHA-256；放行前 20 次频率探针；退出核对 `restore_match`；原始值与失败尝试全留 |
| 为什么不显然 | 直觉是“锁频就能降低方差、提高灵敏度”。实测不锁频/锁频的 CV 比为 0.964、1.006、1.089，方向不一致；锁频的价值是确定、可核对、可恢复的工作点，不是降噪。预注册则防止“不显著就加样本/换分组直到显著” |
| 实测支撑 | 表 12（锁频/不锁频）、2.8 节（运行与恢复核对）、表 6（环境） |
| 代价 | 117 次收尾运行、失败尝试也要登记；机时成本高；不锁频臂需要证明“没有写 sysfs” |
| 禁用表述 | “锁频降低噪声”“p<0.05 即泄漏”“恢复核对等于物理恒频” |

### 创新点 3：多工具交叉与全流程排查

**定位句**：用 9 工具 × 5 模块矩阵和 90 格排查，把定位阳性与计时阳性分开，并识别官方修复后残留的同源分支。

| 问 | 答 |
| --- | --- |
| 相对谁 | 单一工具或单一机制的评估；以及“用了官方补丁就等于修好”的假设 |
| 改了什么 | 9×5=45 格工具矩阵，30 格有真实产物；3×5×6=90 格逐格排查，每格给存在/不存在/不适用/未检查 + 函数/指令/行号 |
| 为什么不显然 | 单看 RTLF 会把 M2 读成“两臂都可区分”；单看 dudect 会因阳性落在已修臂而得出“修复引入泄漏”。交叉后才知道 M2 是“定位阳性、计时未检出”。90 格进一步发现 `272125f` 只修了除法，`poly_frommsg` 的 `bt`/`jae` 仍在；这是历史产物观察，不是新漏洞 |
| 实测支撑 | 表 8（90 格）、图 10（工具矩阵）、3.5 节（残留分支） |
| 代价 | 工具安装、版本固定、人工核对；15 格未运行必须写明原因，不能填“阴性” |
| 禁用表述 | “发现新漏洞”“M2 修复后泄漏降低”“所有工具都同意” |

### 创新点 4：产物与环境的依赖对照

**定位句**：把同一源码在优化级别、架构、虚拟化与网络条件下的产物形态与可检出性并列，界定结论的适用边界。

| 问 | 答 |
| --- | --- |
| 相对谁 | 单环境、单优化级别的评估；把一次 x86_64 结果外推到“ML-KEM 实现”的写法 |
| 改了什么 | 12 格优化级别（3 臂 × 4 级）的产物判定 + 锁频计时；三台 WSL2 虚拟化复现；aarch64 12 格；同机网络五档 + 检测预算 |
| 为什么不显然 | 直觉是“分支越多越容易测到”。实测 `-O2`/`-O3` 的 Memcheck 命中 8/15 个位置，计时却未检出；M1 的 `bt`/`jae` 只在 `-Os` 出现；aarch64 上 clang 生成 `sbfx`/`csel`，机制不复现。结论必须绑定产物与环境 |
| 实测支撑 | 图 8（优化级别）、图 9（架构/网络）、表 12（优化与架构对照） |
| 代价 | 跨环境时间证据不能合并；aarch64 不是第二台测量机；网络只是同机模拟 |
| 禁用表述 | “ARM 上也泄漏”“远程不可测”“跨平台验证完成”（只做了机制层） |

## 六、标题定稿的六条自检

1. **名词短语**：所有二级标题不以“我们”“本文”“如何”开头，不含结论句。
2. **长度**：二级标题 ≤ 14 字；最长的“2.8 防护设计与泄露渠道审计”11 字。
3. **不含数字**：标题里没有 32 ns、12 格、90 格、9×5 等数字；数字放表题与正文。
4. **同级平行**：第 2 章统一“X 设计 / X 结果 / X 指标”；第 3 章以名词短语为主，允许“测试/定位/排查/复测/预算/边界/验证/性”等不同后缀，因为每节回答的问题不同。
5. **不用禁用词**：没有“概述、介绍、分析、研究、探讨、相关、若干、一些、初步、浅谈、综述、探究、浅析”。
6. **只读目录能讲故事**：按 §1.3 的七问逐条对照，能全部答上。
