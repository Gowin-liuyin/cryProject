## 一、项目判断

### 1.1 作品是什么

这不是“发现并修复一个新漏洞”的故事，也不是“写一个更快的 ML-KEM”的故事。它的实质是：

> 在一台真实机器上，把数十纳秒级、容易被噪声淹没的时间差异，变成一条可定位、可复测、可复算、边界清楚的证据链。

作品由五类被测对象、四个共享层和一条四段链组成：

| 维度 | 内容 |
| --- | --- |
| 被测对象 | M1 liboqs 0.10.0 编译器引入分支；M2 pq-crystals Kyber768 秘密除法；M3 秘密下标查表校准夹具；M4 提前返回比较校准夹具；M5 mlkem-native 阴性对照 |
| 对象分类 | 真实历史案例（M1、M2）；人工校准（M3、M4）；阴性对照（M5） |
| 共享层 | 统一计时入口；锁频绑核控制器；统计与功效分析；定位工具与结果登记 |
| 四段链 | 检测 → 定位 → 防护 → 复测 |
| 证据层 | 机制层（反汇编、Memcheck、varlat、Microwalk、Binsec）→ 热点层（函数级微基准）→ 端到端层（完整解封装计时）→ 防护复测层 → 环境边界层（优化级别、架构、虚拟化、网络） |
| 交付形态 | C11 工程、CMake/CTest、一键复现入口、原始 CSV、匿名支撑包、正式报告 |

### 1.2 最强主张

报告只需要让评委记住一句话：

> **源码级常数时间不等于产物级常数时间；时间侧信道结论必须绑定编译产物、分层登记、按检测预算表述。**

这句话有四组直接证据：

1. M1 的源码本来用掩码写成无分支，clang 18 在 x86_64 的 `-Os` 下编出了依赖消息位的 `bt`/`jae`；同一份源码在 aarch64 上被编成 `sbfx`/`and`/`csel`，机制不复现。
2. M2 的三处秘密除法在定位层稳定出现（varlat 1280 errors / 3 contexts），但完整解封装和除法热点微基准都未检出；MDE 为 25–67 ns，远大于可能效应。
3. KyberSlash 官方修复 `272125f` 只消除了除法，`poly_frommsg` 中与 clangover 同源的 `bt`/`jae` 分支仍在，未修与已修两侧指令字节逐字节相同。
4. 不锁频与锁频的变异系数比值为 0.964、1.006、1.089，方向不一致；锁频的价值是确定、可核对、可恢复的工作点，不是“降噪”。

### 1.3 报告不应该讲成什么

### 1.4 最脆弱的评分点

按工程实践类作品的常见评审维度，最脆弱的一档不是“功能能不能跑”，而是**创新性与自主防护**：

- 真实缺陷的修复都采用上游官方补丁；团队自己写的修复只落在 M3、M4 两个人工夹具上。
- `272125f` 的残留分支只定位、未修复、未复测。
- M2 的计时实验设计偏弱：主类对是同一份密文的重复，MDE 25–67 ns，不能证明“除法效应不存在”。

因此，报告不能把创新性押在“我们修了一个真实漏洞”上，而要押在**方法论与证据组织**上：分层证据模型、预注册与可审计锁频、多工具交叉与 90 格排查、产物与环境的依赖对照。这四条是站得住的，也是现有工作没有系统做的。

## 五、推荐目录与页数配额

正文目标 **58–64 页**（不含封面与基本信息表），按楷体四号、24 pt 行距估算约 4.2–4.6 万字；附录目标 **20–24 页**。总篇幅约 82–88 页，低于现有 104 页正式稿，但比 38 页修订版多出方法、伪代码、模块细节与附录全表。

扩充不靠重复结论，靠四类新增内容：

1. **攻击模型与泄漏机理**：把“怎么观测、为什么能区分、为什么还不足以恢复密钥”讲成一条可核查的链路，而不是只给结果。
2. **算法与伪代码**：解封装、攻击者观测、测量循环、锁频控制、统计判定、动态检查、有界验证、90 格排查、常数时间防护，共 9 个算法块。
3. **模块级完整结果**：每个模块的原始 p 值、区间、MDE、工具命中、反汇编片段，正文给摘要，附录给全表。
4. **工程与复现细节**：数据格式、元数据、失败处理、运行台账、工具版本、命令与匿名检查。
