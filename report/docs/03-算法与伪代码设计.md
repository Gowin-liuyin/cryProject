# 算法与伪代码设计

- 用途：为正文第 2、3 章提供 9 个算法块与 4 段最小代码形态的初稿；写作时按此改写为 LaTeX `algorithm` 环境，正文只保留结构与关键步骤，完整参数进附录 C。
- 边界：本文件只写到“观测—判定—定位—防护—复测”，不包含密钥恢复、利用脚本或可直接复用的攻击代码。算法 2 的终点是“两类时间分布是否可区分”，这是本作品与攻击论文的分界。
- LaTeX 依赖：在 `main.tex` 导言区加 `\usepackage{algorithm}` 与 `\usepackage{algpseudocode}`；若模板类不加载，放在 `main.tex` 即可。算法题注用“算法 N 标题”，不与图、表共用编号。

## 一、算法 1：ML-KEM 解封装与隐式拒绝

**放在**：2.1 节开头。**作用**：固定 FO 结构与四个可观测步骤，后面所有泄漏点都挂在这四步上。

```text
算法 1  ML-KEM 解封装与隐式拒绝
输入: 密文 c（1088 B），解封装密钥 dk = (dk_PKE, h, z)
输出: 共享密钥 K（32 B）

1:  m' ← K-PKE.Decrypt(dk_PKE, c)          // 解密，使用私钥
2:  (K', r') ← G(m' ‖ h)                   // 派生候选密钥与重加密随机数
3:  c' ← K-PKE.Encrypt(dk_PKE, m', r')     // 重加密
4:  K̄ ← J(z ‖ c)                          // 隐式拒绝的假密钥
5:  if c' = c then K ← K' else K ← K̄       // 比较与选择
6:  return K
```

**正文要写的三句话**：

1. 第 1 步的秘密是私钥与解密消息；第 3 步把它们重新送进多项式编码、NTT、压缩与序列化；第 5 步同时接触真密钥与假密钥。
2. 第 5 步必须是常数时间比较与掩码选择；若实现提前返回或让分支依赖比较结果，隐式拒绝就失效。
3. 本作品把 M1（消息编码分支）、M2（秘密除法）、M3（秘密下标查表）、M4（提前返回比较）分别映射到第 1、3、5 步；M5 作为整条链的阴性对照。

**表注/边界**：算法 1 是标准结构的伪代码，不表示任何具体实现的优化细节；M1 的对象是 FIPS 203 初始公开草案（ipd），M2 是历史 Kyber768，二者不等同于最终标准 ML-KEM-768。

## 二、算法 2：攻击者的计时观测与可区分性实验

**放在**：2.2 节。**作用**：把“怎么攻击”讲清楚，但止于可区分性；不写密钥恢复。

```text
算法 2  攻击者的计时观测与可区分性实验
输入: 解封装预言机 O，两个密文类 C0/C1，每类样本 n，显著性 α
输出: 可区分 / 未检出（附效应量与区间）

1:  for b ∈ {0, 1} do
2:      for i = 1..n do
3:          c ← Sample(C_b)                 // 公开规则生成，长度合法
4:          t_{b,i} ← Time(O(c))            // 只测一次完整解封装
5:      end for
6:  end for
7:  Δ ← mean(t_0) − mean(t_1)
8:  CI ← Δ 的 95% 置信区间
9:  if CI 不含 0 then return 可区分 (Δ, CI)
10: else return 未检出 (Δ, CI, MDE)
```

**正文要写的四句话**：

1. 攻击者能控制的是密文类别与调用次数，能看到的是每次完整解封装的耗时；看不到私钥、共享密钥与内部验证标志。
2. 两类密文都必须是合法、等长的；主类对只让解密消息的位全 0 或全 1 不同，其他条件相同。
3. 判定是“两类时间分布是否可区分”，不是“能否恢复密钥”。从可区分到密钥恢复还隔着攻击模型、样本量、噪声与后处理，本作品不做这一步。
4. 本地锁频下可区分，不等于远程可观测；远程还要叠加协议栈、排队与链路抖动，本作品只做同机模拟并给出检测预算。

**表注/边界**：算法 2 是测量实验，不是利用工具；`Sample(C_b)` 由公开种子派生，不接触私钥；`Time(·)` 只包住一次完整解封装。

### 框 1 / 框 3 攻击可行性对照

这个框在 1.2 节与 2.2 节各出现一次：1.2 节为框 1，2.2 节为框 3；两处内容相同，1.2 节用于威胁模型边界，2.2 节用于机制细节。它回答“你们讲的是攻击还是检测”，每一行都写清“攻击者需要什么、本作品做到哪、离密钥恢复还差什么”。

| 机制 | 攻击者需要的观测 | 本作品做到哪 | 离密钥恢复还差什么 |
| --- | --- | --- | --- |
| 秘密分支（M1） | 同一密文类下，消息位不同导致耗时不同 | 本地锁频、完整解封装、三次运行可区分（+32.311 ns） | 选择密文构造、逐位消息恢复、纠错与多轮查询；本作品不做 |
| 秘密除法（M2） | 除法操作数不同导致耗时不同 | 定位层稳定命中三处除法；端到端与热点微基准未检出 | 更大的样本量、针对除法的输入类、远程噪声下的可观测性；本作品不做 |
| 秘密下标（M3） | 不同下标落在不同缓存行导致耗时不同 | 人工夹具上 Memcheck/Microwalk 命中；计时层未检出 | 共驻缓存攻击模型、缓存驱逐与观测；本作品不做 |
| 提前返回（M4） | 比较从第几个字节开始不同导致耗时不同 | 32 B 夹具上 vulnerable 臂可区分，ct 臂不可区分 | 完整 KEM 比较路径、远程噪声、逐字节恢复；本作品不做 |
| 阴性对照（M5） | 若存在机制，应能被工具或计时发现 | 三种动态模式 0/0、Binsec 无秘密相关控制流、计时未检出 | 不是常数时间证明；需要更大预算与其他工具 |

**这个框的用法**：正文先讲“可区分”，再讲“离密钥恢复还差什么”，最后落到“本作品只做前者”。这样既回应了“怎么攻击”，又不会把检测平台写成攻击工具。

## 三、代码 1–4：四类泄漏机理的最小形态

**放在**：2.2 节，每段不超过 12 行。**作用**：让评委一眼看到“泄漏长什么样”，再对应到 M1–M5。

### 代码 1 秘密相关分支

```c
/* 消息位决定走哪条路径；两条路径的指令数或访存不同 */
int16_t select_coeff(const uint8_t *msg, size_t i)
{
    if ((msg[i / 8] >> (i % 8)) & 1)
        return COEFF_ONE;
    return 0;
}
```

**对应**：M1 的 `poly_frommsg`；源码本来用掩码，clang 18 在 x86_64 `-Os` 下把它还原成 `bt`/`jae`。**边界**：这段代码只说明机制，不代表上游源码的原样写法。

### 代码 2 秘密相关除法

```c
/* x 来自解密消息；除法指令的时延可能随操作数变化 */
int16_t compress_coeff(int16_t x)
{
    return (int16_t)((((int32_t)x << 4) + (KYBER_Q / 2)) / KYBER_Q);
}
```

**对应**：M2 的 KyberSlash；三处除法分别在 `poly_tomsg`、`poly_compress`、`polyvec_compress`。**边界**：除法是否真的有可测时延取决于处理器与编译选项；本作品在 `-Oz` 产物上定位到 3 条 `div`，但计时层未检出。

### 代码 3 秘密下标查表

```c
/* secret_index 来自消息位；不同下标落在不同缓存行 */
int16_t lookup_coeff(unsigned secret_index)
{
    static const int16_t table[16] = { /* 16 个公开常数 */ };
    return table[secret_index & 15];
}
```

**对应**：M3 的人工校准夹具；插在 mlkem-native 的重加密路径上，on/off 两版输出逐字节相同。**边界**：这是人工埋点，不是上游漏洞。

### 代码 4 提前返回比较

```c
/* 发现第一个不同字节就返回；耗时取决于从哪里开始不同 */
int compare_bytes(const uint8_t *a, const uint8_t *b, size_t len)
{
    for (size_t i = 0; i < len; i++)
        if (a[i] != b[i])
            return 0;
    return 1;
}
```

**对应**：M4 的 vulnerable 臂；ct 臂改为逐字节异或累积、循环结束后统一判断。**边界**：M4 是 32 B 独立比较夹具，不挂到完整解封装上；它证明检测链路能闭环，不证明任何真实库有同样缺陷。

## 四、算法 3：单次解封装的计时循环

**放在**：2.5 节。**作用**：说明计时窗口、预热、乱序、落盘与失败处理。

```text
算法 3  单次解封装的计时循环
输入: 被测二进制，类别集合 C，每类样本 n，种子 s，CPU 核 k
输出: 逐次 CSV 与元数据

1:  生成输入流；按 s 做可复现的类别乱序；记录输入流摘要
2:  在窗口外预热 100 次
3:  for each (class, ciphertext) in shuffled order do
4:      t0 ← Clock()
5:      Decaps(ciphertext)                 // 只包住这一次完整解封装
6:      t1 ← Clock()
7:      write(run, implementation, class, index, t1−t0, unit)
8:  end for
9:  记录元数据: 源摘要、产物摘要、编译器、选项、时钟、频率、CPU、计划摘要
10: 失败样本单列；不删普通长尾；不扣读钟开销
```

**正文要写的三句话**：

1. 输入生成、内存分配、结果消费、日志与 I/O 都在窗口外；窗口内只有一次完整解封装。
2. 类别乱序是为了避免“先测完 A 再测 B”时环境漂移造成假差异；预热是为了让缓存与分支预测进入稳定状态。
3. 原始值全量落盘，普通长尾保留；异常样本规则在计划中预先写定，不在看到数据后删点。

**表注/边界**：`Clock()` 在 x86_64 上为 `CLOCK_MONOTONIC`；M4 的比较调用用 `CLOCK_MONOTONIC_RAW`。读钟开销约 17.4 ns，最小步进 10 ns；32 ns 的效应只有 2–3 个 `rdtsc` 分辨率单位，单次调用不可分辨，必须靠大样本。

## 五、算法 4：锁频控制与恢复核对

**放在**：2.5 节。**作用**：把“锁频”从口号变成可核对的协议。

```text
算法 4  锁频控制与恢复核对
输入: 目标频率 f0 = 4.30 GHz，CPU 核 k，探针次数 m = 20
输出: 放行 / 拒绝；进入、采中、退出三段记录

1:  保存 boost、governor、EPP、min、max 的原始快照
2:  写 boost=0；governor=performance；EPP=performance；min=max=f0
3:  taskset -c k 绑定被测进程
4:  等待 1.0 s
5:  for i = 1..m do
6:      读 cur_khz；间隔 50 ms
7:  end for
8:  if 全部 |cur−f0|/f0 ≤ 2% 且 max−min ≤ 50000 kHz then 放行
9:  else 拒绝，恢复快照，记录原因
10: 采集结束后恢复快照；读取并比较 restore_match
```

**正文要写的三句话**：

1. 放行判据作用于 20 次探针，不作用于采集中每一次调用；采集中 `during.json` 的样本跨度单独记录。
2. `restore_match=yes` 只证明设置恢复一致，不证明物理恒频；本机未配置 isolcpus、SMT 开启、后台约 39 个服务。
3. 锁频/不锁频 A/B 的 CV 比为 0.964、1.006、1.089，方向不一致；锁频的价值是确定性、可核对、可复算，不是“降噪”。

**表注/边界**：一次收尾运行出现 50 310 kHz 的跨度，略超 50 000 kHz 阈值，20 个采样值仍在 ±2% 带内，已如实登记。

## 六、算法 5：Welch 检验、Holm 校正、固定效应合并与 MDE

**放在**：2.6 节。**作用**：把统计层写成可复算的流程，而不是只报 p 值。

```text
算法 5  统计判定与合并
输入: 两组样本 t0、t1；家族大小 m；α = 0.05；功效 1−β = 0.80
输出: Δ、95% CI、p、Holm 判定、合并 Δ、I²、MDE

1:  Δ ← mean(t0) − mean(t1)
2:  SE ← sqrt(var(t0)/n0 + var(t1)/n1)
3:  t ← Δ / SE；df ← Welch–Satterthwaite
4:  p ← 2·(1 − T_df(|t|))；CI ← Δ ± z_{1−α/2}·SE
5:  对家族内 m 个 p 升序排序；Holm 逐步比较 α/(m−i+1)
6:  for each run i do
7:      SE_i ← (CI_high − CI_low) / (2z)
8:      w_i ← 1 / SE_i²
9:  end for
10: Δ_pool ← Σ w_i Δ_i / Σ w_i；SE_pool ← sqrt(1 / Σ w_i)
11: I² ← max(0, (Q − (k−1)) / Q)，Q 为 Cochran 异质性统计量
12: MDE ← (z_{1−α/2} + z_{1−β})·sqrt(s0²/n0 + s1²/n1)
```

**正文要写的四句话**：

1. 区间与 p 值用大样本正态近似（z=1.9599639845），不称为有限样本精确的 Student-t 区间。
2. 每个模块的检验预先归为一个家族，全族 α=0.05；M1、M2、M3、M4 各 6 项，M5 3 项。
3. 三次运行按逆方差固定效应合并；I² 高时合并区间只作描述，判定以预注册的 Holm 结果为准。
4. “未检出”的含义是观测效应小于 MDE，不是效应为 0；MDE 是事后功效描述，不改变已提交的判定。

**表注/边界**：Holm 门槛对最小 p 为 0.05/m；M1 的 m=6，门槛 0.00833；M1 原始 p=1.30×10⁻⁵。M4 的 p=0 是双精度下溢，正文写“小于最小可表示值”，不写“p 严格等于 0”。

## 七、算法 6：秘密标记动态检查

**放在**：2.7 节。**作用**：说明 Memcheck/varlat 的标记、运行、归因与边界。

```text
算法 6  秘密标记动态检查
输入: 被测二进制，私钥 dk，秘密片段 S = dk[0:1152] ∪ z[0:32]，公开输入集合
输出: 错误数、上下文数、源码位置/指令

1:  在 Valgrind Memcheck 下启动被测程序
2:  将 S 标记为“未初始化/秘密”；公开输入保持已初始化
3:  运行完整解封装，覆盖接受与隐式拒绝
4:  收集 “Conditional jump or move depends on uninitialised value”
5:  收集 “Use of uninitialised value” 与可变时延指令报告（varlat）
6:  归因到函数、源码行、调用栈、指令地址
7:  对未修/已修两臂重复；比较错误数与上下文数
```

**正文要写的三句话**：

1. 秘密标记只覆盖实际执行过的输入；0 errors 不是常数时间证明。
2. 普通 Memcheck 看不到可变时延除法，必须用 varlat；M2 未修 1280 errors / 3 contexts，修复后 0/0。
3. M3 的 1280 errors / 2 contexts 都落在人工插入的秘密下标读取；M4 的 32 errors / 1 context 落在提前返回行；M5 三种模式各 10 次完整解封装均 0/0。

**表注/边界**：varlat 基于 Valgrind 3.25.1；Memcheck 基于 Valgrind 3.22.0；M5 的 1152 B 私钥与 32 B 隐式拒绝秘密 z 分别标记。

## 八、算法 7：Binsec 有界常数时间检查

**放在**：2.7 节。**作用**：说明形式化检查的输入、边界与“不能只看退出码”。

```text
算法 7  Binsec 有界常数时间检查
输入: 抽取内核，入口 entry，终点 halt，秘密数组 s，公开数组 p，长度范围 1..16
输出: insecure + 反例 / bounded secure / unknown

1:  固定 i386、-O1 与编译选项；记录二进制摘要
2:  声明 s 为 secret；p 与 len 为 public
3:  关系符号执行，检查控制流与访存是否只依赖 public
4:  若存在反例，输出反例 PC 与路径
5:  检查 pending / cut / discontinued / solver unknown 是否为 0
6:  负对照：同一配置下已知脆弱内核必须报 insecure
```

**正文要写的三句话**：

1. M4 vulnerable 判 insecure，反例 `0x8049047` 对应 `compare_early.c:9`；ct 判 bounded secure，所有路径到达 halt。
2. 把搜索深度限为 5 时工具返回 unknown，而进程退出码仍为 0；所以不能只看退出码判安全。
3. M5 重加密比较 1088/1088 路径、消息编码 1/1 路径完成，无秘密相关控制流；同配置 M4 脆弱内核报 insecure，证明不假阴性。

**表注/边界**：Binsec 0.11.3 + Z3 4.15.3；M4 只开 control-flow 与 memory-access，未开乘除法检查；M5 只覆盖重加密比较与消息编码，不覆盖完整解封装的所有性质。

## 九、算法 8：90 格泄漏源排查

**放在**：3.5 节。**作用**：把“全流程排查”写成可复核的判定流程。

```text
算法 8  90 格泄漏源排查
输入: 实现 {M1, M2, M5}，步骤 {解密, 哈希, 重加密, 比较, 隐式拒绝}，
      来源 {敏感分支, 提前返回, 可变时间比较/指令, 秘密下标, 数据相关循环, 异常路径}
输出: 90 格判定与证据

1:  for each implementation, step, source do
2:      检查源码与反汇编
3:      运行 Memcheck、varlat、Microwalk、Binsec（适用时）
4:      判定：存在 / 不存在 / 不适用 / 未检查
5:      记录函数、源码行/指令地址、证据编号
6:  end for
7:  汇总：存在 5 / 不存在 75 / 不适用 10 / 未检查 0
```

**正文要写的三句话**：

1. “存在”的 5 格：M1 未修/重加密/敏感分支；M2 未修/解密/可变时延指令；M2 未修/重加密/可变时延指令；M2 未修与已修/重加密/敏感分支；M5/隐式拒绝/提前返回（上游设计行为，按有界例外登记）。
2. “不适用”的 10 格都是异常处理类与不可能失败的函数组合；“未检查”为 0，不是把没做写成阴性。

**表注/边界**：全表见附录 F；正文只放汇总表与 5 个“存在”格的说明。人工夹具 M3、M4 不计入 90 格。
