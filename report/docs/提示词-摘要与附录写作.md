# 提示词：摘要、基本信息表与附录

## 【任务】

写 2026 年第十一届全国密码技术竞赛工程实践类作品设计报告的**摘要、基本信息表与附录 A–H**。摘要在 `report/chapters/abstract.tex`，附录在 `report/chapters/appendix.tex`。摘要 700–800 汉字；附录以表格为主，目标 20–24 页。摘要最后写；附录 B–F 可与第 3 章并行整理。写作前先读 `report/CLAUDE.md`、`report/docs/写作状态.md`、`report/docs/01-数据与实验台账.md`、`report/docs/02-小标题与创新点.md` §4、`report/docs/03-算法与伪代码设计.md`、`report/docs/04-得分点与亮点映射.md` §2/§5/§7。

## 一、目的

摘要挣“第一印象”分：评委先看摘要，再决定要不要细读。附录挣“工作量”和“可复现”分：正文只放摘要表，全表进附录，既不把正文变成流水账，又让工作量看得见。

失败模式（逐条避免）：

1. 摘要数字与正文不一致；宏观开篇；英文直译腔。
2. 摘要里出现内部代号、提交号、路径、主机名。
3. 附录命令过期或虚构；表格没有列头、单位、来源、状态。
4. 附录把正文的表原样复制一遍，没有增量。
5. 附录 A 把 10+2 写成 12/12。

## 三、目录与结构

### 3.1 摘要与基本信息表

```latex
% 摘要写进 main.tex 的 \reportabstract{...} 或 chapters/abstract.tex
% 关键词写进 \reportkeywords{...}
```

摘要 700–800 字，八句结构：

1. **问题**：ML-KEM 解封装在 FO 变换下要执行解密、重加密、比较与隐式拒绝；效应只有数十纳秒，源码级常数时间不等于产物级常数时间。
2. **问题**：单工具结论不可靠；“未检出”常被误读为安全。
3. **方法**：面向 ML-KEM-768 便携 C 实现，构建检测—定位—防护—复测平台；五个对象分三类。
4. **方法**：预注册 + 锁频 + Welch/Holm/合并/MDE；六类定位工具；90 格排查。
5. **结果**：M1 +32.3 ns（约 57 µs 的 0.06%），官方修复后区间含 0，开销 +1.51%。
6. **结果**：M2 定位阳性、计时未检出（MDE 25–67 ns）；M4 vulnerable 可区分、ct 不可区分；M5 上 6 种工具误报 0。
7. **亮点**：KyberSlash 官方修复版本仍残留同源分支；aarch64 上 M1 机制不复现；同机网络各档本预算未检出。
8. **边界**：单台 x86_64、clang 18.1.3、本地白盒、不做密钥恢复；时间结论不跨环境合并；题面 10 条满足 + 2 条部分。

关键词五个：**ML-KEM；时间侧信道；常数时间实现；泄漏检测与定位；预注册统计**。

## 四、逐节要求

### 4.1 摘要（700–800 字）

按 §三 的八句写。数字只允许 3–4 个来源：M1 的 +32.3 ns/0.06%/+1.51%，M2 的 MDE 25–67 ns，M4 的可区分/不可区分，M5 的 6 工具误报 0。不要把所有数字塞进摘要。

不要写：内部代号（R05/T25/E67）、提交号（272125f 等）、路径、主机名、“12/12”、“发现新漏洞”、“M5 是常数时间”、“远程不可测”。

### 4.2 附录 A 题面要求对照（2 页）

表 A1：12 行，列为“序号 / 要求 / 本作品的做法 / 章节 / 状态 / 证据”。状态只有“满足 / 部分 / 未执行”；10 条满足 + 2 条部分（第 6、7 条）；缺口写原因与影响。表注首句：“状态以仓库内可打开的证据文件为判据，不以文稿措辞替代实验完成。”

### 4.3 附录 B 实验与运行总表（3 页）

表 B1：每次运行的模块、臂、种子、CPU、样本量、日期、控制器结果、产物摘要、异常/失败。至少覆盖：M2–M5 的 54 次平台家族、6 次 M2 微基准、117 次收尾（格式 18、性能 54、优化 36、锁频 9）、网络 5 档 × 3 臂 × 2 次、aarch64 12 格。表注首句：“运行编号与正文 3.x 节一一对应；失败尝试单列，不计入正式结果。”

### 4.4 附录 C 统计公式与复算说明（3 页）

公式：Welch t 与 df、95% 正态近似区间、Holm 门槛、逆方差固定效应合并、I²、MDE、RTLF bootstrap。每个公式给符号定义、本次参数、一个手算例（用 4–6 个数）。表 C1 给“公式 / 符号 / 本次取值 / 用途”。表注首句：“公式与 `scripts/platform_stats/` 的实现一致；手算例只用于核对，不替代正式数据。”

### 4.5 附录 D 模块级完整结果（4 页）

表 D1–D5：每个模块的逐次运行 Δ、95% CI、原始 p、MDE、Holm 判定、dudect 最大 t、RTLF 结论。M4 分臂；M2 分端到端/微基准；M3 分 on/off；M5 单臂。表注首句：“逐次值来自封存原始数据；‘未检出’附 MDE。”

### 4.6 附录 E 定位工具输出摘要（3 页）

表 E1：工具、版本、对象、关键输出、上下文数、源码位置/指令地址、结论。只放关键行，不放完整日志；错误原文只放在“系统响应”列。表注首句：“工具输出只证明给定输入下的行为，不证明常数时间。”

### 4.7 附录 F 90 格排查全表（3 页）

表 F1：3 实现 × 5 步骤 × 6 类 = 90 行；列为“实现 / 步骤 / 来源 / 判定 / 函数 / 指令或行号 / 证据编号”。判定只取“存在/不存在/不适用/未检查”；合计 5/75/10/0。表注首句：“‘不存在’是给定产物、输入、工具下未发现，不是常数时间证明。”

### 4.8 附录 G 复现入口与命令（2 页）

表 G1：目标、命令、预期输出、实测结果。至少覆盖：

```bash
make test
make sanitize
cmake -S . -B build/platform -DBASELINE_ENABLE_PLATFORM=ON -DA113_ARCHIVED_CASE_ONLY=OFF
cmake --build build/platform
ctest --test-dir build/platform --output-on-failure
scripts/reproduce_all.sh quick --fetch
tools/fetch_all_vendors.sh
```

每条命令实跑一遍；写清“在哪台机器、什么权限、预期通过数”。表注首句：“命令实跑通过；完整锁频采集需要 x86_64 裸金属与频率写权限。”

### 4.9 附录 H 术语、缩略语与匿名检查（2 页）

表 H1 术语：ML-KEM、Kyber、FO、KEM、PQC、MDE、Holm、RTLF、dudect、Binsec、Microwalk、Valgrind、varlat、aarch64、x86_64、ipd。表 H2 匿名检查：单位、姓名、主机名、账号、绝对路径、内部代号、封面“注意”段、作品类别勾选、元数据。表注首句：“匿名检查逐项打勾；发现即改，不带入提交。”

## 五、本章特有规则

1. **摘要数字只认 3–4 个来源**：M1、M2 MDE、M4、M5 误报；其他数字不进摘要。倍数必须写分子分母（0.06% = 32.3 ns / 57 µs）。
2. **摘要不写内部代号/提交号/路径**：`272125f` 写成“KyberSlash 官方修复版本”；`R05/T25` 一律不出现。
3. **附录表必须有列头、单位、来源、状态**：缺一项就重做；表注首句是结论。
4. **附录不复制正文表**：正文表是摘要，附录表是全量/逐次/逐格；两者列不同。
5. **命令实跑**：附录 G 每条命令跑一遍，记录实测输出；不写未跑过的命令。
6. **10+2**：附录 A 不写 12/12；第 6/7 条的缺口写原因与影响。
7. **必要限定**：附录 A 的“部分”、附录 E 的“不证明常数时间”、附录 F 的“不是恒时证明”、附录 G 的“需要硬件”一条不删。

## 七、文献

摘要不引用文献。附录 A/E/F 不新增文献；附录 C 可引用 RTLF、dudect、Welch/Holm 的原始文献；附录 H 不引用。写完跑 `/ars-citation-check`，输出简体中文。

## 八、风格

按 `CLAUDE.md` §7 的 A/B/C 三组全文执行；摘要与附录重点：

- **A 组**：摘要不用“随着……的快速发展”“综上所述”；不写“本作品非常重要”；不用“高效/全面/领先”；段落长度不均。附录表注不用“由表可知”。
- **B 组**：摘要不写“我们尝试/我们希望”；附录 A 的“部分”是事实，不是道歉；附录 E/F 的边界是 B2 必要限定，不删。
- **C 组**：摘要每句一个信息点；附录每张表有“这张表证明什么/不证明什么”的表注；术语全篇统一。
